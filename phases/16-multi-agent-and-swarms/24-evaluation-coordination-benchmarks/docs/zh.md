# 评估与协调基准

> 五个 2025-2026 基准涵盖了多智能体评估领域。**MultiAgentBench / MARBLE**（ACL 2025, arXiv:2503.01935）使用里程碑式 KPI 评估星型/链型/树型/图型拓扑；**图型最适合研究**，认知规划使里程碑达成率提升约 3%。**COMMA** 评估多模态非对称信息协调；包括 GPT-4o 在内的前沿模型难以击败随机基线。**MedAgentBoard**（arXiv:2505.12371）涵盖四类医疗任务，常发现多智能体并不优于单 LLM。**AgentArch**（arXiv:2509.10769）对融合工具使用 + 记忆 + 编排的企业级智能体架构进行基准测试。**SWE-bench Pro**（[arXiv:2509.16941](https://arxiv.org/abs/2509.16941)）包含来自 41 个仓库的 1865 个问题，涵盖商业应用、B2B 服务和开发者工具；前沿模型在 Pro 上得分约 23%，在 Verified 上超过 70%——这是对数据污染的现实检验。Claude Opus 4.7（2026 年 4 月）在 Pro 上通过显式的智能体团队协调达到 **64.3%**（Anthropic 尚未发布主要来源——视为初步结果）；Verdent（智能体支架）在 Verified 上达到 **76.1% pass@1**（[Verdent 技术报告](https://www.verdent.ai/blog/swe-bench-verified-technical-report)）。**AAAI 2026 Bridge Program WMAC**（https://multiagents.org/2026/）是 2026 年的社区焦点。本课基于 MARBLE 的指标，进行拓扑 vs 指标扫描，并明确“仅仅通过 SWE-bench Verified 并非泛化能力的证据”这一原则。

**类型：** 学习  
**语言：** Python (stdlib)  
**前置知识：** Phase 16 · 15（投票与辩论拓扑），Phase 16 · 23（故障模式）  
**时间：** 约 75 分钟

## 问题

当一篇论文声称“我们的多智能体系统更好”时，问题是：比什么更好？在什么上衡量？如何衡量？2023-2024 年代的多智能体评估是一片混乱——每个人选择自己的指标、自己的基线、自己的任务集。2025-2026 的基准引入了结构。

没有共享的基准，你无法有意义地比较两个多智能体系统。更糟的是，没有预留基准，前沿模型可能污染数据。到 2025 年中，SWE-bench Verified 的训练语料已部分被污染；前沿模型得分虚高；Pro 被设计为未受污染的现实检验。

本课列举了五个规范的 2026 基准，指出每个基准衡量什么，并教你以怀疑的态度阅读基准声明。

## 概念

### MultiAgentBench (MARBLE) — ACL 2025

arXiv:2503.01935。在研究、编码和规划任务上评估四种协调拓扑（星型、链型、树型、图型）。基于里程碑的 KPI 跟踪部分进展，而不仅仅是最终成功。

测量结果：

- **图型**拓扑最适合研究场景；支持任意对任意批评。
- **链型**最适合逐步精炼编码。
- **星型**最适合快速事实整合。
- **协调代价**在约 4 个智能体后的图型上显现。
- **认知规划**在各种拓扑上使里程碑达成率提升约 3%。

何时使用：当你希望公平地比较协调拓扑时。MARBLE 仓库（https://github.com/ulab-uiuc/MARBLE）提供了评估器。

### COMMA — 多模态非对称信息

涵盖智能体拥有不同观察模态且必须在没有完全信息共享的情况下进行协调的任务。报告的结果令人不安：包括 GPT-4o 在内的前沿模型在 COMMA 的智能体间协作上难以击败**随机基线**。信号是多智能体模态训练不足且评估不足——LLM 在单模态合作上表现合理；多模态协调则崩溃。

何时使用：你的系统包含多模态或非对称信息协调。COMMA 的零结果是一个警告：在声称之前先测量。

### MedAgentBoard — 领域压力测试

arXiv:2505.12371。四个医疗任务类别：诊断、治疗计划、报告生成、患者沟通。比较多智能体 vs 单 LLM vs 传统基于规则的系统。

发现：多智能体在大多数类别上并**不**优于单 LLM。多智能体的优势很窄——当子任务可以清晰分离时（诊断+治疗），任务分解有帮助；当协调开销超过专业化收益时（报告生成），则有害。

何时使用：你的领域有明确的单 LLM 基线。如果 MedAgentBoard 的结论具有普遍性，许多提出的多智能体系统设计过度了。

### AgentArch — 企业架构

arXiv:2509.10769。企业环境结合工具使用、记忆和编排。该基准隔离了每个层的贡献：添加工具有多大帮助？添加记忆？添加多智能体编排？

何时使用：你在设计企业智能体栈，需要证明每个层的合理性。AgentArch 有助于避免购买无法衡量价值的特性。

### SWE-bench Pro — 现实检验

arXiv:2509.16941。来自 41 个仓库的 1865 个问题，涵盖商业应用、B2B 服务和开发者工具。设计为**未污染**（训练截止日期之后）。前沿模型在 Pro 上得分约 23%，在 Verified 上超过 70%。差距就是污染信号。

2026 年 4 月得分：
- Claude Opus 4.7 在 Pro 上：**64.3%**（报告采用显式智能体团队协调；Anthropic 尚未发布主要来源——视为初步结果）。
- Verdent（智能体支架）在 Verified 上：**76.1% pass@1**（[技术报告](https://www.verdent.ai/blog/swe-bench-verified-technical-report)）。
- 无智能体支架的前沿模型在 Pro 上的原始得分：约 23-35%（[SWE-bench Pro 论文](https://arxiv.org/abs/2509.16941)）。

关键点：“我们在 SWE-bench Verified 上击败了”不再反映能力。Pro 是当前的门槛测试。智能体团队支架在 Pro 上产生了可测量的增益（约 30-40 个百分点的增量），这是 2026 年支持多智能体协调的最有力实证依据之一。

### AAAI 2026 WMAC

AAAI 2026 Bridge Program — Workshop on Multi-Agent Coordination（https://multiagents.org/2026/）。2026 年多智能体 AI 研究的社区焦点。被录用的论文和研讨会论文集是评估新方法的规范场所；在做出生产决策时，应优先采纳 WMAC 接受的声明，而非 arXiv 预印本。

### 以怀疑的态度阅读基准声明——2026 检查清单

当有人声称多智能体结果时：

1. **哪个基准、哪个划分？** SWE-bench Verified 与 Pro 差异很大。在错误的划分上报告的数字毫无价值。
2. **污染检查。** 该基准是在模型训练截止日期之后发布的吗？如果不是，谨慎对待。
3. **基线比较。** 与单 LLM 基线比较、与随机基线比较、与之前的多智能体工作比较。而不是“与同一系统未经调整的版本比较”。
4. **统计显著性。** N 次试验、p 值、置信区间。前沿模型方差高；单次运行会产生误导。
5. **任务多样性。** 一个任务还是很多？泛化能力对生产环境至关重要。
6. **成本披露。** 每个任务的 token 数、挂钟时间。一个 90% 的解决方案但成本高 20 倍是商业决策，而非能力声明。

### 这些基准都没有很好地衡量的方面

- **长期协调。** 数天的挂钟交互。所有当前基准都运行时间短。
- **对抗鲁棒性。** 当某个智能体是恶意的或被攻破时会发生什么？
- **部署中的漂移。** 基准是静态的；生产分布会发生变化。
- **成本归一化的性能。** 大多数基准报告原始准确率，而不是每美元准确率。

为你在意的维度建立自己的内部基准通常是正确的做法。

## 构建它

`code/main.py` 是一个非交互式演练：

- 在一个玩具任务上模拟 3 个多智能体系统。
- 为每个系统计算 MARBLE 风格的里程碑指标。
- 通过从“训练”集中扣留任务来运行污染检查。
- 显式地与随机基线比较。
- 打印基准声明记分卡。

运行：

```bash
python3 code/main.py
```

预期输出：系统记分卡，包含原始准确率、里程碑达成率、每任务成本、与随机基线之差，以及污染检查注释。

## 使用它

`outputs/skill-benchmark-reader.md` 读取任何多智能体基准声明并应用审查检查清单。输出：一个等级和注意事项。

## 交付它

生产评估纪律：

- **构建反映你实际生产分布的内部基准。** 公共基准提供参考，但不能替代。
- **在每个比较中包含随机基线。** 如果你在协调任务上不能以较大幅度击败随机，则该任务可能是有问题的。
- **同时报告成本和准确率。** Token 成本和挂钟时间。运维团队两者都需要。
- **每季度重建基准。** 生产分布会变化；陈旧的基准会产生误导。
- **避免对公开基准过拟合。** 如果你的团队专门针对 SWE-bench Pro 数字进行优化，你将在生产环境上退化。

## 练习

1. 运行 `code/main.py`。识别三个模拟系统中哪一个每里程碑成本最优。它是否与最高原始准确率的系统一致？
2. 阅读 MultiAgentBench（arXiv:2503.01935）。针对你自己的任务领域，决定 MARBLE 会推荐四种拓扑中的哪一种。根据论文的结果证明你的选择。
3. 阅读 SWE-bench Pro 论文。具体是什么使其具有抗污染能力？同样的技术能否应用于你关心的其他基准？
4. 阅读 COMMA 关于多模态协调的发现。设计一个简单的多模态协调任务，你可以将其加入你的内部基准。什么算是有用的信号？
5. 将基准声明检查清单应用于最近一篇多智能体论文的标题结果。你会给该声明什么等级？

| MARBLE | "MultiAgentBench" | ACL 2025；星型/链型/树型/图型拓扑，带有里程碑 KPI。 |
