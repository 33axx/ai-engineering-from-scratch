# Native Sparse Attention (DeepSeek NSA)

> 在 64k 上下文长度下，注意力运算占据了 70-80% 的解码延迟。每个开源模型实验室都有自己的解决方案。DeepSeek 的 NSA（ACL 2025 最佳论文）是最终胜出的方案：通过三个并行的注意力分支——压缩的粗粒度 token、选择性保留的细粒度 token，以及用于局部上下文的滑动窗口——再通过一个可学习的门控合并。该方案与硬件对齐（对 kernel 友好），原生可训练（在预训练中即可工作，而非在推理时后接），并且在 64k 解码时比 FlashAttention 更快，同时匹配或超越全注意力的质量。本节课将端到端地构建这三个分支，并展示稀疏性为何是端到端可微分的。

**类型：** 构建
**语言：** Python（标准库）
**前置知识：** 阶段 7 · 12（KV 缓存，Flash Attention），阶段 7 · 15（注意力变体），阶段 10 · 16（微分注意力）
**时间：** 约 60 分钟

## 学习目标

- 阐述 NSA 的三个注意力分支及其各自捕获的内容。
- 解释为什么 NSA 是“原生可训练的”，而先前的稀疏注意力方法仅适用于推理。
- 计算在 64k 上下文下，NSA 相对于完整注意力在计算量上的节省，作为压缩块大小和选择 top-k 的函数。
- 在短合成序列上使用 Python 标准库实现三分支组合，并验证门控权重的行为。

## 问题

序列长度 N 下的完整注意力需要 `O(N^2)` 时间和每层 `O(N)` 的 KV 缓存。在 64k token 时，计算和内存带宽的数字是灾难性的。来自 NSA 论文的实测理论估计：在 64k 时，注意力占总解码延迟的 70-80%。所有下游指标——TTFT、token/秒、每百万 token 成本——都受注意力成本主导。

稀疏注意力是显而易见的答案。先前的尝试分为两类。固定模式稀疏性（滑动窗口、步进、块局部）会丢弃信息，在长程召回任务上失败。推理时稀疏性（KV 缓存剪枝、H2O、StreamingLLM）应用于在密集注意力上预训练的模型，只能恢复潜在加速的一小部分，因为模型从未被要求通过稀疏模式路由信息。

原生稀疏注意力（Yuan 等人，DeepSeek + PKU + UW，ACL 2025 最佳论文，arXiv:2502.11089）做到了两者兼顾：模型在预训练期间学习到的稀疏模式，实现为与 kernel 对齐的算法，在推理时实际交付计算节省。两年后，NSA 或其直接后代将成为每个前沿长上下文模型的默认注意力机制。

## 概念

### 三个并行分支

对于每个查询，NSA 对 KV 缓存的三种不同视图运行三次注意力：

1. **压缩分支。** Token 被分组为大小为 `l` 的块（通常为 32 或 64）。每个块通过一个小型学习到的 MLP 压缩成单个汇总 token。查询对这些压缩 token 进行注意力，获得整个序列的粗粒度视图。

2. **选择分支。** 利用来自压缩分支的注意力分数，识别与当前查询最相关的 top-k 个块。读取这些块中的细粒度（未压缩）token，查询对所有 token 进行注意力。可以将压缩分支的注意力视为选择的路由信号。

3. **滑动窗口分支。** 查询对最近的 `W` 个 token（通常为 512）进行注意力，以获取局部上下文。该分支捕获结构密集的短程模式（语法、局部共指），这些模式可能被另外两个分支遗漏。

三个分支的输出通过一个学习到的逐位置门控合并：

```
out = g_cmp * out_cmp + g_sel * out_sel + g_win * out_win
```

`g_cmp, g_sel, g_win` 是来自查询上一个小型 MLP 的门控权重。它们不必和为 1——可以独立地对分支进行加权。

### 为什么这是“原生可训练的”

选择步骤（top-k 块）是离散的。离散操作会中断梯度流。先前的稀疏注意力工作要么跳过选择步骤的反向传播（限制训练），要么使用连续松弛，但在推理时不提供真正的稀疏性。

NSA 绕过了这一点：压缩分支的注意力是可微分的粗粒度注意力，作用于整个序列。top-k 操作只是重用压缩分支中 top 注意力分数来决定要加载哪些细粒度块。梯度流经压缩分支的分数（它同时影响压缩输出和选择逻辑），所选块对最终输出的贡献也是可微分的。非可微的 `top_k` 操作在前向计算图中是一个无操作——它只控制哪些块从内存中加载。

这就是 NSA 可以端到端地用于预训练的原因。模型学会联合通过三个分支路由信息，产生一种稀疏模式，在推理时实际提供承诺的加速。

### 与硬件对齐的 kernel

NSA 的 kernel 专为现代 GPU 内存层次结构设计。Kernel 按 GQA 组（外层循环）加载查询，按组获取对应的稀疏 KV 块（内层循环），并在 SRAM 上运行注意力。因为每个查询组看到相同的所选块（选择是按查询组而非按查询头进行的），KV 加载在组内被分摊。算术强度保持较高。

论文报告，在 64k 解码上，Triton kernel 比 FlashAttention 快 9 倍，且加速比随序列长度增加而增长。前向和后向 kernel 均已提供。

### 计算预算

设 `N` 为序列长度，`l` 为压缩块大小，`k` 为 top-k 选择数量，`w` 为滑动窗口，`b` 为所选块大小（通常等于 `l`）。

- 压缩分支：每个查询 `O(N/l)` 个 key，因此总共 `O(N * N / l)`。
- 选择分支：每个查询 `O(k * b)` 个 key，因此总共 `O(N * k * b)`。
- 滑动分支：每个查询 `O(w)` 个 key，因此总共 `O(N * w)`。

总计：`O(N * (N/l + k*b + w))`。

取 `N = 64k, l = 64, k = 16, b = 64, w = 512`：每个查询的 key 数为 `1000 + 1024 + 512 = 2536` 个。完整注意力为 `64000` 个 key。计算量减少 25 倍。

取 `N = 128k, l = 64, k = 16, b = 64, w = 512`：每个查询的 key 数为 `2000 + 1024 + 512 = 3536` 个。完整注意力为 `128000` 个 key。减少 36 倍。收益随序列长度增加而增长，这正是关键所在。

### 如何比较

| 方法 | 可微分 | 实际推理加速 | 长程召回 |
|--------|---------------|----------------------|-------------------|
| 仅滑动窗口 | 是 | 是 | 失败 |
| 步进 / 块稀疏 | 是 | 是 | 部分 |
| KV 剪枝 (H2O, StreamingLLM) | 不适用（推理时） | 是 | 部分 |
| MoBA (Moonshot) | 部分 | 是 | 好 |
| NSA | 是（原生） | 是（64k 下 9x） | 匹配完整注意力 |

MoBA（Moonshot，arXiv:2502.13189）同期发表，采用类似的“三个胜过一个”方法，将 MoE 原则应用于注意力块。NSA 和 MoBA 是 2026 年长上下文预训练中需要了解的两种架构。

## 构建它

`code/main.py` 在短合成序列上实现三个分支，并展示：

- 压缩 MLP（为教学清晰起见，使用简单的均值池化基线；真实的 NSA 使用学习到的 MLP）。
- 由压缩分支分数驱动的 top-k 块选择。
- 对最后 `w` 个 token 的滑动窗口注意力。
- 门控合并。
- 与完整注意力对比的计算量计数打印。

### 步骤 1：将 token 压缩成块

```python
def compress(K, l):
    n = len(K)
    n_blocks = (n + l - 1) // l
    out = []
    for b in range(n_blocks):
        start, end = b * l, min((b + 1) * l, n)
        block = K[start:end]
        summary = [sum(row[d] for row in block) / len(block) for d in range(len(K[0]))]
        out.append(summary)
    return out
```

### 步骤 2：压缩分支注意力

对查询与压缩后的 key 运行 softmax 注意力。压缩分支的分数同时充当 top-k 选择的信号。

### 步骤 3：top-k 块选择

选取得分最高的 `k` 个压缩块的索引。从这些块中加载原始的未压缩 token，并对其运行注意力。

### 步骤 4：滑动窗口注意力

取最后 `w` 个 token，对其运行标准注意力。

### 步骤 5：门控 + 合并

查询上的一个小型 MLP 产生三个门控权重。最终输出是三个分支输出的加权和。

### 步骤 6：计算量计数

打印每个查询在每个分支上处理的 key 数及总数。与 `N`（完整注意力）比较。在 1024 token 的合成数据上，取 `l = 32, k = 4, w = 128`，NSA 每个查询处理 `32 + 128 + 128 = 288` 个 key，而完整注意力为 1024 个 —— 减少了 3.5 倍。

## 使用它

NSA 已在 DeepSeek 自己的长上下文预训练流水线中投入使用。截至 2026 年 4 月，在公共推理栈中的集成状态：

- **DeepSeek 内部**：原生，已发布的权重使用 NSA 或其继任者 DSA（DeepSeek Sparse Attention）。
- **vLLM**：正在为 DeepSeek-V3.x 权重开发实验性 NSA 支持。
- **SGLang**：发布了 NSA 基准测试；生产路径跟随 vLLM。
- **llama.cpp / CPU**：不支持；在 CPU 吞吐量下，kernel 分解的开销不值得。

何时使用 NSA：

- 针对 64k 以上上下文且有大量计算预算的预训练或持续训练任务。
- 对 DeepSeek 自己的长上下文检查点进行推理。权重是 NSA 原生的。

何时不使用：

- 服务于现有密集注意力预训练模型。没有持续训练就无法改造为 NSA。
- 上下文低于 16k。三分支的开销超过节省。
- 批量大小为 1 的交互式聊天。延迟敏感的解码会受益，但仅在长上下文时。

## 关键术语

| 术语 | 通俗说法 | 实际含义 |
|------|----------------|------------------------|
| 压缩分支 | “粗粒度视图” | 对块平均 key 的注意力，以每个查询 O(N/l) 个 key 提供全局上下文 |
| 选择分支 | “top-k 块” | 对压缩分支分数最高的 `k` 个块的细粒度注意力 |
| 滑动窗口 | “局部上下文” | 对最后 `W` 个 token 的注意力，用于短程模式 |
| 原生可训练性 | “预训练时打开稀疏性” | 稀疏模式在预训练期间学习，而非在推理时后接 |
| 压缩块大小 l | “粗粒度视图的组大小” | 多少个 token 合并成一个汇总；典型值 32-64 |
| Top-k | “保留的块数” | 读取其未压缩 token 的压缩块数量；典型值 16 |
| 滑动窗口 W | “局部注意力半径” | 通常为 512；更短损害局部连贯性，更长浪费计算 |
| 分支门控 | “如何混合三者” | 逐位置 MLP 输出，对三个分支的贡献进行加权 |
| 硬件对齐 | “对 kernel 友好的稀疏性” | 选择的稀疏模式使得实际 GPU kernel 能达到理论加速 |
| DSA | “NSA 的继任者” | DeepSeek Sparse Attention，DeepSeek 系列中紧随 NSA 的架构 |
