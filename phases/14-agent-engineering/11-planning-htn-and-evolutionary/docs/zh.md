# 使用 HTN 和进化搜索进行规划

> 符号规划处理计划可证明正确的情况。进化代码搜索处理适应度函数可机器检查的情况。ChatHTN (2025) 和 AlphaEvolve (2025) 展示了它们在与LLM配对时各自解锁的能力。

**类型：** 构建  
**语言：** Python (标准库)  
**前置知识：** 阶段14·02 (ReWOO 与 Plan-and-Execute)  
**时间：** ~75 分钟

## 学习目标

- 解释层次任务网络：任务、方法、操作符、前提条件、效果。
- 描述 ChatHTN 的混合循环——符号搜索与 LLM 后备分解。
- 解释 AlphaEvolve 的进化循环及其为什么只适用于编程式评估器。
- 使用标准库实现一个玩具 HTN 规划器和一个玩具进化搜索。

## 问题

ReWOO (第 02 课)、Plan-and-Execute 和 ReAct 涵盖了大多数智能体规划场景。它们未能很好处理的两个场景：

1. **具有可证明正确性的计划。** 调度、飞行路径规划、合规工作流——计划必须通过构造保证正确。一个流利的 LLM 计划有时会幻觉出一个步骤，这是不可接受的。
2. **具有可机器检查适应度函数的优化。** 矩阵乘法、调度启发式算法、编译器优化——目标不是“一个正确的计划”，而是“最佳计划”。

HTN 规划和 AlphaEvolve 解决了这两个不同的问题。两者都将 LLM 用作放大器，而非替代品。

## 概念

### 层次任务网络

一个 HTN 包含：

- **任务** ——复合任务（待分解）和原子任务（可直接执行）。
- **方法** ——将复合任务分解为子任务的方式，带有前提条件。
- **操作符** ——具有前提条件和效果的原子动作。
- **状态** ——一组事实。

规划：给定一个目标任务和一个初始状态，找到一种分解方式，使得原子操作符的顺序执行满足所有前提条件。

HTN 比 LLM 更古老，并且至今仍是可证明正确计划的参考方法。

### ChatHTN (Gopalakrishnan 等人，2025)

ChatHTN (arXiv:2505.11814) 将符号 HTN 与 LLM 查询交织在一起：

1. 尝试用现有方法分解当前复合任务。
2. 如果没有方法适用，则询问 LLM：“你如何在状态 `s` 下分解 `task`？”
3. 将 LLM 的响应翻译成候选子任务。
4. 根据操作符模式验证；拒绝无效的分解。
5. 递归。

论文的核心主张：生成的每个计划都是可证明正确的，因为 LLM 的建议仅作为候选分解进入，而绝非直接编辑计划。符号层掌控正确性；LLM 扩展方法库。

在线方法学习（OpenReview `gwYEDY9j2x`，2025 后续工作）增加了一个学习器，通过回归泛化 LLM 产生的分解——将 LLM 查询频率降低高达 75%。

### AlphaEvolve (Novikov 等人，2025)

AlphaEvolve (arXiv:2506.13131，DeepMind，2025 年 6 月) 是另一种不同的方法：由 Gemini 2.0 Flash/Pro 集成协调的进化代码搜索。

循环：

1. 从种子程序和一个编程式评估器（返回适应度分数）开始。
2. LLM 集成提出变异。
3. 通过评估器运行变异。
4. 保留最佳者；再次变异。

已公布的成果：

- 56 年来首次改进 Strassen 算法用于 4x4 复数矩阵乘法（48 次标量乘法）。
- 通过 Borg 调度启发式方法恢复 0.7% 的 Google 计算资源。
- 在前沿工作负载上实现 32% 的 FlashAttention 加速。

硬约束：适应度函数必须可机器检查。对散文式答案进行进化搜索不会收敛。

### 何时使用哪种方法

| 问题类别 | 使用方法 | 原因 |
|----------|----------|------|
| 具有硬约束的调度 | HTN + ChatHTN | 可证明的正确性 |
| 编译器优化 | AlphaEvolve | 可机器检查的适应度 |
| 多步骤任务执行 | ReAct / ReWOO | LLM 在循环中，无形式化保证 |
| 带测试的代码改进 | AlphaEvolve | 测试即评估器 |
| 策略驱动的自动化 | HTN | 前提条件编码策略 |

### 该模式在何处会出错

- **没有操作符的 HTN。** 没有前提条件/效果模式，正确性主张就会崩溃。ChatHTN 的“LLM 建议分解”需要模式来拒绝无效动作。
- **没有真实评估器的 AlphaEvolve。** “询问 LLM 代码是否更好”不是适应度函数。评估器必须是确定性的且速度快。
- **过度工程化。** 大多数智能体任务两者都不需要。首先考虑使用 ReAct 或 ReWOO。

## 动手构建

`code/main.py` 实现了两个玩具示例：

- 一个标准库 HTN 规划器，包含操作符、方法、前提条件、效果，以及一个 `LLMFallback`，当没有方法匹配复合任务时触发。这里的“LLM”是一个脚本化的分解器，因此规划器可以离线运行。
- 一个标准库进化搜索，针对算术程序：进化出在测试集上最小化 `|f(x) - target|` 的表达式。评估器是确定性的。

运行它：

```
python3 code/main.py
```

追踪输出显示 HTN 规划器分解一个复合任务（中途有 LLM 后备）以及进化循环收敛到一个目标表达式。

## 如何使用

- **HTN 规划器** ——`pyhop`、`SHOP3`，或者针对特定领域策略执行自行构建。
- **ChatHTN** ——研究代码；该模式（符号 + LLM 后备）可干净地移植到任何 HTN 规划器。
- **AlphaEvolve** ——DeepMind 论文；该模式（集成 + 评估器）可复现。OpenEvolve 和类似的开源分支正在涌现。
- **智能体框架** ——目前没有框架原生支持 HTN 或 AlphaEvolve。将其构建为子智能体或后台工作器。

## 交付物

`outputs/skill-hybrid-planner.md` 生成一个混合规划器脚手架（HTN 或进化），并明确限定 LLM 角色范围。

## 练习

1. 为 HTN 规划器增加回溯功能：当操作符的后置条件在运行时失败时，回滚并尝试下一个方法。
2. 为 ChatHTN 增加一个 LLM 方法缓存：当 LLM 在状态模式 `P` 下分解任务 `T` 时，存储结果。下次调用时首先检查方法库。
3. 将进化搜索的评估器替换为真实的测试套件。进化出一个通过 20 个测试用例的排序函数；报告收敛所需的代数。
4. 阅读 AlphaEvolve 的评估器设计笔记。为你关心的领域设计一个评估器（SQL 查询优化、测试套件最小化、部署 YAML）。
5. 结合使用：用 HTN 将复合任务分解为子任务，然后对每个子任务的原子操作符使用进化搜索。在哪些场景下这种方法表现出色，哪些场景下会过度工程化？

## 关键术语

| 术语 | 人们通常说的 | 实际含义 |
|------|--------------|----------|
| HTN | “层次规划器” | 具有操作符、前提条件、效果的任务分解 |
| 方法 | “分解规则” | 将复合任务拆分为子任务的方式 |
| 操作符 | “原子动作” | 带有前提条件和效果的具体步骤 |
| ChatHTN | “LLM + HTN” | 符号规划器在没有方法匹配时询问 LLM |
| AlphaEvolve | “进化代码搜索” | LLM 集成变异代码；确定性评估器进行选择 |
| 适应度函数 | “评估器” | 对输出进行确定性、可机器检查的评分 |
| 在线方法学习 | “缓存 LLM 分解” | 存储并泛化 LLM 计划以降低查询成本 |
