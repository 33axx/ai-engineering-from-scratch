# AI Scientist v2 — 工作坊级别的自主研究

> Sakana 的 AI Scientist v2（Yamada 等，arXiv:2504.08066）运行完整的研究循环：假设、代码、实验、图表、论文撰写、提交。它是首个让生成的论文通过 ICLR 2025 工作坊同行评审的系统。独立评估（Beel 等）发现 42% 的实验因编码错误而失败，文献检索经常将已有概念错误标记为新颖。Sakana 自己的文档警告，该代码库会执行 LLM 生成的代码，并建议使用 Docker 隔离。这幅图景的两面都是关键所在。

**类型:** 学习  
**语言:** Python（标准库，研究循环状态机玩具）  
**前置知识:** Phase 15 · 03 (AlphaEvolve), Phase 15 · 04 (DGM)  
**时间:** ~60 分钟

## 问题

研究是一项开放式的任务。与 AlphaEvolve 的算法搜索或 DGM 的基准受限自我修改不同，研究结果并没有机器可检查的正确性标准。论文由评审者而非单元测试来评判。这使得闭环更难实现——但如果实现了，其价值也更高，因为研究是复合进步所在。

AI Scientist v1（Sakana, 2024）通过从人类编写的模板出发来闭环。LLM 在固定的脚手架内填充实验。AI Scientist v2（Yamada 等，2025）通过使用基于智能体树搜索与视觉语言模型批评循环的方法，移除了模板需求。该系统生成想法、实现实验、制作图表、撰写论文，并针对评审反馈进行迭代。

同行评审结果：一篇 v2 生成的论文被 ICLR 2025 工作坊接收（已披露）。独立评估结论：该系统远不可靠。两者皆为事实。

## 概念

### 架构

1. **想法生成。** LLM 基于主题和已有文献提出研究想法。v1 使用模板；v2 使用对假设空间的智能体搜索。
2. **新颖性检查。** 通过文献检索步骤检查该想法是否已被发表。Beel 等人的评估发现这一步存在错误标记——已有方法被频繁分类为新颖。
3. **实验计划。** 智能体起草实验方案并编写代码。
4. **执行。** 代码在沙箱中运行。失败会反馈到重试循环中。根据 Beel 等人的测量，42% 的实验在这一阶段因编码错误而失败。
5. **图表生成。** 视觉语言模型读取生成的图表并重新绘制以提高清晰度。这是 v2 的关键技术新增点。
6. **论文撰写。** LLM 起草论文，并与内部评审者迭代。
7. **可选：提交。** 论文提交至某个会议/期刊。

### 工作坊接收结果意味着什么

一篇 v2 生成的论文在 ICLR 2025 工作坊通过了同行评审。作者向程序委员会披露了论文的出处。这一接收是一个数据点，并非声称该系统“在做研究”的许可。

重要背景：工作坊论文的门槛低于主会论文。同行评审存在噪声；在任何一天，只有一小部分投稿会被接收。一次成功是一个概念验证，而非可靠性声明。Nature 2026 的论文记录了端到端循环，且本身由人类研究人员合著；它并非“该系统写了一篇 Nature 论文”。

### 独立评估发现了什么

Beel 等人（arXiv:2502.14297）进行了外部评估。主要发现：

- **实验失败。** 42% 的实验因编码错误（错误的导入、形状不匹配、未定义变量）而失败。重试循环解决了一部分，但并非全部。
- **新颖性错误标记。** 文献检索步骤经常将已有概念标记为新颖。这是等同于幻觉的研究领域错误。
- **呈现质量差距。** 视觉语言模型的图表批评生成了出版级的视觉内容，掩盖了底层的实验缺陷。

最后一点对本阶段至关重要。一个能生成令人信服输出但并未进行令人信服研究的系统，比一个明显失败的系统更危险，而非更安全。评估必须触及底层声明，而不是停留在图表层面。

### 沙箱逃逸风险

Sakana 自己的仓库 README 警告：

> 鉴于本软件的特性（执行 LLM 生成的代码），我们无法保证安全。存在危险包、未受控的网络访问以及生成意外进程的风险。请自行承担风险，并考虑使用 Docker 隔离。

这是非验证领域自治的操作形态。LLM 编写代码；代码运行；代码可以执行其进程权限允许的任何操作。如果没有严格限制文件系统、网络和进程操作的沙箱，任何自我导向的研究智能体都可以泄露数据、消耗计算资源或重写自身。

AlphaEvolve 的沙箱故事更容易，因为它的评估器很严格。AI Scientist v2 的循环运行开放式代码，目标也是开放的。这就是为什么它需要更强的隔离（最低 Docker；推荐 seccomp / gVisor），并且在任何提交离开系统前进行人工审查。

### v2 在前沿栈中的位置

| 系统 | 目标 | 输出类型 | 评估器 | 已知失败 |
|---|---|---|---|---|
| AlphaEvolve | 算法 | 代码 | 单元测试 + 基准 | 受限于评估器严格程度 |
| DGM | 智能体脚手架 | 代码 | SWE-bench | 奖励黑客 |
| AI Scientist v2 | 研究论文 | 文本 + 代码 + 图表 | 同行评审（弱） | 实验失败、错误标记、润色掩盖弱点 |

v2 在这三个系统中拥有最弱的自动评估器、最广泛的输出面以及通往公共工件的最短路径。操作控制（沙箱、审查、披露）承担了大部分安全工作。

## 使用它

`code/main.py` 将 v2 循环模拟为状态机：想法 → 新颖性检查 → 实验 → 图表 → 论文撰写 → 评审 → 接收或迭代。每个状态都有一个从 Beel 等人发现中提取的可配置失败概率。运行 N 次循环的模拟器，并统计：

- 有多少想法到达提交阶段。
- 有多少提交会包含一个被润色后论文掩盖的关键实验缺陷。
- 重试预算如何在质量与产出之间权衡。

## 产出

`outputs/skill-ai-scientist-sandbox-review.md` 是一个双门审查清单，用于研究循环智能体产生的任何内容在离开沙箱之前。

## 练习

1. 使用默认参数运行 `code/main.py`。有多少比例的循环运行产生了“干净的”论文？有多少比例产生了带有实验缺陷（但被图表批评润色过）的论文？

2. 默认参数已使用 Beel 等人的 42% / 25%。使用 `--experiment-failure 0.20 --novelty-mislabel 0.10` 重新运行，然后再使用 `--experiment-failure 0.60 --novelty-mislabel 0.40` 运行。在两次运行之间，润色但有缺陷的论文比例如何变化？

3. 阅读 Sakana 的 AI Scientist v2 仓库 README 中关于沙箱要求的部分。列出你在一次多天的自主运行中会额外施加的两个限制（除了 Docker 之外）。

4. 阅读 Beel 等人论文的第 4 节关于呈现质量差距的内容。设计一个额外的评估器，能够捕捉到看似润色但实验上有缺陷的论文。

5. 提出一种针对研究智能体输出的人工审查协议，该协议比“一位博士生阅读每一篇论文”更具可扩展性。识别瓶颈并围绕它进行设计。

## 关键术语

| 术语 | 常被提及的含义 | 实际含义 |
|---|---|---|
| AI Scientist v1 | "Sakana 的模板化研究智能体" | 将实验填充到固定的脚手架中 |
| AI Scientist v2 | "无模板研究智能体" | 带有 VLM 图表批评的智能体树搜索 |
| 智能体树搜索 | "分支式研究智能体" | 并行展开多个实验计划；由内部批评者剪枝 |
| 视觉语言批评 | "VLM 对图表的润色" | 多模态模型阅读图表并重绘以提高清晰度 |
| 文献检索 | "新颖性检查" | 搜索已有工作以确认想法是否新颖——已被记录存在错误标记 |
| 润色掩盖 | "漂亮的论文，有缺陷的研究" | 呈现质量超过实验质量；掩盖弱点 |
| 沙箱逃逸 | "LLM 代码突破沙箱" | 智能体执行的代码做了循环设计者未预期的事情 |
