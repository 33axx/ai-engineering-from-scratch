# InternVL3: 原生多模态预训练

> 在 InternVL3 之前，每个开放 VLM 都遵循相同的三步配方：拿一个在数万亿文本 token 上训练过的文本 LLM，绑上一个视觉编码器，然后微调接缝。这有效，但有对齐债务——文本 LLM 将全部预训练预算花在了纯文本上，并非原生理解视觉 token。当你事后添加视觉时，LLM 必须重新学习如何将视觉输入与文本推理相关联，同时不忘掉文本。InternVL3（Zhu 等，2025 年 4 月）拒绝了事后方法：一次预训练运行，从第一步开始就将文本和多模态交错在一起。结果以 78B 参数开源在 MMMU-Pro 上匹配了 Gemini 2.5 Pro。本课程解读原生预训练的理由以及当你采用它时会发生什么变化。

**类型:** 学习
**语言:** Python（stdlib，训练语料混合器）
**前置知识:** 阶段 12·05，阶段 12·07（配方）
**时间:** 约 120 分钟

## 学习目标

-  解释为什么事后 VLM 训练会累积对齐债务，引用三个可测量的症状（灾难性遗忘、答案漂移、视觉-文本不一致）。
-  描述 InternVL3 的原生预训练语料混合比例，并解释为什么文本 : 交错 : 描述比例很重要。
-  比较 V2PE（可变视觉位置编码）和 Qwen2-VL 的 M-RoPE。
-  列举视觉分辨率路由器（ViR）和分离式视觉-语言部署（DvD）优化。

## 问题所在

事后 VLM 训练是默认做法。LLaVA、BLIP-2、Qwen-VL、Idefics——所有这些都使用一个已经预训练好的 LLM（Llama、Vicuna、Qwen、Mistral）并添加视觉。训练阶段通常如下：

1. 冻结 LLM + 冻结视觉编码器 + 可训练投影器，在描述对上进行训练以对齐嵌入。
2. 解冻 LLM，在指令数据（LLaVA-Instruct、ShareGPT4V）上训练。
3. 可选的任务特定微调。

表现出三种对齐债务症状：

- 灾难性遗忘。事后 VLM 会忘记纯文本技能。GSM8K 分数下降 5-10 分。Hellaswag 分数下降。纯文本智能体表现退化。
- 答案漂移。同一个视觉问题的不同措辞会得到不同的答案。视觉编码器与 LLM 的连接弱于 LLM 自身 token 之间的连接。
- 视觉-文本不一致。VLM 可以正确描述一张图片，然后回答一个与其自身描述相矛盾的问题。视觉 token 不像文本 token 那样参与 LLM 的内部一致性检查。

这些症状有充分记录。MM1.5 第 4 节量化了它们。LLaVA-OneVision 的消融实验暗示了它们。原生预训练就是答案。

## 概念

### 原生多模态预训练

InternVL3 从头开始在一个从第一步起就是原生多模态的语料库上训练。混合比例如下：

- 40% 纯文本数据（FineWeb、Proof-Pile-2 等）
- 35% 交错图像-文本数据（OBELICS、MMC4 风格）
- 20% 配对图像-描述数据
- 5% 视频-文本数据

视觉 token、文本 token 和跨模态交互都从第一个梯度步骤开始参与相同的损失函数。没有对齐预训练，没有投影器冻结阶段，没有需要恢复的灾难性遗忘。

基础模型的训练是单阶段的。指令调优随后进行，但基础模型已经将视觉 token 视为一等公民。

### V2PE（可变视觉位置编码）

Qwen2-VL 使用具有固定轴分配的 M-RoPE。InternVL3 引入了 V2PE：位置编码根据模态类型（文本、图像、视频）而变化，并使用可学习缩放。实践中：

- 文本 token 获得 1D 位置（文本索引）。
- 图像块获得 2D 位置（行、列）。
- 视频帧获得 3D 位置（时间、行、列）。

三者共享相同的 RoPE 频率基，但每个频带的隐藏维度分配是一个学习参数，而不是固定分割。在预训练期间可以自由权衡时间与空间频率分辨率。

V2PE 的消融实验主张：在相同计算量下，视频基准测试比 M-RoPE 高 1-2 分。不是革命性的，但更简洁。

### 视觉分辨率路由器（ViR）

部署优化。并非所有图像都需要全分辨率编码。一张包含单个低细节物体的照片在编码为 1280px 原生分辨率时会浪费 token。ViR 是一个小型分类器，它在编码之前预测回答问题所需的最小分辨率。

路由有三个层级：低分辨率（256 个 token）、中分辨率（576）、高分辨率（2048+）。在生产流量中，60% 的查询使用低分辨率或中分辨率就足够了。净效果：在相同质量下吞吐量提升 2-3 倍。

### 分离式视觉-语言部署（DvD）

当你服务一个大 VLM 时，视觉编码器每张图像运行一次，但 LLM 为每个输出 token 自回归运行。这两个组件有不同的瓶颈（视觉 = GPU 内存带宽用于卷积和注意力；LLM = KV 缓存）。DvD 将它们分离到不同的 GPU 上，并在之间进行流传输。

对于 8B + 400M 编码器模型，DvD 的每节点吞吐量大约是共址部署的两倍。

### 单阶段 vs 多阶段质量

InternVL3 的主要基准声明：在 78B 参数时，在 MMMU-Pro 上匹配 Gemini 2.5 Pro。在 38B 时匹配 GPT-4o。在 8B 时领先开放 8B 排行榜。所有这些都基于单阶段预训练 + 指令调优配方。

对齐债务假设是可测量的：InternVL3-8B 每单位视觉基准增益所损失的文本基准分数（MMLU、GSM8K）比 Qwen2.5-VL-7B 更少。该模型更像一个通才，因为训练是一个整体，而不是两个部分。

### InternVL3.5 和 InternVL-U

InternVL3.5（2025 年 8 月）扩展了配方。相同的原生预训练方法，更多数据，更多参数。MMMU 的改进是渐进的。

InternVL-U（2026 年）增加了统一生成——在同一条 backbone 之上通过 MMDiT 头进行图像输出。“U”代表“理解 + 生成”，追求 Transfusion 风格统一模型（第 12.13 课）。相同的原生预训练 backbone 支持理解和生成两种头。

### 原生预训练的权衡

原生预训练并非免费：

- 计算。从头训练一个新的 VLM 的成本与训练文本 LLM 相同——数百万 GPU 小时。事后适应重用现有 LLM 权重，节省了大部分成本。
- 数据。大规模的交错图像-文本语料库很稀缺。OBELICS 有 1.41 亿个文档；MMC4 有 5.71 亿个。纯文本则达到 15T token。多模态预训练数据稀缺是一个硬约束。
- 基础 LLM 重用。原生预训练放弃了以后替换新 LLM 的选项。事后可以让你只重新训练适配器就将 Llama-3.1 换成 Llama-4。

InternVL3 的赌注是：对齐债务比重用损失更糟糕。基准测试支持这一主张。生成成本使未来的实验室难以廉价复制。事后 VLM 将继续存在，因为它们对大多数项目来说仍然更便宜。

## 使用它

`code/main.py` 是一个训练语料混合器和 ViR 路由器模拟器。它可以：

- 给定目标语料混合比例（%文本，%交错，%描述，%视频），计算每个模态的期望步骤数。
- 在一批查询上模拟 ViR 路由（分布：50% 低细节，30% 中细节，20% 高细节）并报告平均 token 数。
- 根据编码器与 LLM 的 FLOPs 报告 DvD 吞吐量估计。
- 打印事后与原生预训练在参数、计算、数据和预期对齐债务症状方面的并排对比。

## 交付它

本课程产出 `outputs/skill-native-vs-posthoc-auditor.md`。给定一个提议的 VLM 训练计划，它会审计是采用原生还是事后方式，标记对齐债务风险，并推荐语料混合比例。当你正在评估一个新开放 VLM 项目并需要选择训练策略时使用它。

## 练习

1. 估计 InternVL3-8B（原生预训练）和 LLaVA-OneVision-7B（事后）之间的计算差异。GPU 小时数的大致比例是多少？差距的原因是什么？
2. InternVL3 报告了 40% 文本 / 35% 交错 / 20% 描述 / 5% 视频。如果你的目标任务偏向视频，提出一个新的比例，并论证为什么基础模型仍然需要大量文本和描述数据。
3. 阅读 MM1.5 第 4 节关于遗忘的内容。说出事后训练表现出最大回归的确切基准。回归代价有多大？
4. ViR 将 60% 的流量路由到低分辨率编码。什么样的查询会被它错误路由（发送到低分辨率但实际需要高分辨率）？提出三种路由器失效模式。
5. DvD 将视觉和 LLM 分离到不同 GPU 上。在什么流量模式下 DvD 反而会降低吞吐量而不是提升？

## 关键术语

| 术语 | 大家说的 | 实际含义 |
|------|----------|----------|
| 原生多模态预训练 | “从头一起训练” | 从第一步开始，文本 + 图像 + 视频 token 就参与损失，而不是后来才绑上去 |
| 对齐债务 | “事后惩罚” | 将视觉绑定到冻结 LLM 上所带来的文本技能和答案一致性的可测量退化 |
| V2PE | “可变视觉位置编码” | 每模态可学习位置编码分配；InternVL3 的 M-RoPE 继承者 |
| ViR | “分辨率路由器” | 小分类器，在编码前为每个查询选择所需最小分辨率，节省推理 token |
| DvD | “分离式部署” | 视觉编码器在一个 GPU 上，LLM 在另一个 GPU 上，流传输；对大型 VLM 吞吐量翻倍 |
| InternVL-U | “统一理解 + 生成” | 2026 年后续工作，为原生预训练 backbone 添加图像生成头 |
| 交错语料 | “OBELICS / MMC4” | 文本和图像以自然阅读顺序排列的文档；原生预训练的原材料 |
