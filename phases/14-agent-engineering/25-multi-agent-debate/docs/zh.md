# 多智能体辩论与协作

> Du 等人（ICML 2024，"Society of Minds"）运行 N 个模型实例独立提出答案，然后通过 R 轮迭代互相批评，最终收敛。提升了事实性、规则遵循和推理能力。稀疏拓扑在 token 成本上优于全连接。

**类型：** 学习 + 构建  
**语言：** Python（stdlib）  
**前置要求：** 第 14 阶段 · 12（工作流模式），第 14 阶段 · 05（Self-Refine 与 CRITIC）  
**时间：** ~60 分钟

## 学习目标

- 解释辩论协议：N 个提议者，R 轮迭代，收敛于一个共享答案。
- 描述为什么辩论能提升事实性、规则遵循和推理能力。
- 解释稀疏拓扑：并非每个辩论者都需要看到其他所有人。
- 使用 stdlib 实现一个基于脚本化 LLM 的辩论，包含全连接和稀疏两种变体；衡量 token 成本与准确率。

## 问题

Self-Refine（第 05 课）是单个模型自我批评——有群体思维的风险。CRITIC（第 05 课）将批评基于外部工具——并非始终可用。辩论引入了第三种模式：多个实例、相互批评、通过分歧收敛。

## 概念

### Society of Minds（Du 等人，ICML 2024）

- N 个模型实例独立对同一问题提出答案。
- 在 R 轮迭代中，每个模型阅读其他模型的提议并对其进行批评。
- 模型根据批评更新自己的答案。
- 经过 R 轮后，返回收敛的答案。

原始实验因成本原因采用 N=3，R=2。在困难问题（MMLU、GSM8K、象棋移动合法性、传记生成）上，增加智能体数量和轮次可提高准确率。

跨模型组合优于单一模型辩论：ChatGPT + Bard 一起使用 > 两者单独使用。

### 稀疏拓扑

"Improving Multi-Agent Debate with Sparse Communication Topology"（arXiv:2406.11776，2024-2025）表明全连接辩论并非始终最优。稀疏拓扑（星型、环型、中心辐射型）可以在较低 token 成本下达到相同准确率。每个辩论者只查看一部分同伴。

含义：

- 全连接 N=5，R=3 = 5 × 3 = 15 条提议，每人阅读 4 个同伴 = 60 次批评操作。
- 星型 N=5，R=3（1 个中心 + 4 个辐条）= 15 条提议，辐条只阅读中心 = 12 次批评操作。

### 辩论何时有益

- **事实性。** N 个独立提议，相互检查减少幻觉。
- **规则遵循。** 象棋移动合法性——一个模型遗漏规则，其他模型发现。
- **开放式推理。** 多种框架聚焦于正确答案。

### 辩论何时有害

- **对延迟敏感的用户体验。** N × R 轮串行迭代造成可能无法承受的延迟。
- **对成本敏感的规模。** 每个问题消耗 N × R 个 token。
- **简单的事实查找。** 一次查找比五次辩论更便宜。

### 2026 年实际实例

- **Anthropic 编排者-工作者**（第 12 课）——辩论的一种变体，包含综合步骤。
- **LangGraph 监督者**（第 13 课）——中央路由器 + 专门智能体可将辩论实现为一个节点。
- **OpenAI Agents SDK**（第 16 课）——智能体之间来回交接以进行迭代批评。
- **多智能体评估**——配对辩论 + 评估者-优化器以获得评估信号。

### 此模式出错的情形

- **收敛崩溃。** 所有智能体收敛于第一个错误答案。缓解方法：规定必须有分歧的轮次。
- **中心故障。** 在星型拓扑中，一个坏中心会污染所有人。轮换或使用多个中心。
- **提示同质化。** 所有智能体使用相同提示，产生相同答案。使用多样化提示和/或模型。

## 构建它

`code/main.py` 实现了 stdlib 辩论：

- `Debater` 类（脚本化 LLM，每个辩论者有独立的观点漂移）。
- `FullMeshDebate` 和 `SparseDebate` 运行器。
- 三个问题：一个是事实型，一个是基于规则的，一个是推理型。
- 指标：收敛答案、收敛轮次、总批评操作次数。

运行：

```
python3 code/main.py
```

输出：每种协议的准确率和成本；稀疏协议在 2/3 的问题上以更低成本匹配全连接。

## 使用它

- **Anthropic 编排者-工作者** 用于简单的 2-3 工作者辩论。
- **LangGraph** 用于有状态的多轮辩论，支持检查点。
- **自定义实现** 用于研究或特定正确性保证。

## 交付它

`outputs/skill-debate.md` 提供了一个可配置的多智能体辩论框架，包含拓扑、N、R 和收敛规则。

## 练习

1. 实现一个"强制分歧"规则：在第 1 轮中，每个辩论者必须提出不同的提议。衡量对收敛速度的影响。
2. 添加置信度加权聚合：辩论者返回 (答案, 置信度)；聚合器按置信度加权。是否有帮助？
3. 将一个"智能体"替换为具有不同观点的不同脚本化 LLM。异质性是否提高准确率？
4. 针对你的 3 个问题，测量全连接与稀疏的 token 成本。绘制成本与准确率的关系图。
5. 阅读 Society of Minds 论文。将你的玩具实现扩展到 N=5，R=3。哪些地方出问题？哪些方面变得更好？

## 关键术语

| 术语 | 人们常说的 | 实际含义 |
|------|------------|----------|
| 辩论 | "多智能体批评" | N 个提议者，R 轮相互批评，收敛 |
| 全连接 (Full mesh) | "每个人阅读每个人" | 每轮每个辩论者阅读所有同伴 |
| 稀疏拓扑 (Sparse topology) | "有限的同伴视图" | 辩论者只阅读部分同伴 |
| 中心辐射型 (Hub-and-spoke) | "星型拓扑" | 一个中央辩论者，N-1 个辐条只阅读中心 |
| 收敛 (Convergence) | "一致同意" | 辩论者收敛于一个共享答案 |
| Society of Minds | "Du 等人的辩论论文" | ICML 2024 多智能体辩论方法 |
