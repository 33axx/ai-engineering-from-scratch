# 文档与图表理解

> 文档不是照片。一份 PDF、科学论文、发票或手写表格具有布局、表格、图表、脚注、页眉和语义结构，纯粹的图像理解无法捕捉这些信息。VLM 之前的堆栈是一条流水线：Tesseract OCR + LayoutLMv3 + 表格提取启发式方法。VLM 浪潮用无 OCR 模型取代了这一堆栈——Donut（2022）、Nougat（2023）、DocLLM（2023）——它们直接输出结构化标记。到 2026 年，前沿技术就是“将页面图像以 2576 像素原生分辨率喂给 Claude Opus 4.7”，结构化标记输出自然生成。本课程讲述了文档 AI 的三个时代演进。

**类型：** 构建
**语言：** Python（标准库，布局感知文档解析器框架）
**前置知识：** 第 12 阶段 · 05（LLaVA），第 5 阶段（NLP）
**时间：** 约 180 分钟

## 学习目标

- 解释文档 AI 的三个时代：OCR 流水线、无 OCR、VLM 原生。
- 描述 LayoutLMv3 的三个输入流：文本、布局（边界框）、图像块，以及统一掩码。
- 比较 Donut（无 OCR，图像 → 标记）、Nougat（科学论文 → LaTeX）、DocLLM（布局感知生成式）、PaliGemma 2（VLM 原生）。
- 为新任务（发票、科学论文、手写表格、中文收据）选择文档模型。

## 问题所在

“理解这份 PDF”其实非常困难。信息分布在：

- 文本内容（90% 的信号）。
- 布局（页眉、脚注、侧边栏、双栏格式）。
- 表格（行、列、合并单元格）。
- 图表和示意图。
- 手写批注。
- 字体和排版（标题 vs 正文）。

原始 OCR 只提取文本，丢失了其余信息。一个关心发票的系统需要知道“总计：$1,245”来自右下角，而不是来自脚注。

## 概念

### 时代 1 —— OCR 流水线（2021 年之前）

经典堆栈：

1. PDF → 每页图像。
2. Tesseract（或商业 OCR）提取文本，附带每个词的边界框。
3. 布局分析器识别块（页眉、表格、段落）。
4. 表格结构识别器解析表格。
5. 领域规则 + 正则表达式提取字段。

适用于清晰的印刷文本。在手写、歪斜扫描、复杂表格、非英语脚本上会失效。每种失效模式都需要自定义异常处理。

### TrOCR（2021）

TrOCR（Li 等人，arXiv:2109.10282）用基于合成和真实文本图像训练的 Transformer 编码器-解码器取代了 Tesseract 经典的 CNN-CTC。在手写和多语言文本上效果显著提升。但仍是一个流水线（检测器 + TrOCR + 布局），不过 OCR 步骤得到了极大改进。

### 时代 2 —— 无 OCR（2022-2023）

第一批无 OCR 模型说：完全跳过检测，直接将图像像素映射到结构化输出。

Donut（Kim 等人，arXiv:2111.15664）：
- 编码器-解码器 Transformer，编码器为 Swin-B。
- 对于表单理解为 JSON，对于摘要为 Markdown，或任何任务特定的模式。
- 无 OCR、无布局、无检测。

Nougat（Blecher 等人，arXiv:2308.13418）：
- 专门针对科学论文训练。
- 输出为 LaTeX / Markdown。
- 能处理方程、多栏布局、图表。
- 每个 arXiv 解析器都会调用的模型。

这些是专家模型，而非通用模型。Donut 处理科学论文会失败；Nougat 处理发票会失败。

### LayoutLMv3（2022）

一条不同的路线。LayoutLMv3（Huang 等人，arXiv:2204.08387）保留了 OCR，但增加了布局理解：

- 三个输入流：OCR 文本令牌、每个令牌的二维边界框、图像块。
- 跨三种模态的掩码训练目标（掩码文本、掩码块、掩码布局）。
- 下游任务：分类、实体提取、表格问答。

LayoutLMv3 是基于 OCR 的文档理解的巅峰。在表单和发票上表现出色。需要上游 OCR。在标准化文档基准上，是 VLM 之前的最佳准确率。

### DocLLM（2023）

DocLLM（Wang 等人，arXiv:2401.00908）是 LayoutLM 的生成式兄弟。基于布局令牌生成自由形式的答案。更适合文档上的问答；仍然依赖 OCR 输入。

### 时代 3 —— VLM 原生（2024 年以后）

2024 年的 VLM 已经足够好，可以完全替代流水线。将全页图像以高分辨率输入 VLM，提问，得到答案。

- LLaVA-NeXT 336-tile AnyRes 适用于小型文档。
- Qwen2.5-VL 动态分辨率原生支持 2048+ 像素。
- Claude Opus 4.7 支持 2576 像素的文档。
- PaliGemma 2（2025 年 4 月）专门针对文档和手写进行训练。

VLM 原生与 OCR 流水线之间的差距迅速缩小。到 2026 年，VLM 原生在以下方面胜出：

- 场景文本（手写 + 印刷，混合脚本）。
- 带合并单元格的复杂表格。
- 嵌入文本中的数学方程。
- 带有文本注释的图表。

OCR 流水线仍然在以下方面胜出：

- 大规模纯扫描工作负载，每页延迟至关重要。
- 流水线可靠性（确定性失败 vs VLM 幻觉）。
- 需要可审计 OCR 输出的监管环境。

### Claude 4.7 / GPT-5 前沿

在 2576 像素原生输入下，前沿 VLM 在文档理解上达到接近人类准确率。2026 年初的基准数字：

- DocVQA：Claude 4.7 ~95.1，PaliGemma 2 ~88.4，Nougat ~77.3，流水线 LayoutLMv3 ~83。
- ChartQA：Claude 4.7 ~92.2，GPT-4V ~78。
- VisualMRC：Claude 4.7 ~94。

闭源模型的差距主要来自分辨率和基础 LLM 的规模。7B 的开源模型略逊几分，但正在追赶。

### 数学方程与 LaTeX 输出

科学论文需要方程的精确 LaTeX 输出。Nougat 是在此之上训练的。经过 LaTeX 目标训练的 VLM（Qwen2.5-VL-Math、Nougat 衍生版）能产生可用的 LaTeX。没有显式的 LaTeX 训练，VLM 会产生可读但不精确的转录。

2026 年科学论文流水线：在 PDF 上链式使用 Nougat，然后对棘手的页面使用 VLM。

### 手写

仍然是最困难的子任务。印刷与手写混合（医生笔记、填写表单）是 OCR 流水线仍在成本上优于 VLM 的领域。纯手写 VLM 正在改进（Claude 4.7、PaliGemma 2）。

### 2026 年配方

对于一个新的文档 AI 项目：

- 纯印刷发票大规模处理：LayoutLMv3 + 规则，成本高效。
- 混合文档（科学 + 手写 + 表单）：VLM 原生（PaliGemma 2 或 Qwen2.5-VL）。
- 完整 arXiv 摄入：数学用 Nougat，图表用 VLM。
- 监管要求：OCR 流水线 + VLM 验证器进行交叉校验。

## 使用它

`code/main.py`：

- 一个玩具级布局感知分词器：给定（文本，边界框）对，产生 LayoutLMv3 风格的输入。
- 一个 Donut 风格的任务模式生成器：用于表单的 JSON 模板。
- 每页令牌预算在 OCR 流水线、Donut、Nougat 和 VLM 原生之间的比较。

## 交付

本课程产出 `outputs/skill-document-ai-stack-picker.md`。给定一个文档 AI 项目（领域、规模、质量、监管），在 OCR 流水线、无 OCR 专家模型和 VLM 原生之间进行选择。

## 练习

1. 你的项目每天处理 1000 万张发票。哪种堆栈能在不损失准确率的情况下最小化每页成本？

2. 为什么 LayoutLMv3 在表单问答上优于纯 CLIP-VLM，但在场景文本上表现不如？边界框流放弃了什么？

3. Nougat 生成 LaTeX。提出一个测试案例，其中 VLM 原生输出在 LaTeX 保真度上优于 Nougat，再提出一个 Nougat 胜出的案例。

4. 阅读 PaliGemma 2 论文（Google，2024）。与 PaliGemma 1 相比，提升文档准确率的关键训练数据增加是什么？

5. 设计一个监管安全混合方案：OCR 流水线作为主要，VLM 作为辅助交叉校验。如何解决分歧？

## 关键术语

| 术语 | 人们说的 | 实际含义 |
|------|----------|----------|
| OCR 流水线 | “Tesseract 风格” | 分阶段堆栈：检测 -> OCR -> 布局 -> 规则；确定性，脆弱 |
| 无 OCR | “Donut 风格” | 图像到输出的 Transformer，跳过显式 OCR；单一模型 |
| 布局感知 | “LayoutLM” | 输入包含每个令牌的边界框坐标；跨模态统一掩码 |
| VLM 原生 | “前沿 VLM” | 直接以高分辨率将页面图像输入 Claude/GPT/Qwen VLM；无流水线 |
| DocVQA | “文档基准” | 文档 VQA 标准；引用最多的分数 |
| 标记输出 | “LaTeX / MD” | 结构化输出格式，而非自由文本；支持下游自动化 |
