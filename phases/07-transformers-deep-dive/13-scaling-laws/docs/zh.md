# 缩放定律

> 2020 年 Kaplan 论文说：模型越大，损失越低。2022 年 Hoffmann 论文说：你训练不足。算力投入两个桶——参数量和 token 数——如何划分并不显而易见。

**类型:** 学习
**语言:** Python
**前置知识:** 阶段 7 · 05（完整 Transformer），阶段 7 · 07（GPT）
**时长:** ~45 分钟

## 问题

当你拥有 C FLOPs 的训练算力并希望获得最佳模型时，你面临两个旋钮：

1. **参数量（N）？** 模型越大，容量越高。
2. **训练 token 数（D）？** 数据越多，容量利用越好。

FLOPs 大致按 `6 × N × D` 缩放。你可以增大 N 并减少 D，或者增大 D 并减少 N。哪种更好？

2022 年之前，答案是“大力推 N”。GPT-3（2020）有 175B 参数，在约 300B token 上训练。比例大约为每参数 1.7 个 token。Kaplan 缩放定律支持了这一点。

Hoffmann 等人（2022）训练了一个名为 Chinchilla 的小型模型家族，发现了不同的结论：最优比例接近 **每参数 20 个 token**。GPT-3 训练不足 10 倍。Chinchilla（70B 参数，1.4T token）在每项基准测试上都击败了 GPT-3（175B，300B token），而推理成本降低了 2.5 倍。

2026 年是 Chinchilla 的世界——但有一个重要转折。Llama 3 8B 在 15 万亿个 token 上训练，比例为每参数 1,875 个 token。超出 Chinchilla 最优值九十四倍。对于将被大规模使用的模型，推理成本比训练成本更重要，因此为了更小的可部署规模而进行过度训练（超出 Chinchilla）是 2026 年的默认做法。

## 概念

![Chinchilla 曲线：不同 N/D 比例下损失 vs 算力](../assets/scaling-laws.svg)

### Hoffmann 定律

根据 Chinchilla 论文，损失遵循：

```
L(N, D) = A / N^α + B / D^β + E
```

- `N` = 参数量（非嵌入层）。
- `D` = 训练 token 数。
- `α ≈ 0.34`，`β ≈ 0.28`（大致对称）。
- `E ≈ 1.69`，不可约损失的极限。
- `A ≈ 406`，`B ≈ 411`。

两个项在缩放时相互权衡。对固定算力（C = 6ND）下的 N 求导并求解：

```
N_opt ≈ 0.6 × (C/6)^0.5
D_opt ≈ 0.6 × (C/6)^0.5
D_opt / N_opt ≈ 20
```

算力最优：每参数 20 个 token。

### 为什么还要过度训练

Chinchilla 最优值最小化了每训练 FLOP 的训练损失。但你只需要为训练付一次钱；推理成本却永远存在。

对于一个每月服务一万亿 token 的聊天机器人，推理成本主导总成本。Llama 的方法：训练更小的模型，训练更长时间。8B 在 15T token 上是深度推理优化的：

- 适合消费级 GPU。
- 延迟仅为 70B Chinchilla 最优模型的一小部分。
- 质量在大多数任务上足够接近。

DeepMind 2024 年的论文（“过度训练是新的最优”）将其形式化。对于推理主导的工作负载，根据服务量，合适的比例接近每参数 100-500 个 token。

### 涌现 vs 平滑性

声称：某些能力（算术、多步推理、思维链跟随）在某个规模下突然“涌现”。

Schaeffer 等人（2023）认为这是一种测量伪影：涌现指标使用不连续的评分（精确匹配、阈值准确率），掩盖了底层 logits 中的平滑改进。连续指标（交叉熵）则显示平滑曲线。

到 2026 年，共识是：通过连续损失进行的预测是可靠的。基准测试的跳跃往往是评分器伪影。应针对连续指标制定预算计划。

### 2026 年的图景

缩放定律仍然有效，但：

| 因素 | 变化方式 |
|--------|-------------|
| 数据质量 | 策划“优质”token（Phi 风格）可将曲线移动超过 2 倍有效算力 |
| MoE | 总参数量与活跃 FLOPs 解耦；缩放定律按活跃 FLOPs 计算 |
| 训练后处理 | 一些能力（指令跟随、代码）受 SFT+RLHF 的影响大于预训练 |
| 多模态 | 图像 + 文本 token 一起缩放；每种模态有单独的曲线 |
| 合成数据 | 模型生成训练数据；有效算力可以复合 |

Muon 优化器（Kimi Moonlight，2024）在匹配数据下相比 AdamW 显示出约 2 倍有效算力增益。2026 年的一些训练运行默认使用 Muon。它改变了缩放定律中的绝对值常数，但不改变其形状。

## 动手实践

参见 `code/main.py`。我们实现 Chinchilla 损失方程，并在多个算力预算下求解算力最优的 `(N, D)`。

### 第 1 步：Chinchilla 损失

```python
def chinchilla_loss(N, D, A=406.4, B=410.7, alpha=0.34, beta=0.28, E=1.69):
    return A / N ** alpha + B / D ** beta + E
```

在固定 `C = 6ND` 下，绘制 `L` 在 `(N, D)` 上的等高线图。找到最小值。

### 第 2 步：算力最优前沿

对于从 `1e17` 到 `1e25` FLOPs 的算力预算，找到在约束 `6ND = C` 下最小化损失的 `(N, D)`。验证比值 `D/N ≈ 20`。

### 第 3 步：过度训练成本

计算训练一个缩小 10 倍的模型（最优 N 的 1/10，最优 D 的 10 倍）所付出的额外损失。报告作为交换节省的推理 FLOPs（与 N 成比例）。

### 第 4 步：与实际模型比较

插入已知的 GPT-3、Chinchilla、Llama 3 8B、DeepSeek-V3（活跃参数）的 `(N, D)` 对，比较预测损失与报告损失。

## 应用

你不太可能自己训练一个前沿模型。但缩放定律告诉你：

1. **你的微调是否有足够的数据。** 如果你的任务特定数据低于基础模型每参数 20 个 token，预计会在某个损失下限处饱和。
2. **是否选择更大的基础模型。** 如果你将全部预算花在推理上，则倾向于更小但训练时间更长的模型。
3. **收益在何处递减。** 超过 Chinchilla 最优 1000 倍后，log 损失的变化将变成噪声。

**2026 年的研究轨迹：**

- **数据受限阶段。** 网络上有有限数量的高质量 token（经过过滤后的英语约 5-10 万亿）。前沿预训练正在接近这一上限。合成数据、多语言、多模态和 RLHF 规模微调是下一个杠杆。
- **算力倍增技巧。** Muon 优化器、MoE、更好的数据整理——每项都改变了绝对常数，而不改变渐近线。
- **RL 的缩放定律。** 开放问题。早期证据表明 RL 样本中存在幂律，但指数与预训练非常不同。

## 关键术语

| 术语 | 人们说的意思 | 实际含义 |
|------|-----------------|-----------------------|
| 参数量 (N) | “模型大小” | 非嵌入层权重数量；决定容量。 |
| Token 数 (D) | “训练数据” | 已看到的训练 token 数量；决定参数被利用的程度。 |
| 算力 (C) | “花费的 FLOPs” | 对于标准 Transformer 近似为 `6 × N × D`。 |
| Chinchilla 最优 | “D/N ≈ 20” | 使每预训练 FLOP 的损失最小化的比例。 |
| 过度训练 | “超出 Chinchilla” | 花费额外训练 FLOPs 以节省推理 FLOPs；D/N >> 20。 |
| 不可约损失 | “下限” | 缩放定律中的 `E` 项；数据本身的熵。 |
| 涌现能力 | “在规模下突然跳跃” | 往往是评分器伪影；连续损失是平滑的。 |
| 有效算力 | “训练效率倍增器” | 更好的数据 / 优化器 / 架构使得每个 FLOP 走得更远。 |
