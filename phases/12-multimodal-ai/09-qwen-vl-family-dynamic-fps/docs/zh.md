# Qwen-VL 家族与动态FPS视频

> Qwen-VL 家族——Qwen-VL（2023）、Qwen2-VL（2024）、Qwen2.5-VL（2025）、Qwen3-VL（2025）——是2026年最具影响力的开源视觉语言模型系列。每一代都作出了一个决定性的架构选择，其余开源生态在十二个月内纷纷效仿：基于 M-RoPE 的原生动态分辨率、带绝对时间对齐的动态FPS采样、ViT 中的窗口注意力，以及结构化的智能体输出格式。到了 Qwen3-VL，设计已趋于稳定：一个支持原生宽高比输入的 2D-RoPE-ViT 编码器、一个将视觉特征投射到大语言模型 Qwen3 的 MLP 投影器，以及将 OCR、定位和智能体行为作为一等目标的训练阶段。本课按时间线阅读该家族，让您理解每个旋钮为何位于当前位置。

**类型：** 学习

**前置知识：** 第12阶段·06（patch-n'-pack）

## 学习目标

- 计算 M-RoPE 的三轴旋转（时间、高度、宽度）并解释为何需要三者。
- 为视频选择动态FPS采样策略，并推理 tokens-per-second 与事件检测精度的关系。
- 按顺序说出 Qwen-VL 的四代升级及每一代带来的能力。
- 构建 Qwen2.5-VL 风格的 JSON 智能体输出格式，并从 VLM 响应中解析结构化工具调用。

## 问题

Qwen-VL 于2023年8月发布，直接对标 LLaVA-1.5 和 BLIP-2。Qwen 团队瞄准的差距有三方面：分辨率、视频和结构化输出。

分辨率：LLaVA-1.5 运行在 336×336 分辨率下。这对照片很好，但对中文发票或密集的电子表格截图无用。Qwen-VL 的第一个创新是 448×448 以及带定位边界框的输出，让模型能够指向物体。

视频：Video-LLaMA 堆叠了每帧编码器并将其输入语言模型。它适用于短视频片段，但对于多分钟长度的视频（其中时间轴是核心信号）则不够用。Qwen 团队希望一个单一的编码器就能理解时间。

结构化输出：LLaVA 输出自由文本。智能体需要 JSON。Qwen-VL 在明确的 JSON 输出格式（包括以文本形式输出边界框坐标）上进行了训练。

Qwen-VL 的每一代都在这三个轴线上进行了扩展。

## 概念

### Qwen-VL（2023年8月）

第一代：编码器为 OpenCLIP ViT-bigG/14（2.5B 参数），兼容 LLaMA 的 Q-Former（单步，256 个查询），基座模型为 Qwen-7B。贡献：

- 448×448 分辨率（当时开源 VLM 的最优水平）。
- 定位：在图像-文本对上进行训练，输出显式的坐标 token。"The cat is at <box>(112, 204), (280, 344)</box>"。
- 从训练之初就包含中英文双语训练。

当时的基准：英文上与 GPT-4V 相当，中文上处于领先地位。定位监督才是真正的亮点。

### Qwen2-VL（2024年9月）——M-RoPE 和原生分辨率

Qwen2-VL 用原生动态分辨率的 ViT 编码器替换了固定分辨率 + Q-Former 堆栈。关键变化：

- 原生动态分辨率。ViT 接受任何能被 28 整除的 H×W（patch 14，2×空间合并）。1120×672（40×24 合并 patch）的图像产生 960 个视觉 token。无需缩放、分块或缩略图。
- M-RoPE（多模态 RoPE）。每个 token 携带 3D 位置（t, h, w），而不是 1D。对于图像 t=0，对于视频 t = 帧索引。RoPE 按每个轴频率对 query/key 向量进行旋转。无位置嵌入表。
- MLP 投影器。去掉 Q-Former；在合并的 patch token 上使用两层 MLP。
- 动态FPS视频。默认视频以 1-2 FPS 采样，但模型接受任意帧数。

结果：Qwen2-VL-7B 在多个多模态基准上匹配 GPT-4o，并在 DocVQA（94.5 vs 88.4）上超越它。架构变化是决定性的举措。

### Qwen2.5-VL（2025年2月）——动态FPS + 绝对时间

Qwen2.5-VL 的重大转变在视频。动态FPS 不仅仅是“需要时采样更多帧”。论文形式化了：

- 绝对时间 token。不使用位置索引（帧0, 1, 2...），而是使用实际时间戳。"At 0:04, the cat jumps." 模型看到 `<time>0.04</time>` token 与帧 token 交错排列。
- 动态FPS。对于慢速素材以 1 FPS 采样，对于动作场景以 4+ FPS 采样。由用户或训练器选择；M-RoPE 自适应。
- ViT 中的窗口注意力。空间注意力限制在局部窗口内（块内），以提高吞吐量；每若干层加入全局注意力。
- 明确的 JSON 输出格式。在工具调用数据上训练：`{"tool": "click", "coords": [380, 220]}`。开箱即用的智能体准备。
- MRoPE-v2 缩放。位置随最大输入大小缩放，使得 10 分钟视频不会超出频率范围。

基准：Qwen2.5-VL-72B 在大多数视频基准上超越 GPT-4o，在文档上匹配 Gemini 2.0，并在 GUI 定位上创下开源模型最优 (ScreenSpot: 84% 准确率 vs GPT-4o 的 38%)。

### Qwen3-VL（2025年11月）

Qwen3-VL 是增量升级，更多是整合而非重新发明：更大的语言模型主干（Qwen3-72B）、扩展的训练数据、改进的OCR、通过 Qwen3 的“思考模式”增强的推理能力。ViT 和 M-RoPE 保持不变。论文重点关注数据和训练改进，而非架构变化。

系列总结：到2025年，Qwen-VL 架构已稳定。后续世代扩展的是计算和数据，而非基本构件。

### M-RoPE 的数学原理

经典 RoPE 使用配对坐标将维度为 d 的查询 `q` 按位置 `m` 旋转：

```
q_rot[2i]   = q[2i]   * cos(m * theta_i) - q[2i+1] * sin(m * theta_i)
q_rot[2i+1] = q[2i]   * sin(m * theta_i) + q[2i+1] * cos(m * theta_i)
theta_i     = 10000^(-2i/d)
```

M-RoPE 将隐藏维度分成三个频带。假设 `d=96`。分配 32 维给时间，32 维给高度，32 维给宽度。每个频带按各自的轴位置旋转。位置为 (t=5, h=10, w=20) 的 patch，其三个频带分别应用旋转 `R_t(5)`、`R_h(10)`、`R_w(20)`。

文本 token 使用 `t=text_index, h=0, w=0`（或归一化选择），保持兼容性。视频帧使用 `t=frame_time, h=row, w=col`。单张图像使用 `t=0`。

好处：一个位置编码就能处理文本、图像和视频，无需分支代码或不同的位置表。

### 动态FPS采样逻辑

给定时长 `T` 秒的视频和目标 token 预算 `B`：

1. 计算能负担的最大 FPS：`fps_max = B / (T * tokens_per_frame)`。
2. 从 `{1, 2, 4, 8}` 中选择满足 `fps <= fps_max` 的目标 FPS。
3. 如果运动剧烈（基于光流启发式或用户显式请求），则选择更高的 FPS。如果运动缓慢，则选择较低的 FPS。
4. 以所选 FPS 均匀采样；在帧之间插入 `<time>t</time>` token。

Qwen2.5-VL 隐式地训练这一逻辑；推理时用户通过 `fps` 参数控制。一个 60 秒的动作序列，以 4 FPS 采样，每帧 81 个 token，共 19440 个 token，在 32k 上下文中是可控的。

### 结构化智能体输出

Qwen2.5-VL 的智能体训练明确针对结构化工具调用：

```
{
  "tool": "mouse_click",
  "coords": [1024, 512],
  "button": "left",
  "modifier": null
}
```

解析是确定性的：在模型输出上使用 `JSON.parse`。相比之下，自由形式的 "click at (1024, 512)" 需要正则表达式和歧义处理。这一转变是 Qwen2.5-VL 在 ScreenSpot 上的分数从 Qwen2-VL 的 55% 跃升至 84% 的原因。

## 关键术语

| 术语 | 人们怎么说 | 实际含义 |
|------|------------|----------|
| M-RoPE | "多模态 RoPE" | 具有时间、高度和宽度频带的 3D 旋转位置嵌入，分布在隐藏维度中 |
| 动态 FPS | "智能采样" | 根据视频的运动、时长和 token 预算，为每个视频选择帧采样率 |
| 绝对时间 token | "时间戳 token" | 在序列中交错插入 `<time>t</time>`，使模型看到实际秒数而非帧索引 |
| 窗口注意力 | "局部注意力" | 空间自注意力限制在小窗口内以提高速度；周期性加入全局注意力 |
| 结构化智能体输出 | "JSON 模式" | 训练数据监督，教会 VLM 输出可解析的 JSON，包含坐标和工具名称 |
| min_pixels / max_pixels | "分辨率界限" | 每次请求的 Qwen2.5-VL 控制，限制总像素数，从而限制 token 数 |
| 定位 Grounding | "指向它" | 以文本 token 形式输出边界框坐标；自 Qwen-VL v1 起使用 |
