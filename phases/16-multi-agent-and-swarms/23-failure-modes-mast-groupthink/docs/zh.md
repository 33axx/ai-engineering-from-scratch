# 失败模式 — MAST、群体思维、单一文化、级联错误

> 2026年的参考分类法是 **MAST**（Cemri等人，NeurIPS 2025，arXiv:2503.13657），该分类法基于7个最先进的开源MAS的1642条执行轨迹得出，显示**失败率为41–86.7%**。三个根本类别：**规约问题（41.77%）** — 角色模糊、任务定义不清晰；**协调失败（36.94%）** — 通信中断、状态不同步；**验证缺口（21.30%）** — 缺少验证、缺乏质量检查。**群体思维**家族（arXiv:2508.05687）增加了：单一文化崩溃（相同基座模型 → 相关错误）、从众偏差（智能体互相强化错误）、心智理论缺陷、混合动机动态、级联可靠性失败。级联示例：重试风暴——一次支付失败触发订单重试，订单重试触发库存重试，进而压垮库存服务（数秒内负载增长10倍——需要断路器）。记忆中毒：一个智能体的幻觉进入共享内存，下游智能体将其视为事实；准确度逐渐下降，导致根因诊断痛苦不堪。**STRATUS**（NeurIPS 2025）报告通过专门的检测/诊断/验证智能体，缓解成功率提升1.5倍。本课将失败模式视为第一类工程目标。

**类型：** 学习
**语言：** Python（标准库）
**前置条件：** 阶段16 · 13（共享内存），阶段16 · 14（共识与BFT），阶段16 · 15（投票与辩论拓扑）
**时间：** ~75分钟

## 问题

多智能体系统在实际任务中失败率为41-86.7%（Cemri等人2025年在7个开源MAS中测得）。这不能通过“多加几个智能体”来调试。失败有其结构性原因。MAST分类法提供了类别。本课将每个类别映射到具体的检测、诊断和缓解模式，使这些数字不再显得随意。

2026年的生产实践是将失败模式作为设计输入。只有当你能指出每个MAST类别并说出你部署的缓解措施时，你的架构才算“足够好”。

## 概念

### MAST类别

**规约问题（占失败率的41.77%）。** 智能体的任务定义不够严谨。示例：

- 角色模糊：两个智能体都认为自己是评审者。
- 任务规约不足：“总结这个”，而用户想要特定角度。
- 成功标准隐含：智能体无法判断自己是否成功。

缓解措施：
- 编写显式角色契约。每个智能体的提示都说明它做什么*以及不做什么*。
- 每个任务的验收测试。在智能体开始之前，定义“完成的样子是X”。
- 前置规约检查：一个独立的智能体在分派任务之前审查任务定义。

**协调失败（36.94%）。** 通信或状态故障。示例：

- 两个智能体无同步地更新共享状态。
- 智能体间消息丢失（队列故障、超时）。
- 状态漂移：智能体A认为任务完成；智能体B仍在执行。

缓解措施：
- 带乐观并发的版本化共享状态。
- 关键消息的显式确认（重试直到确认）。
- 定期状态同步检查点；及早检测漂移。

**验证缺口（21.30%）。** 对输出缺乏独立检查。示例：

- 一个智能体声称成功；无人验证。
- 智能体链条中每个智能体都信任前一个的输出。
- 对涌现的组合行为缺乏测试覆盖。

缓解措施：
- 独立验证智能体（第13课）。只读、独立源访问。
- 显式移交契约：“A的输出必须通过检查器C后B才能开始。”
- 输出日志记录用于事后分析。

### 群体思维家族（arXiv:2508.05687）

当智能体同质化或互相模仿时产生的五种相关失败：

**单一文化崩溃。** 相同基座模型或训练数据 → 相关错误。当三个智能体共享一个LLM时，它们共享其幻觉。

**从众偏差。** 智能体倾向于附和声音最大或最自信的同级者，即使它是错的。

**心智理论缺陷。** 智能体无法建模彼此的信念；协调崩溃（第18课）。

**混合动机动态。** 具有部分一致激励的智能体趋向于折中中间地带，这令任何一方都不满意。

**级联可靠性失败。** 一个组件的错误模式触发依赖组件中的错误模式。

### 级联示例——重试风暴

一个典型的2026年事故模式：

```
payment service fails 10% of requests
   ↓
order agent retries payment (exponential backoff but naive)
   ↓
each retry is a new order-inventory check
   ↓
inventory service sees 2x normal load
   ↓
inventory service starts timing out
   ↓
every order retries inventory check
   ↓
inventory service sees 10x normal load
   ↓
cluster goes down
```

修复方法是经典的：**断路器**。当下游错误率超过阈值时，短路并用缓存或默认结果响应。外加每请求的重试预算上限。

断路器是从分布式系统中直接借用而无需修改的少数几种多智能体失败缓解措施之一。

### 记忆中毒（复习）

来自第13课：一个智能体的幻觉成为共享内存中的事实；下游智能体基于中毒事实推理。用MAST术语来说，这是共享内存层的验证缺口。

准确度逐渐下降是症状。你不会得到崩溃，而是难以根因分析的缓慢漂移。

缓解措施：仅追加日志、溯源、不可写入验证器。已在第13课中涵盖。

### STRATUS — 专门用于失败检测的智能体

STRATUS（NeurIPS 2025）报告，当你部署以下内容时，缓解成功率提升1.5倍：

- **检测智能体。** 监测症状模式（高分歧、重试峰值、准确度漂移）。
- **诊断智能体。** 给定症状，从MAST分类推断可能的根因。
- **验证智能体。** 在应用缓解措施后，检查症状是否消除。

这是SRE风格的事故响应，应用于智能体系统。这三个角色都可以是带有专用提示的LLM智能体。

### 失败模式审计

2026年的最佳实践是每年（或每次大版本发布）进行一次失败模式审计：

1. **轨迹采样。** 收集约1000条真实执行轨迹。
2. **分类。** 对于每条轨迹的失败，映射到MAST + 群体思维类别。
3. **计算各类别失败率。** 哪些类别在你的系统中占主导？
4. **对缓解措施排序。** 哪个修复能消除最多的失败？
5. **选择2-3项缓解措施。** 实施；下个季度重新审计。

这种纪律比具体选择更重要。没有审计，失败会混入噪声中，永远不会被系统性地解决。

### 当系统静默失败时

最危险的失败类别是静默正确性失败。一个大声失败的系统（崩溃、异常、告警）可以被监控。一个产生看似合理但错误输出的系统无法通过异常日志检测。这就是为什么每个失败的验证缺口按次计算代价最高，尽管按数量统计只占21.30%。

投资于：
- 基于样本的人工审查。
- 黄金数据集回归测试。
- 对重要输出进行交叉智能体互相检查。

### 失败与慢速失败

有些失败是立即发生的；有些是缓慢发生的。立即失败（超时、模式不匹配、认证错误）易于检测。缓慢失败（记忆中毒、单一文化漂移、角色模糊）难以检测和预防。

2026年的工程举措：为慢速失败配备代理指标，以便在漂移变成可见错误之前捕捉它。共识率、重试率、输出长度分布以及连续智能体版本间的编辑距离都是有用的代理指标。

## 交付它

生产中的失败模式纪律：

- **每季度一次MAST审计。** 不是每年。随着系统增长，类别会变化。
- **处处使用断路器。** 对每个对任何依赖服务的出站调用。默认打开阈值为5-10%错误率。
- **黄金数据集。** 小型、高质量、人工审计。每周进行回归测试。
- **STRATUS三件套。** 检测 + 诊断 + 验证智能体监控生产环境。先从检测智能体开始；当症状变得嘈杂时再加入诊断。
- **失败预算。** 每个类别的失败率有显式SLO。超出预算会触发暂停发布讨论。

## 练习

1. 运行 `code/main.py`。确认断路器限制了重试风暴。改变失败阈值并观察权衡。
2. 实现一个**慢速失败代理指标**：3个并行智能体间的共识率。当它急剧下降时触发告警。通过逐渐关联智能体输出来模拟单一文化漂移。
3. 阅读Cemri等人（arXiv:2503.13657）。选择他们7个MAS系统中的一个，映射其前3个失败类别。它们与MAST预测的相比如何？
4. 阅读群体思维论文（arXiv:2508.05687）。确定五个模式中哪一个最难在生产中检测。提出一个代理指标。
5. 为你熟悉的一个特定多智能体系统设计一个STRATUS风格的检测-诊断-验证三件套。检测器关注哪些症状？诊断器推荐哪些缓解措施？验证器如何确认它们有效？

## 关键术语

| 术语 | 人们常说的意思 | 实际含义 |
|------|----------------|------------------------|
| MAST | “2026年的分类法” | Cemri 2025；3个根类别 + 14个子类型的失败。 |
| 规约问题 | “角色模糊” | 任务或角色定义不足；智能体不知道做什么。 |
| 协调失败 | “状态漂移” | 智能体间通信或同步故障。 |
| 验证缺口 | “没人检查” | 输出未经独立验证就被接受。 |
| 群体思维家族 | “同质化失败” | 单一文化、从众、心智理论缺陷、混合动机、级联。 |
| 单一文化崩溃 | “相同模型，相同幻觉” | 共享基座模型或训练数据导致的相关错误。 |
| 重试风暴 | “级联错误放大” | 一次失败触发重试，放大下游负载。 |
| 断路器 | “错误率过高时快速失败” | 当错误率超过阈值时打开；短路并用默认结果响应。 |
| STRATUS | “事故响应三件套” | 检测 + 诊断 + 验证智能体。缓解成功率提升1.5倍。 |
| 记忆中毒 | “幻觉传播” | 共享内存事实被污染；下游智能体基于毒化信息推理。 |
