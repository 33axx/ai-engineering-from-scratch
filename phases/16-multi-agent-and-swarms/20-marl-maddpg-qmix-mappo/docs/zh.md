# MARL — MADDPG, QMIX, MAPPO

> 多智能体协调的强化学习传统，在 2026 年仍对 LLM 智能体系统产生影响。**MADDPG**（Lowe 等人，NeurIPS 2017，arXiv:1706.02275）引入了集中训练、分散执行（CTDE）：每个评论家在训练时看到所有智能体的状态和动作；测试时仅本地演员运行。适用于合作、竞争和混合场景。**QMIX**（Rashid 等人，ICML 2018，arXiv:1803.11485）是一种带有单调混合网络的值分解方法；每个智能体的 Q 值组合成联合 Q 值，使得 `argmax` 干净地分布——在星际争霸多智能体挑战赛（SMAC）中占主导地位。**MAPPO**（Yu 等人，NeurIPS 2022，arXiv:2103.01955）是带有集中值函数的 PPO；“令人惊讶地有效”，在粒子世界、SMAC、Google Research Football、Hanabi 上只需最少的调参。这些方法为必须分散行动的智能体团队训练策略奠定了基础。MAPPO 是 **2026 年合作式 MARL 的默认基线**。本课程将通过一个小型网格世界玩具构建这三个概念，并在触及 LLM 智能体训练之前将它们内化为肌肉记忆。

**类型：** 学习
**语言：** Python（stdlib，不使用 NumPy 的小型实现）
**前置知识：** 阶段 09（强化学习），阶段 16·09（并行群体网络）
**时长：** ~90 分钟

## 问题

LLM 智能体系统越来越多地训练智能体间协调的策略：何时推迟、何时行动、调用哪个同伴。教你如何训练此类策略的文献是多智能体强化学习（MARL），它早于 LLM 浪潮，并且有一小套主导算法。

没有模式词汇表，阅读 MARL 论文会很痛苦。集中训练与分散执行（CTDE）、值分解和集中评论家并不是流行语——它们是对特定问题的具体答案：

- 独立 RL（每个智能体单独学习）从每个智能体的角度来看是非平稳的。不好。
- 集中式 RL（一个智能体控制所有）不能扩展，并且违反执行约束。
- CTDE 兼得两者之长：用全局信息训练，用局部策略部署。

## 概念

### 论文中使用的三个环境

- **粒子世界（多智能体粒子环境）。** 简单的 2D 物理，具有合作/竞争任务。MADDPG 最初的测试平台。
- **星际争霸多智能体挑战赛（SMAC）。** 合作微操作，部分观测。QMIX 的测试平台。离散动作，连续状态。
- **Google Research Football、Hanabi、MPE。** MAPPO 的基准测试。

不同的环境具有不同的动作/观测类型。算法相应地选择。

### MADDPG（2017）——CTDE 模式

每个智能体 `i` 有一个演员 `mu_i(o_i)`，将其观测映射到动作。每个智能体还有一个评论家 `Q_i(x, a_1, ..., a_n)`，在训练期间看到所有观测和所有动作。演员根据评论家的评估进行策略梯度更新。

```
actor update:    grad_theta_i J = E[grad_theta mu_i(o_i) * grad_a_i Q_i(x, a_1..n) at a_i=mu_i(o_i)]
critic update:   TD on Q_i(x, a_1..n) given next-state joint estimate
```

为什么是 CTDE：在训练时，我们知道每个人的动作；我们用它来降低每个评论家的方差。在部署时，每个智能体只看到 `o_i` 并调用 `mu_i(o_i)`。

失败模式：评论家随 N 个智能体增长（输入包括所有动作）。在没有近似的情况下，扩展到约 10 个智能体以上不可行。

### QMIX（2018）——值分解

仅限合作。全局奖励是每个智能体 Q 值的单调函数之和：

```
Q_tot(tau, a) = f(Q_1(tau_1, a_1), ..., Q_n(tau_n, a_n)),   df/dQ_i >= 0
```

单调性保证了 `argmax_a Q_tot` 可以通过每个智能体独立选择 `argmax_{a_i} Q_i` 来计算。这正是你需要的**分散执行属性**。在训练时，混合网络从每个智能体的 Q 值产生 `Q_tot`。

为什么 QMIX 在 SMAC 上获胜：合作型星际争霸微操作具有同质智能体、局部观测、全局奖励——完美契合值分解。

失败模式：单调性约束具有限制性；某些任务的奖励结构不是单调可分解的（一个智能体为团队牺牲）。扩展方法（QTRAN，QPLEX）放宽了这一限制。

### MAPPO（2022）——被忽视的默认选择

多智能体 PPO：带有集中值函数的 PPO。每个智能体有自己的策略；所有智能体共享（或拥有各自的）看到完整状态的值函数。Yu 等人 2022 年在五个基准测试上对 MAPPO 与 MADDPG、QMIX 及其扩展进行了基准测试，发现：

- MAPPO 在粒子世界、SMAC、Google Research Football、Hanabi、MPE 上匹配或击败了 off-policy MARL 方法。
- 需要的超参数调优最少。
- 训练稳定；跨种子可复现。

社区低估了 on-policy MARL，直到这篇论文。在 2026 年，MAPPO 是合作式 MARL 的默认基准；任何新方法都必须超越它。

### 为什么 LLM 智能体工程师应该关心

三个直接用途：

1. **路由器训练。** 一个元智能体选择哪个子智能体处理任务。这是一个具有 N 个分散子智能体和一个集中路由器的 MARL 问题。MAPPO 适用。
2. **角色涌现。** 在生成式智能体模拟中，训练智能体随时间采取互补角色是一个伪装下的 MARL 问题。QMIX 风格的值分解通过构造强制互补性。
3. **多智能体工具使用。** 当智能体共享工具并竞争预算时，通过 CTDE 训练它们会产生可部署的本地策略，这些策略尊重资源约束。

实际警告：在 2026 年，大多数生产级 LLM 智能体系统通过提示来驱动策略，而不是训练策略。当你拥有（a）大量交互数据，（b）清晰的奖励信号，以及（c）愿意投资训练基础设施时，MARL 才发挥作用。

### CTDE 作为超越 RL 的设计模式

即使没有训练，CTDE 也是一个有用的架构模式：

- 在**设计**期间，假设完整的团队可见性。
- 在**运行时**，强制分散执行：每个智能体只看到 `o_i`。

这种模式迫使你将每个智能体的状态保持显式，并提前考虑部分可观测性。许多生产级多智能体系统静默地假设处处共享状态——CTDE 纪律可以防止这种情况。

### 非平稳性问题

当多个智能体同时学习时，每个智能体的环境（包括其他智能体的策略）是非平稳的。经典单智能体 RL 证明失效。本课程中的 MARL 算法都解决了这个问题：

- MADDPG：全局评论家看到所有动作，因此其值估计是平稳的。
- QMIX：值分解将学习转移到最优性定义良好的联合 Q 空间。
- MAPPO：集中值函数抑制了来自其他策略变化的方差。

在 LLM 智能体系统中，非平稳性表现为“我的智能体上个月工作正常，现在上游其他智能体发生了变化，我的智能体行为异常。”使用 CTDE 训练 MARL 是原则性的修复；提示级别的修复更快但持久性较差。

### 本课程不涉及的内容

训练实际网络是阶段 09 的主题。本课程构建了脚本化策略版本，这些版本展示了 CTDE、值分解和集中值模式，而无需梯度更新。目标是在你拿起完整的 MARL 库（PyMARL、MARLlib、RLlib multi-agent）之前，将这些模式内化。

## 构建它

`code/main.py` 实现了三个模式演示，全部在一个小型 2 智能体合作网格世界上运行：

- 环境：2 个智能体在 4x4 网格上，一个奖励颗粒。奖励 = 1（如果任何智能体到达颗粒）；任务结束。
- `IndependentAgents`——每个智能体将其他智能体视为环境。基线。
- `MADDPGStyle`——集中评论家计算联合值；演员策略从中更新。脚本化策略改进。
- `QMIXStyle`——使用单调混合器的值分解。
- `MAPPOStyle`——集中值函数；策略根据共享基线更新。

所有四个都运行相同的回合并报告平均到达目标的步数。CTDE 变体收敛到比独立基线更短的路径。

运行：

```
python3 code/main.py
```

预期输出：独立智能体平均约 6 步；CTDE 变体收敛到约 3.5 步（4x4 网格的最优值为 3）。尽管是脚本化策略，模式差异仍然显现。

## 使用它

`outputs/skill-marl-picker.md` 是一个技能，用于为给定的多智能体任务选择 MARL 算法：合作 vs 竞争，同质 vs 异质，动作空间类型，规模，奖励信号。

## 交付它

生产中的 MARL 很少见。当你确实使用它时：

- **从 MAPPO 开始。** 2022 年的论文将其确立为基线；首先重现它可以节省数周追逐更花哨方法的时间。
- **记录每个智能体的观测和动作流。** 没有每个智能体的痕迹，调试 MARL 是不可能的。
- **将训练代码与执行代码分离。** CTDE 是一种纪律；让执行路径真的只看到 `o_i`。
- **奖励塑造警告。** MARL 对奖励设计极其敏感。塑造中的一个协调错误会导致智能体利用它。运行对抗性测试。
- **对于 LLM 智能体**，首先考虑提示级别的策略。仅当交互数据 + 奖励信号 + 基础设施都具备时，才投资 MARL 训练。

## 练习

1. 运行 `code/main.py`。测量独立智能体与 MAPPO 风格智能体之间到达目标步数的差距。在 6x6 网格上差距是增大还是缩小？
2. 实现一个竞争变体：两个智能体，一个颗粒，只有先到达的获得奖励。哪种模式能干净地处理竞争？历史上是 MADDPG。
3. 阅读 MADDPG（arXiv:1706.02275）第 3 节。用你自己的话以伪代码形式象征性地实现精确的评论家更新规则。
4. 阅读 MAPPO（arXiv:2103.01955）。为什么作者认为集中值 + PPO 在其基准测试中优于 off-policy MARL？列出三个最强的主张。
5. 将 CTDE 作为设计模式应用于一个假设的 LLM 智能体系统（例如，研究智能体 + 摘要生成器 + 编码器）。在设计时可用的联合信息中，哪些在运行时不可用？

## 关键术语

| 术语 | 人们说的 | 实际意思 |
|------|----------|----------|
| MARL | "Multi-Agent RL" | 多智能体强化学习。 |
| CTDE | "集中训练，分散执行" | 用全局信息训练；用本地策略部署。 |
| MADDPG | "多智能体 DDPG" | CTDE，每个评论家看到所有观测 + 动作。 |
| QMIX | "值分解" | 单调混合每个智能体的 Q 值。合作。 |
| MAPPO | "多智能体 PPO" | 带有集中值函数的 PPO。2026 默认基线。 |
| 值分解 | "单个 Q 值的和" | 联合 Q 值表示为每个智能体 Q 值的单调函数。 |
| 非平稳性 | "移动目标" | 每个智能体的环境随其他智能体学习而改变。核心 MARL 问题。 |
| on-policy / off-policy | "从当前/回放中学习" | PPO 是 on-policy（MAPPO）；DDPG 和 Q-learning 是 off-policy。 |
| SMAC | "星际争霸多智能体挑战赛" | 合作微操作基准测试；QMIX 的诞生之地。 |
