# 为何选择Transformer——RNN的问题

> RNN逐个处理词元。Transformer一次性处理所有词元。这一个架构上的赌注改变了2017年后深度学习中所有规模曲线。

**类型：** 学习  
**语言：** Python  
**先决条件：** 第3阶段（深度学习核心），第5阶段·09（序列到序列），第5阶段·10（注意力机制）  
**时间：** ~45分钟

## 问题所在

在2017年之前，地球上每一个最先进的序列模型——语言、翻译、语音——都是循环神经网络。LSTM和GRU在翻译基准测试中称霸了五年，堪比ImageNet的统治力。那是当时人们唯一拥有的工具。

它们有三个致命的弱点。**顺序计算**意味着你无法沿着时间轴进行并行化：词元`t+1`需要词元`t`的隐藏状态。一个1024词元的序列意味着在一个每周期能进行1,000,000次浮点运算的GPU上需要1024个串行步骤。在专为并行设计的硬件上，训练墙钟时间随序列长度线性增长。

**梯度消失**意味着50个词元前的信息已经被压缩通过了50个非线性层。门控循环单元（LSTM、GRU）缓解了这种压榨，但从未消除。长距离依赖——“我去年夏天在去京都的飞机上读的那本书是……”——常常失败。

**固定宽度的隐藏状态**意味着编码器在解码器看到任何东西之前，将整个源序列压缩成一个单一向量。无论源序列是5个词元还是500个，瓶颈形状都是一样的。

2017年的论文《Attention Is All You Need》提出了一个激进的想法：完全放弃循环。让每个位置并行地关注所有其他位置。用一个大的矩阵乘法来训练，而不是1024个顺序步骤。

到2026年，这个结果主导了每一个模态。语言（GPT-5、Claude 4、Llama 4）、视觉（ViT、DINOv2、SAM 3）、音频（Whisper）、生物学（AlphaFold 3）、机器人学（RT-2）。相同的模块，不同的输入。

## 概念

![RNN 顺序计算 vs Transformer 并行注意力](../assets/rnn-vs-transformer.svg)

**循环作为瓶颈。** RNN计算 `h_t = f(h_{t-1}, x_t)`。每一步都依赖于前一步。在 `h_4` 之前你无法计算 `h_5`。在拥有10000多个并行核心的现代GPU上，这在处理长序列时浪费了99%的芯片资源。

**注意力作为广播。** 自注意力同时为每一对 `(i, j)` 计算 `output_i = sum_j(a_ij * v_j)`。整个 N×N 注意力矩阵在一个批处理矩阵乘法中填充。没有步骤依赖于其他步骤。GPU喜欢这样。

**加速不是常数。** 它是 `O(N)` 串行深度与 `O(1)` 串行深度之间的差异。在实践中，在匹配的硬件上，当 N=512 时，Transformer 每个 epoch 的训练速度快 5-10 倍，并且随着序列长度的增加，这个差距会扩大，直到达到注意力的 `O(N²)` 内存墙（后来被Flash Attention修复——参见第12课）。

**Transformer 的代价。** 注意力内存缩放为 `O(N²)`。对于2K上下文，没问题。对于128K上下文，你需要滑动窗口、RoPE外推、Flash Attention分块或线性注意力变体。循环在时间和内存上都是 `O(N)`；Transformer 用时间来换内存，然后通过并行性把时间赢回来。

**归纳偏置的转变。** RNN 假设局部性和近时性。Transformer 不做任何假设——每一对都是注意力的候选者。这就是为什么 Transformer 需要更多数据才能训练好，但一旦拥有足够的数据就能扩展得更好。Chinchilla (2022) 形式化了这一点：给定足够的词元，一个 Transformer 总是能击败同等参数量的 RNN。

## 动手构建

这里没有神经网络——我们用数值模拟核心瓶颈，让你在你的笔记本电脑上感受到差距。

### 第1步：测量串行深度

参见 `code/main.py`。我们构建了两个函数。一个将序列编码为加法链（串行，像RNN）。另一个将其编码为并行规约（广播，像注意力）。相同的数学计算，不同的依赖关系图。

```python
def rnn_style(xs):
    h = 0.0
    for x in xs:
        h = 0.9 * h + x   # can't parallelize: h depends on previous h
    return h

def attention_style(xs):
    return sum(xs) / len(xs)  # every x is independent
```

我们计时这两个函数，序列长度最高达100,000个元素。RNN版本是O(N)的，并且在单个CPU流水线上运行。即使在纯Python中，当长度≥1,000时，注意力风格的规约已经打败了它，因为Python的 `sum()` 是用C实现的，并且每一步迭代没有解释器开销。

### 第2步：计算理论操作次数

两种算法都进行了N次加法。区别在于**依赖深度**：在下一个操作开始之前必须顺序执行多少个操作。RNN深度 = N。注意力深度 = log(N)（使用树规约）或1（使用并行扫描）。决定GPU时间的是深度，而不是操作计数。

### 第3步：长序列上的经验性缩放

我们打印一个时序表，让O(N)的差距可见。在2026年的Mac笔记本上，序列长度小于1,000时快得无法测量。100,000的序列显示出清晰的线性扫描。把这个规模放大到一个16,384词元的Transformer，相当于12层LSTM，你就会明白为什么在2016年训练墙钟时间是一个瓶颈。

## 何时使用

在2026年何时仍然选择RNN：

| 场景 | 选择 |
|-----------|------|
| 流式推理，一次一个词元，恒定内存 | RNN 或状态空间模型（Mamba，RWKV） |
| 非常长的序列（>1M词元），注意力内存爆炸 | 线性注意力，Mamba 2，Hyena |
| 边缘设备，无矩阵乘法加速器 | 深度可分离RNN在FLOPs/瓦特上仍然占优 |
| 其他一切（训练、批处理推理、最多128K上下文） | Transformer |

状态空间模型（SSM）如Mamba本质上是具有结构化参数化的RNN，通过选择性扫描实现两者的最佳效果：`O(N)` 扫描内存，并行训练。它们在更好的长上下文缩放下恢复了Transformer 90%的质量。到2026年，大多数前沿实验室训练混合SSM+Transformer模型（例如Jamba、Samba）——循环没有消亡，它只是一个组件。

## 关键术语

| 术语 | 人们说的 | 实际含义 |
|------|-----------------|-----------------------|
| 循环 | "RNN是顺序的" | 计算中步骤`t`依赖于步骤`t-1`，迫使沿时间轴串行执行。 |
| 串行深度 | "图有多深" | 依赖操作的最长链；即使在无限硬件上也限制了墙钟时间。 |
| 注意力 | "让词元互相看" | 加权和 `sum_j a_ij v_j`，其中 `a_ij` 来自位置i和j之间的相似度分数。 |
| 上下文窗口 | "模型能看到多少" | 注意力层可以作为输入的位置数量；二次内存成本在此缩放。 |
| 归纳偏置 | "架构中内置的假设" | 关于数据外观的先验知识；CNN假设平移不变性，RNN假设近时性。 |
| 状态空间模型 | "背后有代数的RNN" | 通过结构化状态空间矩阵参数化以实现并行训练的循环。 |
| 二次瓶颈 | "为什么上下文这么贵" | 注意力内存 = `O(N²)` 序列长度；Flash Attention隐藏了常数，但没有改变缩放。 |
