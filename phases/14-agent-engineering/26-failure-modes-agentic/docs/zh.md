# 故障模式：智能体为何会崩溃

> MASFT（伯克利，2025）将14种多智能体故障模式归纳为3个类别。微软的分类法记录了现有AI故障在智能体场景中如何被放大。行业实际数据聚焦于五种反复出现的模式：幻觉行为、范围蔓延、级联错误、上下文丢失、工具误用。

**类型：** 学习 + 构建
**语言：** Python (stdlib)
**前置知识：** 第14阶段·05（自我精炼与CRITIC），第14阶段·24（可观测性）
**时间：** 约60分钟

## 学习目标

- 列出MASFT的三种故障类别，以及每个类别中至少四种具体模式。
- 解释为什么智能体故障会放大现有AI故障模式（偏见、幻觉）。
- 描述五种行业反复出现的模式及其缓解措施。
- 实现一个stdlib检测器，为智能体轨迹打上故障模式标签。

## 问题

团队交付的智能体在90%的轨迹上表现正常。剩下的10%故障并非随机噪声——它们属于少量重复出现的类别。一旦你能命名它们，就可以监控并修复它们。

## 概念

### MASFT（伯克利，arXiv:2503.13657）

多智能体系统故障分类法。14种故障模式聚类为3个类别。注释者间的Cohen's Kappa为0.88——这些类别可靠地可区分。

核心主张：故障是多智能体系统中的根本设计缺陷，而非可通过更好的基础模型修复的LLM限制。

### 微软的智能体AI系统故障模式分类法

- 现有的AI故障（偏见、幻觉、数据泄露）在智能体场景中被放大。
- 新的故障源于自主性：大规模意外行为、工具误用、任务偏离。
- 这份白皮书是智能体产品的风险登记册。

### 智能体AI中的故障特征描述（arXiv:2603.06847）

- 故障源于编排、内部状态演化以及环境交互。
- 不仅仅是“糟糕的代码”或“糟糕的模型输出”。

### LLM智能体幻觉综述（arXiv:2509.18970）

两种主要表现形式：

1. **指令遵循偏离**——智能体未遵循系统提示。
2. **长程上下文误用**——智能体忘记或误用来自更早轮次的上下文。

子意图错误：遗漏（缺失步骤）、冗余（重复步骤）、无序（步骤顺序错误）。

### 五种行业反复出现的模式

Arize、Galileo、NimbleBrain在2024-2026年的实际分析共同指向：

1. **幻觉行为。** 智能体调用一个不存在的工具或捏造参数。
2. **范围蔓延。** 智能体将任务扩展到用户的请求之外（创建额外的PR、发送额外邮件）。
3. **级联错误。** 一次错误调用触发下游影响。一个幻影SKU幻觉导致四次API调用——一次多系统事故。
4. **上下文丢失。** 长周期任务忘记早期轮次的约束。
5. **工具误用。** 使用正确的工具但参数错误，或者完全用错工具。

级联错误是最致命的。智能体无法区分“我失败了”和“任务不可能完成”，并且经常在收到400错误时幻觉一个成功消息来闭合循环。

### 缓解措施：每一步设置关卡

在推理链的每一步设置自动化验证关卡，根据环境状态检查事实依据。具体来说：

- 每一步的安全分类器（第21课）。
- 工具调用参数验证（第06课）。
- 将检索到的内容与已知事实交叉核对（第05课，CRITIC）。
- 通过重新探测状态来检测成功幻觉（文件是否真的被创建了？）。

### 故障监控的常见误区

- **仅标记崩溃。** 大多数智能体故障会产生看起来有效的输出。需要内容层面的检查。
- **缺少基线。** 漂移检测需要一个“上次已知良好”的状态；没有它你就无法说“情况正在恶化”。
- **过度告警。** 每个故障都发一次告警。应当聚类并限速。

- 一个覆盖五种模式的合成轨迹数据集。

python3 code/main.py

## 关键术语

| 术语 | 人们常说的 | 实际含义 |
|------|------------|----------|
| MASFT | “多智能体故障分类法” | 伯克利14模式分类 |
| 级联错误 | “连锁故障” | 一个早期错误通过N步传播 |
| 上下文丢失 | “忘记约束” | 长周期轮次丢弃早期轮次的事实 |
| 工具误用 | “错误工具/错误参数” | 有效调用但错误的调用方式 |
| 成功幻觉 | “伪造完成” | 智能体在400错误上声称成功；状态未变 |
| 范围蔓延 | “越界” | 智能体做了超出要求的事 |
| 指令遵循偏离 | “不服从” | 忽略系统提示或用户约束 |
| 子意图错误 | “计划缺陷” | 计划执行中的遗漏、冗余、无序 |
