# 工具接口——为什么代理需要结构化 I/O

> 语言模型生成词元。程序执行动作。这两者之间的鸿沟就是工具接口：一个让模型请求动作、宿主执行动作的契约。每一个 2026 年的技术栈——OpenAI、Anthropic 和 Gemini 上的函数调用；MCP 的 `tools/call`；A2A 的 task parts——都是同一个四步循环的不同编码。本课命名了这个循环，并展示了运行它的最小机制。

**类型：** 学习  
**语言：** Python（标准库，无 LLM）  
**先修知识：** 阶段 11（LLM 补全 API）  
**时间：** ~45 分钟

## 学习目标

- 解释为什么一个只能生成文本的 LLM 本身无法对现实世界采取行动。
- 画出四步工具调用循环（描述→决策→执行→观察），并指出每一步的归属方。
- 将工具描述写为三部分：名称、JSON Schema 输入和确定性执行器函数。
- 区分纯工具和副作用工具，并说明为何这种区分对安全性至关重要。

## 问题所在

LLM 输出下一个词元的概率分布。这就是整个输出表面。如果你问一个聊天模型“班加罗尔现在的天气如何”，它可以写出一句看似合理的句子，但无法真正调用天气 API。这句话可能只是巧合正确，或者已经是三天前的信息。

弥合这一鸿沟正是工具接口的目的。宿主程序——你的代理运行时、Claude Desktop、ChatGPT、Cursor 或自定义脚本——向模型公布一个可调用工具的列表。当模型决定需要某个动作时，它会发出一个结构化的负载，指明工具名称及其参数。宿主解析该负载，真实执行工具，并将结果反馈回来。循环一直持续到模型认为不再需要更多调用为止。

这个契约的第一个版本于 2023 年 6 月作为 OpenAI 的“functions”参数发布。Anthropic 在 Claude 2.1 中紧随其后推出了 `tool_use` 块。几个月后 Gemini 增加了 `functionDeclarations`。现在每个提供商都暴露了相同的形状：输入是一个 JSON Schema 类型化的工具列表，输出是一个 JSON 负载的工具调用。模型上下文协议（2024 年 11 月）将这个契约泛化，使得一个工具注册表可以为所有模型服务。A2A（2026 年 4 月，v1.0）将相同的基本原语用于代理间委托。

四步循环是所有这一切之下不变的核心。阶段 13 中其余一切内容都是在此基础上展开。

## 核心概念

### 第一步：描述

宿主用三个字段声明每个工具。

- **名称：** 一个稳定的、机器可读的标识符。`get_weather`，而不是“天气那个东西”。
- **描述：** 一段自然语言的简短说明。“当用户询问特定城市的当前天气状况时使用。不要用于历史数据。”
- **输入模式：** 一个 JSON Schema 对象（2020-12 草案），描述工具的参数。

模型收到这个列表。现代提供商会使用提供商特定的模板将这些声明序列化到系统提示中，因此作为调用者，你只需处理结构化形式即可。

### 第二步：决策

根据用户的消息和可用工具，模型选择三种行为之一。

1. **直接回答** 文本。无工具调用。
2. **调用一个或多个工具。** 发出结构化的调用对象。在 `parallel_tool_calls: true`（OpenAI 和 Gemini 默认开启，Anthropic 选择开启）下，模型可以在一个回合中发出多个调用。
3. **拒绝：** 严格模式下的结构化输出可以产生一个类型化的 `refusal` 块，而不是调用。

工具调用负载有三个稳定的字段：调用 `id`、工具 `name` 和 JSON `arguments` 对象。id 的存在是为了让宿主能够将后续结果与特定调用关联起来，这在并行调用返回顺序错乱时非常重要。

### 第三步：执行

宿主收到调用，根据声明的模式验证参数，然后运行执行器。无效参数意味着模型幻想了某个字段或使用了错误类型——这在较弱模型上是十分常见的失败模式。生产宿主对无效参数采取三种做法之一：快速失败并将错误返回给模型；使用受限解析器修复 JSON；或者将验证错误包含在提示中重试模型。

执行器本身是普通代码。Python、TypeScript、shell 命令、数据库查询。它产生一个结果，通常是一个字符串，但也可以是任何 JSON 值或结构化内容块（MCP 中的文本、图像或资源引用）。结果必须是可序列化的。

### 第四步：观察

宿主将工具结果追加到对话中（作为带有匹配 `id` 的 `tool` 角色消息），并重新调用模型。模型现在在其上下文中有了工具输出，可以生成最终答案或请求更多调用。一直持续到模型停止发出调用或宿主达到安全迭代次数上限。

### 信任的划分

工具从安全角度分两种类型。

- **纯工具：** 只读、确定性、无副作用。`get_weather`、`search_docs`、`get_current_time`。可以安全地投机性调用。
- **后果性工具：** 改变状态、花费金钱、接触用户数据。`send_email`、`delete_file`、`execute_trade`。必须设置门控。

Meta 2026 年关于代理安全的“两条规则”指出，单个回合最多可以组合以下三种中的两种：不可信输入、敏感数据、后果性动作。工具接口正是你强制执行该规则的地方——通过拒绝调用、要求用户确认或提升作用域。有关完整的安全章节，请参见阶段 13 · 15；有关代理级别的权限策略，请参见阶段 14 · 09。

### 循环存在于何处

| 上下文 | 谁描述 | 谁决策 | 谁执行 |
|---------|--------|--------|--------|
| 单回合函数调用（OpenAI/Anthropic/Gemini） | 应用开发者 | LLM | 应用开发者 |
| MCP | MCP 服务器 | 通过 MCP 客户端的 LLM | MCP 服务器 |
| A2A | Agent Card 发布者 | 调用方代理 | 被调用方代理 |
| Web 浏览器（函数调用代理） | 浏览器扩展 / WebMCP | LLM | 浏览器运行时 |

无论何处，都是相同的四步。列名改变，结构不变。

### 为什么不直接让模型输出 JSON？

“让模型用 JSON 回复”是函数调用之前的模式。在前沿模型上，它大约有 5% 到 15% 的概率会失败，在更小的模型上失败率更高。失败模式包括缺少大括号、尾随逗号、幻象字段以及类型错误。然后你需要 JSON 修复、重试或受限解码器。

原生函数调用更好的原因有三个。首先，提供商端到端地训练模型以符合确切的调用结构，因此在严格模式下有效 JSON 率达到 98% 到 99%。其次，调用负载位于其自己的协议槽中，而不是在自由文本内——因此工具调用永远不会泄漏到用户可见的回复中。第三，提供商使用受限解码（OpenAI 的严格模式、Anthropic 的 `tool_use`、Gemini 的 `responseSchema`）强制模式合规。输出保证验证通过。

### 断路器

当模型停止发出调用或宿主达到最大回合数时，循环终止。生产宿主将其设置为 5 到 20 回合之间。超过这个数，你几乎肯定进入了一个模型无法退出的循环。Claude Code 默认为 20；OpenAI Assistants 为 10；Cursor 的代理模式为 25。

另一种选择——无界循环——每六个月就会出现一次“代理一晚上花费 400 美元 API 调用”的事后分析。没有设置上限就不要发布。

## 使用它

`code/main.py` 在没有 LLM 的情况下运行四步循环。一个假的“决策器”函数通过在用户消息上模式匹配来模拟模型；执行器、模式验证器和观察步骤的脚手架是真实的。运行它可以看到带有可打印中间状态的完整请求/响应协作，然后在后续课程中用任何真实提供商替换假的决策器。

需要注意的地方：

- 工具注册表为每个工具保存三个字段：名称、描述、模式和执行器引用。
- 验证器是一个最小的 JSON Schema 子集（类型、required、enum、min/max），仅用标准库编写。阶段 13 · 04 会提供更完整的版本。
- 循环将迭代次数限制在五次。生产代理需要这种断路器。

## 交付它

本课产出 `outputs/skill-tool-interface-reviewer.md`。给定一个工具定义草稿（名称 + 描述 + 模式 + 执行器大纲），该技能会审计其循环适用性：名称是否机器稳定、描述是否是完整的使用说明、模式是否正确使用了 JSON Schema 2020-12、纯工具与后果性工具的分类是否明确。

## 练习

1. 向 `code/main.py` 添加第四个工具 `get_stock_price(ticker)`。将其描述写为“当用户按股票代码询问当前股票价格时使用。不要用于历史价格或市场摘要。”运行脚手架，确认假决策器将提到股票代码的查询路由到新工具。

2. 破坏模式验证器。传递一个缺少必需字段的 `arguments` 对象的调用，并确认宿主在执行前拒绝它。然后传递一个带有多余未知字段的调用。决定：宿主应该拒绝还是忽略？用安全性论证来证明你的选择。

3. 将脚手架中的每个工具分类为纯工具或后果性工具。向需要它的注册表条目添加 `consequential: true` 标志，并修改循环，使每当选择后果性工具时打印一行“将与用户确认”。这就是每个生产宿主需要的确认门的形态。

4. 在白纸上画出四步循环，并填入上面与提供商列对应的表格，内容为你最喜欢的客户端（Claude Desktop、Cursor、ChatGPT 或自定义堆栈）。与阶段 13 · 06 中的 MCP 特定变体进行交叉参考。

5. 从头到尾阅读 OpenAI 的函数调用指南。找出位于请求中但未出现在这里展示的四步循环中的那个字段。解释它添加了什么，以及为什么它是便捷的而非必需的。

## 关键术语

| 术语 | 人们常说的 | 实际含义 |
|------|-----------|---------|
| Tool | “模型可以调用的东西” | 名称 + JSON Schema 类型化输入 + 执行器函数的三元组 |
| Function calling | “原生工具使用” | 提供商级别的 API 支持，用于发出结构化工具调用而非散文 |
| Tool call | “模型请求动作” | 由模型发出的包含 `id`、`name`、`arguments` 的 JSON 负载 |
| Tool result | “工具返回的结果” | 执行器的输出，包装在带有匹配 id 的 `tool` 角色消息中 |
| Parallel tool calls | “一次多个调用” | 一个模型回合中的多个调用对象，独立且可按 id 排序 |
| Strict mode | “保证 JSON” | 受限解码，强制模型输出符合声明的模式 |
| Pure tool | “只读工具” | 无副作用；可安全重复运行 |
| Consequential tool | “动作工具” | 改变外部状态；需要门控、审计或用户确认 |
| Four-step loop | “工具调用循环” | 描述 → 决策 → 执行 → 观察 |
| Host | “代理运行时” | 持有工具注册表、调用模型并运行执行器的程序 |
