# 谈判与讨价还价

> 智能体就资源、价格、任务分配和条款进行谈判。2026年的基准测试集非常明确：NegotiationArena（arXiv:2402.05863）表明，LLM 通过角色操纵（“绝望”）可以将收益提高约 20%；“Measuring Bargaining Abilities”（arXiv:2402.05813）表明，买方比卖方更难，且规模扩大并无帮助——他们的 **OG-Narrator**（确定性出价生成器 + LLM 叙述器）将成交率从 26.67% 提升至 88.88%；大规模自主谈判竞赛（arXiv:2503.06416）进行了约 18 万次谈判，发现 **chain-of-thought-concealing** 智能体通过向对手隐藏推理过程而获胜；Bhattacharya 等人 2025 年关于哈佛谈判项目指标的研究将 Llama-3 评为最有效，Claude-3 最具攻击性，GPT-4 最公平。本课程实现了 Contract Net 协议（FIPA 的前身，第 02 课），搭建了一个 LLM 风格的买方/卖方，运行了一个 OG-Narrator 风格的分解，并衡量成交率如何随每种结构选择而变化。

**类型：** 学习 + 构建
**语言：** Python（标准库）
**前置知识：** 阶段 16 · 02（FIPA-ACL 遗产），阶段 16 · 09（并行群体网络）
**时间：** 约 75 分钟

## 问题

两个智能体需要就价格达成一致。如果仅凭纯语言提示，2024-2026 年的 LLM 以出人意料低的比率成交（在 arXiv:2402.15813 的严格参数化讨价还价中约 27%）。规模扩大并不能解决这个问题：GPT-4 在讨价还价方面并不比 GPT-3.5 有结构性优势；它只是在讨价还价的*语言*方面更出色。

根本原因在于 LLM 将两项工作混为一谈——决定出价和叙述出价。OG-Narrator 将这两者分离开来：一个确定性的出价生成器计算数字移动；LLM 仅负责叙述。成交率跃升至约 89%。

这反映了经典的多智能体发现：将机制与通信层分离是获胜之道。Contract Net 协议（FIPA，1996；Smith，1980）是参考的任务市场机制。将 LLM 插入叙述槽位，你就得到了一个现代 LLM 驱动的任务市场。

## 概念

### Contract Net，一句话概括

Smith 1980 年的 Contract Net 协议：一个**管理者**广播**征求建议书 (cfp)**；**投标者**以包含其出价的**提议**消息回应；管理者选出获胜者，向获胜者发送**接受提议**，向失败者发送**拒绝提议**。获胜者执行工作。可选消息：**拒绝**（投标者拒绝提议）。FIPA 将其规定为 `fipa-contract-net` 交互协议。

### 为什么 OG-Narrator 获胜

“Measuring Bargaining Abilities of Language Models”（arXiv:2402.15813）观察到：

- LLM 经常违反谈判规则（以无意义的价格出价，忽略对方的 ZOPA）。
- 它们锚定不佳（接受糟糕的首次出价；以象征性而非战略性的金额还价）。
- 仅靠规模扩大无法解决这些问题。更大的模型生成更合理的语言，但具有类似的战略错误。

OG-Narrator 分解：

```
           ┌──────────────────┐        ┌──────────────────┐
  state  → │ offer generator  │ price → │  LLM narrator    │ → message
           │  (deterministic) │        │  (writes the     │
           │                  │        │   human-style    │
           └──────────────────┘        │   accompaniment) │
                                       └──────────────────┘
```

出价生成器是一种经典的谈判策略：Rubinstein 讨价还价模型、Zeuthen 策略，或简单的以牙还牙式价格调整。LLM 负责叙述。消息中包含确定性的价格和自然语言框架。

成交率跃升的原因：
- 价格保持在谈判区域内。
- 锚定是战略性的，而非情绪化的。
- LLM 做它擅长的事情：写作。

### NegotiationArena 的发现

arXiv:2402.05863 提供了权威的基准测试。主要发现：

- LLM 可以通过采用角色（“我迫切希望在周五之前卖掉这个”）将收益提高约 20%——角色操纵是一种真实的战术。
- 公平/合作的智能体会被对抗性智能体利用；防御需要明确的对抗姿态。
- 对称配对在大约 40% 的基准场景中收敛到不公平的结果。

这并不是说“LLM 是糟糕的谈判者。”而是“LLM 的谈判方式太像人类了，包括那些可被利用的部分。”

### 思维链隐藏

大规模自主谈判竞赛（arXiv:2503.06416）在众多 LLM 策略中进行了约 18 万次谈判。获胜者向对手隐藏了他们的推理：

- 如果一个智能体将“我只出到 75 美元；我的保留价是 70 美元”打印到公开可见的草稿板上，对手就能读到。
- 获胜者私下计算策略；输出通道仅包含出价和最少的必要叙述。

这是 2026 年对经典博弈论（Aumann 1976 关于理性与信息）的呼应：泄露你的私人估值会损害收益。LLM 无法直觉地理解这一点，并且会在推理痕迹中愉快地输入他们的保留价，而这些痕迹对对手是可见的。

工程上的启示：将私人草稿板上下文与公共消息上下文分开。这不是可选项。

### Bhattacharya 等人 2025 年——模型排名

根据哈佛谈判项目指标（原则性谈判、BATNA 尊重、利益互惠）：

- **Llama-3** 在达成交易方面最有效（成交率 + 收益）。
- **Claude-3** 是最具攻击性的谈判者（高锚点、让步迟缓）。
- **GPT-4** 是最公平的（各配对之间的收益方差最小）。

这是 2025 年的快照。重点不在于 2026 年 4 月哪个模型胜出——而在于不同的基础模型具有持久的谈判风格。异质集成（第 15 课）将其作为多样性来源。

### 通过 Contract Net + LLM 进行任务分配

Contract Net 在 LLM 多智能体中的现代重用：

1. 管理者智能体将任务分解为单元。
2. 向工作智能体广播带有任务描述的 `cfp`。
3. 每个工作智能体返回一个报价：`(price, eta, confidence)`，其中价格可以是代币、计算单元或美元。
4. 管理者选择获胜者（单个或多个，取决于任务）并授予。
5. 被拒绝的工作智能体可以自由竞标其他任务。

这种方法可以很好地扩展到 100 个以上的工作智能体，因为协调是广播和响应，而不是同步聊天。在生产中使用：微软智能体框架的编排模式，一些 LangGraph 实现。

### LLM-利益相关者交互式谈判

NeurIPS 2024（https://proceedings.neurips.cc/paper_files/paper/2024/file/984dd3db213db2d1454a163b65b84d08-Paper-Datasets_and_Benchmarks_Track.pdf）介绍了多方可评分游戏，其中包含**秘密分数**和**最低接受阈值**。每个利益相关者都有私人效用；LLM 必须从消息中推断出它们。这是双方谈判到 N 方联盟形成的泛化。与具有异构工作能力的生产任务市场相关。

### 叙述 vs 机制规则

在 2024-2026 年的所有谈判基准测试中，一致的工程规则是：

> 让 LLM 叙述。不要让 LLM 计算出价。

如果出价需要是一个数字（价格、ETA、数量），则根据谈判状态确定性地生成它，并让 LLM 生成框架。如果出价需要是一个提案结构（任务分解、角色分配），让 LLM 起草，但在发送之前根据模式和约束检查进行验证。

## 构建它

`code/main.py` 实现了：

- `ContractNetManager`, `ContractNetTask`, `Bid` — 管理者 + 投标者，广播 cfp，收集提议，授予。
- `og_narrator_bargain(state, rng)` — OG-Narrator 买方：确定性的 Zeuthen 风格让步，向中点靠拢。
- `seller_response(state, rng)` — 确定性的卖方还价策略（两种风格的结构性事实基础）。
- `naive_llm_bargain(state, rng)` — 模拟一个纯 LLM 谈判者：以高方差选择价格，通常超出 ZOPA。
- 测量：在 1000 次试验中的成交率，每次试验重新采样保留价。

运行：

```
python3 code/main.py
```

预期输出：纯 LLM 成交率约 65-75%；OG-Narrator 成交率约 85-95%；15-25 个百分点的差距是将出价生成与叙述分离所带来的结构优势。此外还有一个包含三个投标者和一个任务的 Contract Net 任务市场分配示例。

## 使用它

`outputs/skill-bargainer-designer.md` 设计了一个谈判协议：谁生成出价（确定性或 LLM），谁叙述，私人草稿板如何与公共消息分开，以及如何监控成交率。

## 交付它

生产级谈判检查清单：

- **分离草稿板。** 私人状态绝不进入对手的上下文。这是不容商量的。
- **确定性出价生成。** 价格、数量、ETA：计算，不要提示。
- **根据模式验证所有传入出价。** 在协议边界拒绝超出 ZOPA 的出价。
- **限制轮数。** 最多 3-5 轮；僵局时升级到调解人。
- **持续测量成交率和收益方差。** 成交率下降是一个症状——通常是提示漂移或对手方攻击。
- **记录所有被拒绝的提议及确定性理由。** 对于 Contract Net 管理者，失败的投标者需要理解原因。

## 练习

1. 运行 `code/main.py`。确认 OG-Narrator 在成交率上优于纯 LLM。高出多少？
2. 实现**基于角色的收益提升**（arXiv:2402.05863）——买方仅在叙述中采用“迫切希望本周购买”的角色，出价生成器不变。成交率或收益会改变吗？
3. 实现思维链**隐藏**：维护一个私有草稿板字符串，不传递给对手。如果不小心泄露了它（通过交换通道模拟），会发生什么？
4. 将 Contract Net 扩展为带有保留价的 N 投标者拍卖。当所有出价都超过保留价时，管理者如何在最低价格和最高质量之间做出决定？你选择哪个授予规则，为什么？
5. 阅读 Bhattacharya 等人 2025 年关于哈佛谈判项目指标的论文。实现两个具有不同风格（攻击性与公平）的谈判者。在对称和非对称配对下测量收益方差。

## 关键术语

| 术语 | 人们说的话 | 实际含义 |
|------|------------|----------|
| Contract Net | “任务市场” | Smith 1980, FIPA 1996。cfp + 提议 + 接受/拒绝。经典的任务市场。 |
| ZOPA | “可能达成协议的区域” | 买方最高价与卖方最低价之间的重叠区域。超出此区域的出价无法成交。 |
| BATNA | “达成协议的最佳替代方案” | 如果这笔交易失败，你的备选方案。决定了你的保留价。 |
| OG-Narrator | “出价生成器 + 叙述器” | 分解：确定性出价，LLM 叙述。 |
| Zeuthen 策略 | “风险最小化让步” | 经典的出价生成器，基于风险限制让步。 |
| Rubinstein 讨价还价 | “交替出价均衡” | 用于无限视野讨价还价并考虑折现的博弈论模型。 |
| 思维链隐藏 | “隐藏你的推理” | arXiv:2503.06416 中的获胜者保持私人草稿板；公共通道仅显示出价。 |
| 角色操纵 | “情绪姿态” | arXiv:2402.05863：通过绝望/紧迫感角色获得约 20% 的收益提升。 |
