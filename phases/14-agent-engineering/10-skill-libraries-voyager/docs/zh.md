# 技能库与终身学习 (Voyager)

> Voyager（Wang et al., TMLR 2024）将可执行代码视为技能。技能是有名称、可检索、可组合，并能通过环境反馈进行精炼的。这是 Claude Agent SDK 技能、skillkit 以及 2026 年技能库模式的参考架构。

**类型:** 构建  
**语言:** Python (stdlib)  
**前置条件:** 阶段 14 · 07 (MemGPT)，阶段 14 · 08 (Letta Blocks)  
**时间:** ~75 分钟

## 学习目标

- 说出 Voyager 的三个组件——自动课程、技能库、迭代提示——以及每个组件的作用。
- 解释为什么 Voyager 将动作空间设为代码，而非原始命令。
- 实现一个 stdlib 技能库，包含注册、检索、组合和基于失败的精炼。
- 将 Voyager 模式映射到 2026 年 Claude Agent SDK 技能和 skillkit 生态系统。

## 问题所在

那些每次会话都从零重建所有能力的智能体做错了三件事：

1.  **浪费令牌。** 每个任务都重新引出相同的推理过程。
2.  **丢失进展。** 在会话 A 中学到的修正不会迁移到会话 B。
3.  **在长视野组合上失败。** 复杂任务需要能力层次结构；一次性提示无法表达它们。

Voyager 的答案：将每个可复用能力视为存储在库中的命名代码块，可通过相似性检索，可与其他技能组合，并通过执行反馈进行精炼。

## 概念

### 三个组件

Voyager（arXiv:2305.16291）围绕这三个部分构建智能体：

1.  **自动课程。** 一个好奇心驱动的提议者根据智能体当前的技能集和环境状态选择下一个任务。探索是自底向上的。
2.  **技能库。** 每个技能都是可执行的代码。当任务成功时添加新技能。通过查询描述与技能的相似性进行检索。
3.  **迭代提示机制。** 失败时，智能体会收到执行错误、环境反馈和自我验证输出，然后精炼该技能。

Minecraft 评估（Wang et al., 2024）：独特物品数量是基线的 3.3 倍，石制工具速度快 8.5 倍，铁制工具速度快 6.4 倍，地图遍历距离是基线的 2.3 倍。这些数字是 Minecraft 特有的，但模式具有通用性。

### 动作空间 = 代码

大多数智能体发出原始命令。Voyager 发出 JavaScript 函数。一个技能是：

```
async function craftIronPickaxe(bot) {
  await mineIron(bot, 3);
  await mineStick(bot, 2);
  await placeCraftingTable(bot);
  await craft(bot, 'iron_pickaxe');
}
```

由子技能组合而成。以描述和嵌入为键进行存储。作为程序检索，而不是提示。

这就是 2026 年 Claude Agent SDK 的技能：一个命名、可检索的代码块加上智能体按需加载的指令。

### 技能检索

新任务“制作一把钻石镐”。智能体：

1.  嵌入任务描述。
2.  查询技能库获取 top-k 相似技能。
3.  检索 `craftIronPickaxe`、`mineDiamond`、`placeCraftingTable` 等。
4.  从检索到的原语 + 新逻辑组合出新的技能。

这就是 MCP 资源（阶段 13）和 Agent SDK 技能实现的模式：在知识/代码表面上进行检索，范围限定在当前任务。

### 迭代精炼

Voyager 的反馈循环：

1.  智能体编写一个技能。
2.  技能在环境中运行。
3.  返回三种信号之一：`success`、`error`（附带堆栈跟踪）、`self-verification failure`。
4.  智能体使用该信号作为上下文重写技能。
5.  循环直到成功或达到最大轮数。

这是 Self-Refine（第 05 课）应用于代码生成，并带有环境为基础的验证。CRITIC（第 05 课）是相同的模式，只是使用外部工具作为验证器。

### 课程与探索

Voyager 的课程模块根据智能体拥有什么以及尚未做什么来提议诸如“在湖边建一个避难所”之类的任务。提议者利用环境状态 + 技能清单选择一个刚好高于当前能力的任务——即探索的最佳点。

对于生产环境中的智能体，这转化为一个“缺少什么”的操作：给定当前的技能库和一个领域，我们还有哪些技能没有覆盖？团队通常通过课程评审手动实现这一点。

### 这个模式在什么地方会出错

-   **技能库腐化。** 同一个技能因描述略有不同被添加了 10 次。在写入时添加去重；检索只返回一个。
-   **组合技能漂移。** 父技能依赖一个已被精炼的子技能。对技能进行版本管理；固定到 v1 的父技能不会神奇地拾取 v3。
-   **检索质量。** 当技能库增长到几百个以上时，基于技能描述的向量检索质量会下降。用标签过滤器和硬约束（“仅 `category=tooling` 的技能”）进行补充。

## 构建它

`code/main.py` 实现了一个 stdlib 技能库：

-   `Skill` —— 名称、描述、代码（字符串形式）、版本、标签、依赖项。
-   `SkillLibrary` —— 注册、搜索（令牌重叠）、组合（依赖项拓扑排序）和精炼（更新时版本号递增）。
-   一个脚本化的智能体，注册三个原语技能，组合出第四个，遇到失败，然后精炼。

运行它：

```
python3 code/main.py
```

追踪输出显示了库写入、检索、组合、一次失败的执行以及一个 v2 精炼——从端到端走通了 Voyager 的循环。

## 使用它

-   **Claude Agent SDK 技能**（Anthropic）——2026 年参考：每个技能都有描述、代码和指令；在智能体会话期间按需加载。
-   **skillkit**（npm: skillkit）——面向 32 个以上 AI 编码智能体的跨智能体技能管理。
-   **自定义技能库**——领域特定（面向数据智能体的 SQL 技能，面向基础设施智能体的 Terraform 技能）。Voyager 模式可以向下缩放。
-   **OpenAI Agents SDK `tools`**——在低端；每个工具是一个轻量级技能。

## 交付它

`outputs/skill-skill-library.md` 生成一个 Voyager 风格的技能库，其中嵌入了注册、检索、版本管理和精炼，适用于任何目标运行时。

## 练习

1.  为 `compose()` 添加一个依赖循环检测器。当技能 A 依赖于技能 B，而技能 B 又依赖于技能 A 时会发生什么？报错 vs 警告？
2.  实现每个技能版本的固定。当父技能组合了子技能 `crafting@1` 时，对 `crafting@2` 的精炼不得静默升级父技能。
3.  将令牌重叠检索替换为 sentence-transformers 嵌入（或 BM25 stdlib 实现）。在一个 50 个技能的玩具库上测量 retrieval@5。
4.  添加一个“课程”智能体：给定当前库和一个领域描述，提议 5 个缺失的技能。每周调用一次。
5.  阅读 Anthropic 的 Claude Agent SDK 技能文档。将玩具库移植到 SDK 的技能模式。关于可发现性发生了什么变化？

## 关键术语

| 术语 | 人们所说的含义 | 实际含义 |
|------|----------------|----------|
| 技能 | “可复用能力” | 命名的代码块 + 描述，可通过相似性检索 |
| 技能库 | “智能体的知识回忆库” | 技能的持久化存储，可搜索和组合 |
| 课程 | “任务提议者” | 自底向上的目标生成器，由当前能力差距驱动 |
| 组合 | “技能 DAG” | 技能调用技能；执行时按拓扑排序 |
| 迭代精炼 | “自我修正循环” | 环境反馈 + 错误 + 自我验证折回到下一个版本 |
| 动作空间即代码 | “程序化动作” | 发出函数而非原始命令，以获得时间扩展的行为 |
| 写入时去重 | “技能折叠” | 近乎重复的描述折叠为一个规范技能 |
