# LLM 功能的 A/B 测试 —— GrowthBook、Statsig 与“感觉”问题

> 传统的 A/B 测试并非为非确定性的 LLM 而设计。关键区别在于：评估回答的是“模型能完成任务吗？”而 A/B 测试回答的是“用户在乎吗？”两者都是必需的；仅凭感觉就发布已经过时。2026 年需要测试的内容：提示工程（措辞）、模型选择（GPT-4 vs GPT-3.5 vs 开源模型；准确率 vs 成本 vs 延迟）、生成参数（temperature、top-p）。实际案例：某聊天机器人的奖励模型变体使对话长度增加 70%，留存率提升 30%；Nextdoor 的 AI 主题行实验在优化奖励函数后使点击率提升 1%；可汗学院 Khanmigo 在延迟与数学准确率之间迭代取舍。平台对比：**Statsig**（2025 年 9 月被 OpenAI 以 11 亿美元收购）—— 支持序贯测试、CUPED、一体化方案。**GrowthBook** —— 开源、基于数据仓库、支持贝叶斯+频率派+序贯引擎、CUPED、SRM 检查、Benjamini-Hochberg 校正和 Bonferroni 校正。根据您对数据仓库 SQL 的偏好以及“被 OpenAI 收购”是否对您的组织重要来选择。

**前置知识：** 阶段 17·13（可观测性），阶段 17·20（渐进式部署）

## 学习目标

- 区分评估（“模型能完成任务吗”）与 A/B 测试（“用户在乎吗”）。
- 列举三个可测试的维度（提示、模型、参数），并为每个维度选择指标。
- 解释 CUPED、序贯测试以及 Benjamini-Hochberg 多重比较校正。
- 根据数据仓库 SQL 策略和公司对收购的态度选择 Statsig 或 GrowthBook。

## 问题所在

你手动调整了一条系统提示。感觉更好了。你发布上线。转化率的变化只是噪声。你责怪指标。或者你上线了一个新模型，转化率没有变化——是模型退化还是变化太小无法检测？你不知道，因为你没有做 A/B 测试就发布了。

评估回答的是模型能否在标注集上完成任务。它们不能回答用户是否更喜欢输出。只有受控的在线实验才能回答这个问题，而且前提是实验要有足够的统计功效、控制非确定性，并校正多重比较。

## 概念

### 评估 vs A/B 测试

**评估** —— 离线，标注集，判断者（评分准则或 LLM 作为判断者或人工）。回答：“在这个固定分布上，输出是否正确/有用/安全？”

**A/B 测试** —— 在线，真实用户，随机分配。回答：“新变体是否改变了用户层面的关键指标？”

两者都需要。评估在暴露前捕获回归；A/B 在暴露后确认产品影响。

### 测试什么

1. **提示工程** —— 措辞、系统提示结构、示例。指标：任务成功率、用户留存、每次请求成本。
2. **模型选择** —— GPT-4 vs GPT-3.5-Turbo vs Llama 开源模型。指标：准确率（任务）+ 每次请求成本 + P99 延迟。多目标。
3. **生成参数** —— temperature、top-p、max_tokens。指标：任务特定（输出多样性 vs 确定性）。

### CUPED —— 方差缩减

利用实验前数据控制实验。通过回归剔除实验前阶段的方差，再比较实验后阶段。典型的方差缩减：30-70%。有效样本量无需额外成本即可增加。

实现：Statsig 和 GrowthBook 都实现了。

### 序贯测试

经典 A/B 测试假设固定样本量。序贯测试（“边看边决定”）在多次查看下控制假阳性率。始终有效的序贯方法（mSPRT、Howard 置信序列）允许在结果明确时提前停止。

### 多重比较校正

同时运行 20 个 A/B 测试，在 95% 置信水平下会偶然产生一个假阳性。Bonferroni 校正收紧每个测试的 α；Benjamini-Hochberg 控制错误发现率。GrowthBook 两者都实现。

### SRM —— 样本比例不匹配

分配哈希将用户随机分配到变体。如果 50/50 的分流变成了 47/53，说明有问题——SRM 检查会标记出来。两个平台都实现。

### Statsig vs GrowthBook

**Statsig**：
- 2025 年 9 月被 OpenAI 以 11 亿美元收购。托管型 SaaS。
- 支持序贯测试、CUPED、保留人群。
- 一体化：功能开关 + 实验 + 可观测性。
- 最适合：团队已经想要一体化产品，且不在意 OpenAI 所有权。

**GrowthBook**：
- 开源（MIT 许可）；基于数据仓库（直接从 Snowflake/BigQuery/Redshift 读取）。
- 多种引擎：贝叶斯、频率派、序贯。
- CUPED、SRM、Bonferroni、BH 校正。
- 可自托管或托管云。
- 最适合：数据仓库优先的团队，数据团队控制指标层，需要开源。

### 非确定性使统计功效复杂化

相同的提示会产生不同的输出。传统的功效计算假设观测独立同分布。由于 LLM 的非确定性，有效样本量低于名义值。建议将所需样本量乘以约 1.3-1.5 倍作为安全裕度。

### 实际案例结果

- 聊天机器人奖励模型变体：对话长度 +70%，留存 +30%。
- Nextdoor 主题行：优化奖励函数后点击率 +1%。
- 可汗学院 Khanmigo：在延迟与数学准确率之间迭代权衡。

### 反模式：凭感觉发布

每个资深工程师都能举出一个功能发布时“感觉更好”但未经 A/B 测试的例子。大多数这类功能在数月内都未被团队察觉地损害了产品指标。A/B 测试是强制约束机制。

### 你应该记住的数字

- Statsig 被 OpenAI 收购：11 亿美元，2025 年 9 月。
- GrowthBook：开源 MIT 许可；贝叶斯 + 频率派 + 序贯。
- CUPED 方差缩减：30-70%。
- LLM 非确定性 → 样本量缓冲 +30-50%。

## 关键术语

| 术语 | 人们常说的 | 实际含义 |
|------|-----------|----------|
| 评估 | “离线测试” | 对模型能力在标注集上的评估 |
| A/B 测试 | “实验” | 对真实用户进行受控的随机对比 |
| CUPED | “方差缩减” | 利用实验前数据进行回归以降低方差 |
| 序贯测试 | “可边看边停的测试” | 允许提前停止的始终有效方法 |
| 多重比较 | “族系错误” | 同时运行多个测试会膨胀假阳性率 |
| Bonferroni | “严格校正” | 将 α 除以测试数量 |
| Benjamini-Hochberg | “BH FDR” | 错误发现率控制，相对不保守 |
| SRM | “比例失衡” | 样本比例不匹配；分配错误 |
| Statsig | “OpenAI 旗下” | 商业一体化平台，2025 年被收购 |
| GrowthBook | “开源那个” | MIT 许可的基于数据仓库的平台 |
| mSPRT | “序贯概率比检验” | 经典的序贯方法 |
