# 审核系统 —— OpenAI、Perspective、Llama Guard

> 生产环境审核系统将第12-16课所定义的安全策略付诸实施。OpenAI 审核 API：`omni-moderation-latest`（2024年）基于 GPT-4o 构建，一次调用即可对文本+图像进行分类；在多语言测试集上比之前版本提升了42%；响应模式返回13个类别布尔值——骚扰、骚扰/威胁、仇恨、仇恨/威胁、非法、非法/暴力、自残、自残/意图、自残/指令、色情、色情/未成年、暴力、暴力/血腥；对大多数开发者免费。分层模式：输入审核（生成前）、输出审核（生成后）、自定义审核（领域规则）。异步并行调用隐藏延迟；触发时返回占位响应。Llama Guard 3/4（第16课）：14个 MLCommons 危害类别、代码解释器滥用、8种语言（v3）、多图像（v4）。Perspective API（Google Jigsaw）：毒性评分，早于 LLM 即审核器的浪潮；主要为单维度毒性，带有严重毒性/侮辱/粗俗变体；是内容审核研究的基线。弃用：Azure 内容审查器已于2024年2月弃用，2027年2月停用，由 Azure AI 内容安全替代。

## 概念

### OpenAI 审核 API

`omni-moderation-latest`（2024年）。基于 GPT-4o 构建。一次调用即可对文本+图像进行分类。对大多数开发者免费。

类别（响应模式中的13个布尔值）：
- 骚扰、骚扰/威胁
- 仇恨、仇恨/威胁
- 自残、自残/意图、自残/指令
- 色情、色情/未成年
- 暴力、暴力/血腥
- 非法、非法/暴力

多模态支持适用于 `暴力`、`自残` 和 `色情`，但不适用于 `色情/未成年`；其余类别仅限文本。

在 `code/main.py` 的代码框架中，为了教学简洁性，我们将 `/威胁`、`/意图`、`/指令` 和 `/血腥` 子类别折叠到它们各自的顶层父类别中。生产代码应使用完整的13类别模式。

在多语言测试集上比上一代审核端点提升了42%。每个类别都有分数；应用程序可自行设置阈值。

### Llama Guard 3/4

第16课已涵盖。14个 MLCommons 危害类别（组织方式与 OpenAI 的13个响应模式布尔值不同）。支持8种语言（v3）。Llama Guard 4（2025年4月）原生多模态，12B。

OpenAI 和 Llama Guard 的分类体系有重叠但也有分歧。OpenAI 将“非法”作为一个宽泛类别；Llama Guard 则分别列出了“暴力犯罪”和“非暴力犯罪”。部署时根据其策略与分类体系的契合度进行选择。

### Perspective API（Google Jigsaw）

毒性评分系统，早于 LLM 即审核器的浪潮（2020年之前）。类别：毒性、严重毒性、侮辱、粗俗、威胁、身份攻击。单一维度主要分数（毒性）带有子维度变体。

作为内容审核研究的基线被广泛使用，因为该 API 稳定、有文档记录，并且拥有多年的校准数据。对于现代与 LLM 相关的用例，Llama Guard 或 OpenAI 审核通常更合适。

### 三层模式

1. **输入审核。** 在生成之前对用户的提示进行分类。若被标记则拒绝。延迟：一次分类器调用。
2. **输出审核。** 在交付之前对模型的输出进行分类。若被标记则替换为拒绝。延迟：生成后一次分类器调用。
3. **自定义审核。** 领域特定规则（正则表达式、白名单、业务策略）。在输入或输出阶段运行。

三层按顺序设计：输入审核必须在生成之前完成，输出审核在生成之后运行。并行性应用于层内——对同一文本同时运行多个分类器（例如 OpenAI 审核 + Llama Guard + Perspective）可隐藏每个分类器的延迟。作为一种可选优化，可以在输入审核完成时显示占位响应（“请稍候，正在检查……”）并延迟令牌1的流式传输。触发行为是可配置的：拒绝、净化、升级到人工审核。

### 失败模式

- **仅输入。** 无法捕获输出幻觉（第12-14课的编码攻击可绕过输入分类器）。
- **仅输出。** 允许任何输入到达模型；增加成本；向攻击者暴露内部推理。
- **仅自定义。** 跨类别不稳健；正则表达式脆弱。

分层是默认方式。双重保险。

### Azure 弃用

Azure 内容审查器：已于2024年2月弃用，2027年2月停用。由 Azure AI 内容安全替代，后者基于 LLM 并与 Azure OpenAI 集成。对于 Azure 部署，迁移是2024-2027年的现场级项目。

## 使用它

`code/main.py` 构建了一个三层审核框架：输入审核器（关键词 + 类别分数）、输出审核器（对输出使用相同分类器）、自定义审核器（领域规则）。你可以运行输入，观察哪一层捕获了什么。

## 交付它

本课产出 `outputs/skill-moderation-stack.md`。针对给定的部署，它会推荐一个审核栈配置：输入端使用哪个分类器，输出端使用哪个，哪些自定义规则，以及边缘情况下使用哪个判断器。

## 练习

1. 运行 `code/main.py`。将一个良性、边界性和有害的输入分别通过所有三层。报告每一层对每个输入的触发情况。

2. 使用 Perspective API 风格的毒性评分扩展框架，针对特定类别。比较其阈值行为与类别分数。

3. 阅读 OpenAI 审核 API 文档和 Llama Guard 3 类别列表。将每个 OpenAI 类别映射到最接近的 Llama Guard 类别。找出三个无法清晰映射的类别。

4. 为代码助手部署（例如 GitHub Copilot）设计一个审核栈。确定最相关和最不相关的类别，并提出自定义规则。

5. Azure 内容审查器将于2027年2月停用。规划迁移到 Azure AI 内容安全。确定迁移中风险最高的元素。
