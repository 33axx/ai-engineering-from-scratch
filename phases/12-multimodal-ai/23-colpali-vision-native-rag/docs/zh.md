# ColPali 与视觉原生文档 RAG

> 传统 RAG 将 PDF 解析为文本，拆分成块，嵌入块，存储向量。每一步都会丢失信息：OCR 丢掉了图表数据，分块破坏了表格行，文本嵌入忽略了图形。ColPali（Faysse 等人，2024 年 7 月）提出了一个更简单的问题：为什么要提取文本？直接通过 PaliGemma 嵌入页面图像，使用 ColBERT 风格的后期交互进行检索，并保留文档携带的所有布局、图形、字体和格式信息。已发表的基准测试：在视觉丰富的文档上，端到端准确率比文本 RAG 高出 20-40%。ColQwen2、ColSmol 和 VisRAG 扩展了这一模式。本课将解读视觉原生 RAG 论文并构建一个类似 ColPali 的微型索引器。

**类型：** 构建
**语言：** Python（标准库，多向量索引器 + MaxSim 评分器）
**前置知识：** 阶段 11（LLM 工程 — RAG 基础），阶段 12 · 05（LLaVA）
**时间：** ~180 分钟

## 学习目标

- 解释双编码器检索（每文档一个向量）与后期交互检索（每文档多个向量）之间的区别。
- 描述 ColBERT 的 MaxSim 运算以及 ColPali 如何将其从文本令牌推广到图像补丁。
- 构建一个类似 ColPali 的微型索引器：页面 → 补丁嵌入 → 对查询令牌嵌入的 MaxSim → top-k 页面。
- 在发票/财务报告用例上比较 ColPali + Qwen2.5-VL 生成器与文本 RAG + GPT-4。

## 问题

PDF 上的文本 RAG 丢弃了文档的大部分内容。财务报告中的 Q3 收入增长通常是一个图表；医疗报告中的发现是在带注释的图像中；法律合同中的签名块是一个布局事实，而不是文本事实。

文本 RAG 流程：

1. PDF → 通过 OCR / pdftotext 转为文本。
2. 文本 → 300-500 令牌的块。
3. 块 → 双编码器嵌入（一个向量）。
4. 用户查询 → 嵌入 → 余弦相似度 → top-k 块。
5. 块 + 查询 → LLM。

五个有损步骤。图表未被捕获。表格跨块断开。多列布局被展平。图形注释消失。

ColPali 的修复：跳过 OCR，直接嵌入页面图像。使用 ColBERT 风格的后期交互进行检索，以便模型在查询时可以关注细粒度的补丁。

## 概念

### ColBERT（2020）

ColBERT（Khattab & Zaharia，arXiv:2004.12832）是一种文本检索方法。它不是每文档一个向量，而是每令牌一个向量。在查询时：

- 查询令牌获得自己的嵌入（N_q 个向量）。
- 文档令牌获得嵌入（N_d 个向量，通常缓存）。
- 得分 = 查询令牌中每个令牌取文档令牌中最大余弦相似度后求和：Σ_i max_j cos(q_i, d_j)。

这就是 MaxSim 运算。每个查询令牌“选择”其最佳匹配的文档令牌。最终得分是求和。

优点：强召回率，处理词级语义。缺点：每文档 N_d 个向量，存储代价高。

### ColPali

ColPali（Faysse 等人，arXiv:2407.01449）将 ColBERT 模式应用于图像。

- 每个页面由 PaliGemma（ViT + 语言）编码为补丁嵌入：每页面 N_p 个向量。
- 每个用户查询（文本）被编码为查询令牌嵌入：N_q 个向量。
- 得分 = Σ_i max_j cos(q_i, p_j)，即查询文本令牌与页面图像补丁之间的 MaxSim。
- 根据总分检索 top-k 页面。

在文档摄取时：用 PaliGemma 嵌入每个页面，存储所有补丁嵌入。在查询时：嵌入查询令牌，计算对所有已存储页面嵌入的 MaxSim，返回 top-k 页面。

优点：在视觉丰富的文档上，端到端比文本 RAG 提升 20-40%。每个补丁向量捕获局部布局和内容。

缺点：N_p 个补丁 × 4 字节浮点数 × D 维向量每页面 = 存储快速增长。通过 PQ/OPQ 量化缓解。

### ColQwen2 和 ColSmol

ColQwen2（illuin-tech，2024-2025）将 PaliGemma 替换为 Qwen2-VL。更好的基础编码器，更好的检索。

ColSmol 是针对本地/边缘使用的小规模变体。大约 1B 参数的 ColSmol 检索器可以在消费级 GPU 上运行。

### VisRAG

VisRAG（Yu 等人，arXiv:2410.10594）是一种不同的变体：不是对补丁进行 MaxSim，而是通过 VLM 将每个页面池化为单个向量，然后进行双编码器检索。更快的索引 + 更小的存储，但召回率较弱。

质量与成本的权衡：ColPali 用于质量，VisRAG 用于规模。

### M3DocRAG

M3DocRAG（Cho 等人，arXiv:2411.04952）将多模态检索扩展到多页面多文档推理。跨文档检索页面，构建多页面上下文供 VLM 使用。

### ViDoRe — 基准测试

ColPali 的配套基准测试。视觉文档检索评估。任务包括财务报告、科学论文、行政文档、医疗记录、手册。指标：nDCG@5。

ColPali-v1 在 ViDoRe 上得分约 80% nDCG@5；相同文档上的文本 RAG 得分约 50-60%。

### 端到端 RAG 流程

对于视觉原生 RAG：

1. 摄取：PDF → 页面图像 → PaliGemma 编码 → 存储所有补丁嵌入。
2. 查询：用户文本 → 查询令牌嵌入 → 对所有索引页面进行 MaxSim → top-k 页面。
3. 生成：top-k 页面图像 + 查询 → VLM（Qwen2.5-VL 或 Claude）→ 答案。

任何地方都没有 OCR。图形、图表、字体、布局都流入答案中。

### 存储计算

一份 50 页的财务报告，每页 729 个补丁，128 维嵌入：

- ColPali：50 * 729 * 128 * 4 字节 = 约 18 MB 原始，约 4 MB（PQ 后）。
- 文本 RAG：50 个块 * 768 维 * 4 字节 = 约 150 kB。

ColPali 每文档的存储量大约是文本 RAG 的 30 倍。在大规模下，OPQ/PQ 将其降到约 5-10 倍，通常可接受。

### 文本 RAG 仍然胜出的时候

- 没有布局信号的纯文本文档（维基文章、聊天记录）。文本 RAG 更简单且存储成本更低。
- 数百万页的档案，存储占主导成本。
- 严格的法规要求检索时附带可提取的 OCR 文本。

对于 2026 年其他几乎所有情况——财务报告、科学论文、法律合同、医疗记录、UX 文档——视觉原生 RAG 胜出。

## 使用

`code/main.py`：

- 玩具补丁编码器：将“页面”（一个小的特征向量网格）映射为补丁嵌入数组。
- MaxSim 评分器：计算一组查询令牌嵌入与一组页面补丁嵌入之间的 ColBERT 风格得分。
- 索引 5 个玩具页面，运行 3 个查询，返回带有得分的 top-k 页面。

## 练习

1. 一份 200 页的年度报告，每页 729 个补丁，128 维嵌入，4 字节浮点数。计算原始存储和 PQ 压缩（8 倍）存储。

2. MaxSim 是 Σ_i max_j cos(q_i, p_j)。这个求和捕获了哪些简单平均相似度无法捕获的信息？

3. ColPali 将页面索引为补丁集合。如果我们改为在词级别索引（如 ColBERT 所做），会有什么变化？权衡？

4. 为一个 100 万页的语料库设计端到端流程，延迟预算为每查询 500ms。选择 ColQwen2 / VisRAG 并说明理由。

5. 阅读 M3DocRAG（arXiv:2411.04952）。描述多页面注意力模式及其与单页面 ColPali 检索的不同之处。

## 关键术语

| 术语 | 人们通常说的 | 实际含义 |
|------|-----------------|------------------------|
| 后期交互 | "ColBERT 风格" | 使用每令牌或每补丁嵌入 + MaxSim 进行检索，而非单个文档向量 |
| MaxSim | "最大补丁" | 对每个查询令牌，选择相似度最高的文档令牌；所有查询令牌求和 |
| 双编码器 | "单向量" | 每文档一个向量；更快但失去粒度 |
| 多向量 | "每文档多个向量" | 每文档/页面存储 N_p 个向量；存储成本增加但召回率提升 |
| 补丁嵌入 | "页面特征" | 来自 VLM 编码器的每个图像补丁一个向量，每页面缓存 |
| ViDoRe | "视觉文档基准" | ColPali 的视觉文档检索基准套件 |
| PQ 量化 | "乘积量化" | 在保持向量相似性的同时压缩存储约 8 倍的压缩方法 |
