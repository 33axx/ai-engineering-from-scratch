# CAIS、CAISI 与社会规模风险

> AI安全中心（CAIS，旧金山，2022年由 Hendrycks 和 Zhang 创立）发布了四类风险框架——恶意使用、AI竞赛、组织风险、失控AI——以及2023年5月由数百位教授和公司领袖签署的灭绝风险声明。CAIS于2026年发布：前沿模型评估的AI仪表盘、远程劳动指数（与Scale AI合作）、超级智能战略报告、AI前沿通讯。另一个独立实体：NIST AI标准与创新中心（CAISI）——面向美国政府的自愿协议和机密能力评估，重点关注网络、生物和化学武器风险。CAIS将组织风险列为四大顶级风险之一：安全文化、严格审计、多层防御和信息安全是基础，但常与部署速度权衡。加利福尼亚州SB-53法案如获签署，将成为美国首部州级灾难性风险监管法律。

**类型：** 学习
**语言：** Python（标准库，四类风险清单与缓解措施匹配器）
**前置要求：** 阶段15·19（RSP），阶段15·20（PF + FSF）
**时间：** 约45分钟

## 问题

第19课和第20课涵盖了实验室内部规模政策。第21课涵盖了独立能力评估。本课涵盖第三个视角：塑造公众讨论和灾难性AI风险监管基准的民间社会与政府组织。

两个不同的实体值得关注。CAIS是一个非盈利研究组织，发布思考AI风险的框架并协调公开声明。CAISI是美国政府机构，隶属于NIST，负责与实验室运行自愿协议以及非机密能力评估。名称相似，但使命无重叠。实践者应了解两者。

实用内容：CAIS的四类风险框架是文献中被引用最广泛的社会规模风险分类法。安全文化和组织风险是四大类之一，也是实践者最可控的一类。SB-53（加州）如获签署，将成为美国首部州级灾难性风险监管法律；该法案的框架重要，因为在美国科技政策历史上，州级监管常引领联邦行动。

## 概念

### CAIS — AI安全中心

- 成立：2022年，旧金山，由Dan Hendrycks及同事创立（“Zhang”指早期合作者，非现任联合创始人；当前领导层见CAIS网站）。
- 状态：501(c)(3)非营利组织。
- 2023年显著成果：灭绝风险声明，数百位研究人员和CEO联署。声明：“减轻AI灭绝风险应成为全球优先事项，与大流行病和核战争等其他社会规模风险并列。”
- 2026年成果：前沿模型评估的AI仪表盘、远程劳动指数（与Scale AI联合）、超级智能战略报告、AI前沿通讯。

### 四类风险框架

CAIS的框架将灾难性AI风险分为四大顶级类别：

1. **恶意使用**：不良行为者利用AI造成伤害（生物武器合成、虚假信息、网络攻击）。
2. **AI竞赛**：实验室、公司或国家之间的竞争压力推动部署越过安全边界。
3. **组织风险**：实验室内部动态（安全文化失败、审计不足、安全投入不足）导致不良部署。
4. **失控AI**：能力足够强的AI追求与人类福祉相冲突的目标。

这并非唯一的分类法，但却是被引用最多的。类别并非互斥——一个由为追求速度而牺牲审计的组织在竞赛中产出的失控AI，同时属于全部四类。

### 组织风险的定位

四类中，组织风险对实践者最可操作。实验室的安全文化、审计严谨性、防御层次和信息安全，决定了其模型是否真正带有第10–18课所述的控制措施，还是仅停留在无人核验的检查表项目。

具体的组织风险杠杆：

- **安全文化**：团队成员是否能够在不损害职业前途的情况下上报关切？CAIS调查发现，这是其他杠杆的强预测指标。
- **严格审计**：外部和内部。仅靠内部审计会产生乐观报告。
- **多层防御**：没有哪一层足够（阶段15贯穿主题）。
- **信息安全**：模型权重泄露、评估数据泄露、监控规避技术泄露。第19课中的RAND SL-4是具体标准。

### CAISI — AI标准与创新中心

- 隶属于NIST。
- 与前沿实验室运行自愿协议。
- 发布非机密能力评估，重点关注网络、生物和化学武器风险。
- 与CAIS不同；缩写撞车；检查URL（nist.gov）确认正在阅读的是哪个。

CAISI的角色是METR私人实验室接洽（第21课）的公共、政府对应方。CAISI报告是非机密的；METR报告往往受NDA限制。同时阅读两者的实践者能获得更全面的图景。

### 加利福尼亚州SB-53

加州参议院法案（2025–2026会期）针对前沿模型的灾难性风险。起草中的关键规定：

- 触发州级义务的具体能力阈值。
- AI实验室员工的举报人保护。
- 灾难性故障的事件报告要求。

如获签署，将成为美国首部州级灾难性风险监管法律。无论签署与否，该法案的框架塑造了其他州立法机构处理该问题的方式。加州的实践者应跟踪法案状态；其他地区的实践者应阅读它以了解美国州级监管可能的样子。

### 社会规模风险并非单一层级问题

阶段15贯穿主题——纵深防御——同样适用于社会层级。没有任何单一组织、法规或框架能消除灾难性风险。生态系统仅在以下条件同时满足时才能正常运作：

- 实验室制定规模政策（第19、20课）。
- 外部评估者进行测量（第21课）。
- 民间社会跟踪并公开（CAIS）。
- 政府运行自愿项目和基线监管（CAISI、SB-53）。
- 实践者构建多层控制措施（第10–18课）。

这是该阶段的最终综合：每一前置课都是堆栈中的一层，其完整度比任何单层强度更为重要。

## 使用

`code/main.py` 实现了一个小型风险库存工具。给定一个拟议的部署，它对部署进行四类风险标签，并返回缓解清单。它是框架的阅读辅助工具，不能替代人工判断。

## 交付

`outputs/skill-societal-risk-review.md` 审查一个部署的社会规模风险态势：涉及哪几类风险，已有哪些缓解措施，组织风险暴露情况如何。

## 练习

1. 运行 `code/main.py`。输入三个不同规模的合成部署。确认四类风险标签与你预期一致；找出一个工具过度标记或不足标记的案例。

2. 完整阅读CAIS的四类风险论文。选择一个风险类别，写两段话说明你认为是2026年该类别中最重要的发展。

3. 阅读加州SB-53的当前草案。找出一条你认为能加强灾难性风险态势的规定和一条你认为会削弱风险态势的规定。为两者给出理由。

4. 选择一个你了解的生产级AI部署（你自己的或已发布的）。对照组织风险子杠杆评分：安全文化、审计严谨性、多层防御、信息安全。哪个最薄弱？使其达到标准需要多少成本？

5. 草拟一份2028年版的四类风险框架，反映额外一年的能力和一年部署经验。你会添加、移除或重组什么？
