# 合规 — SOC 2、HIPAA、GDPR、PCI-DSS、欧盟AI法案、ISO 42001

> 多框架覆盖是2026年企业交易的入场门槛。**欧盟AI法案**：自2024年8月1日起生效。高风险要求大多自2026年8月2日起执行。高风险系统义务罚款额高达1500万欧元或全球年营业额的3%（第99条第4款）；被禁止的AI行为罚款额高达3500万欧元或7%（第99条第3款）。若服务欧盟用户，则全球适用。**科罗拉多州AI法案**：自2026年6月30日起生效（由SB25B-004从2026年2月推迟）——高风险系统需进行影响评估，AI决策的上诉权。弗吉尼亚州类似，覆盖信贷、雇佣、住房、教育。**SOC 2 Type II**：企业AI的事实标准（B2B领域要求Type II而非Type I，金融科技尤甚）。**GDPR**：迄今最大的AI专项GDPR罚款为3050万欧元（针对Clearview AI，荷兰DPA，2024年9月）；意大利Garante于2024年12月对OpenAI处以1500万欧元罚款（2026年3月在上诉中被推翻）。推理时实时PII脱敏是可辩护的标准；事后清理不够充分。**HIPAA**：医疗保健行业受约束——如果没有BAA，不得将受保护健康信息（PHI）发送给外部AI服务。**PCI-DSS**：AI交互层覆盖需要配置加合同约定，非自动生效。**ISO 42001**：新兴的AI治理标准，与ISO 27001一同成为日益增长的采购要求。参考档案：OpenAI拥有SOC 2 Type 2、ISO/IEC 27001:2022、ISO/IEC 27701:2019、GDPR/CCPA/HIPAA（BAA）/FERPA、ChatGPT支付组件相关的PCI-DSS。跨框架映射可减少审计疲劳：访问控制可映射至ISO 27001 A.5.15-5.18、GDPR第32条、HIPAA §164.312(a)。

## 学习目标

- 列举2026年与LLM产品相关的七个框架，并将每个框架对应到客户细分领域。
- 引用欧盟AI法案的执行时间线（2024年8月生效；高风险强制执行2026年8月）及两档罚款上限（高风险义务1500万欧元/3%，禁止行为3500万欧元/7%）。
- 解释为何事后PII清理不足以满足GDPR，并指出推理层实时脱敏是可辩护的标准。
- 描述跨框架控制映射（例如，访问控制映射至ISO 27001 A.5.15-5.18 + GDPR第32条 + HIPAA §164.312(a)）。

## 问题

一家企业客户的采购部门要求具备SOC 2 Type II、GDPR、HIPAA BAA、ISO 27001以及“欧盟AI法案合规声明”。你的团队只有SOC 2 Type I。距离获得Type II还有六个月，并且尚未开始维护GDPR第30条记录。

多框架覆盖并非LLM特有的问题——这是一个企业SaaS问题，加上LLM特定的覆盖层。2026年的采购团队希望看到一个矩阵：每行一个框架，每列一个控制项，而不是PDF文件。

## 概念

### 七个框架

| 框架 | 适用范围 | LLM特定要求 |
|------|----------|-------------|
| SOC 2 Type II | B2B SaaS基线 | 流程控制需审计6-12个月 |
| HIPAA | 美国医疗保健 | 需要BAA；未经签署协议，PHI不得离开基础设施 |
| GDPR | 欧盟用户 | 实时PII脱敏；数据主体权利；第30条记录 |
| PCI-DSS | 支付数据 | 涉及支付的AI需要配置加合同 |
| 欧盟AI法案 | 服务欧盟用户 | 风险等级分类；高风险系统：合规评估、文档、日志 |
| 科罗拉多州AI法案 | 服务科罗拉多州居民 | 影响评估；上诉权 |
| ISO 42001 | AI治理 | 新兴；与ISO 27001配套 |

### 欧盟AI法案时间线

- 2024年8月1日：生效。
- 2025年2月2日：禁止的AI行为开始执行。
- 2026年8月2日：高风险系统开始执行（合规评估、文档、日志）。
- 2027年8月：纳入统一立法产品中的高风险系统。

风险等级：不可接受（禁止）、高风险（合规+日志）、有限风险（透明度）、最低风险（无约束）。大多数B2B LLM SaaS属于有限风险；就业、信贷、教育、执法、移民、基础服务领域属于高风险。

罚款（第99条）：违反高风险系统义务最高1500万欧元或全球年营业额3%（第99条第4款）；被禁止的AI行为最高3500万欧元或7%（第99条第3款）；取较高者。

### GDPR — 实时脱敏是标准

事后清理（在LLM看到PII后再脱敏）不是可辩护的立场——模型已经看到了数据。推理层实时脱敏是2026年的标准：

- 在LLM调用前进行实体识别。
- 一致的标记化（Mesh方法）保留语义。
- 仅存储已脱敏的提示及经过同意的原始数据（opt-in）。

近期执法案例：3050万欧元罚款（针对Clearview AI，荷兰DPA，2024年9月）是有记录以来最大的AI专项GDPR罚款；1500万欧元罚款（针对OpenAI，意大利Garante，2024年12月）是最大的LLM专项GDPR罚款，但在2026年3月上诉中被推翻，裁决仍在进一步审查中。基于事后处理的主张在审计中未被接受。

### HIPAA — BAA不可省略

未经签署业务伙伴协议（BAA），不得将PHI发送给外部AI服务。三大超大规模LLM平台（Bedrock、Azure OpenAI、Vertex）均提供BAA。OpenAI直接API提供BAA。Anthropic直接API提供BAA。在发送PHI前请务必确认。

### SOC 2 Type II

Type I：控制被设计并有文档记录。  
Type II：控制在实际运行中有效运作6-12个月。

2026年B2B采购默认要求Type II。Type I是起点，Type II是门槛。

常见审计驱动因素：访问日志（谁看到了什么）、变更管理（如何部署）、风险评估（季度）、事件响应（是否经过测试？）。阶段17 · 25中的审计日志可直接复用。

### 跨框架映射

一项访问控制策略可满足多个框架的控制要求：

| 控制项 | 适用框架 |
|--------|----------|
| 访问日志 | ISO 27001 A.5.15-5.18、GDPR第32条、HIPAA §164.312(a) |
| 变更管理 | ISO 27001 A.8.32、PCI DSS要求6、HIPAA违规通知范围 |
| 传输加密 | ISO 27001 A.8.24、GDPR第32条、HIPAA §164.312(e) |
| 密钥管理 | ISO 27001 A.8.19、PCI DSS要求8、SOC 2 CC6.1 |

合规工具（Drata、Vanta、Secureframe）可自动完成此类映射。规模化后值得投入成本。

### ISO 42001 — 新兴标准

发布于2023年底。与ISO 27001一同成为日益增长的采购要求。AI治理框架，包括风险管理、数据质量、透明度、人工监督。

### OpenAI参考档案

OpenAI持有SOC 2 Type 2、ISO/IEC 27001:2022、ISO/IEC 27701:2019、GDPR/CCPA/HIPAA（BAA）/FERPA、ChatGPT支付组件的PCI-DSS。这大致就是2026年企业入场门槛的要求。

### 应记住的数字

- 欧盟AI法案罚款：高风险义务最高1500万欧元/3%（第99条第4款）；禁止行为最高3500万欧元/7%（第99条第3款）。
- 欧盟AI法案高风险强制执行：2026年8月2日。
- 有记录的AI专项GDPR最高罚款：3050万欧元，Clearview AI（荷兰DPA，2024年9月）。
- LLM专项GDPR最高罚款：1500万欧元，OpenAI（意大利Garante，2024年12月；2026年3月上诉推翻）。
- SOC 2 Type II窗口：控制运行6-12个月。
- 科罗拉多州AI法案生效日期：2026年6月30日（由SB25B-004从2026年2月推迟）。
