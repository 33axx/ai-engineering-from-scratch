# 基于评估的智能体开发

> Anthropic 的指导原则："从简单提示开始，用全面评估优化，只有在必要时才添加多步智能体系统。" 评估不是最后一步。它是驱动第 14 阶段所有其他选择的外部循环。

**类型：** 学习 + 构建  
**语言：** Python (stdlib)  
**先决条件：** 第 14 阶段全部内容  
**时间：** ~60 分钟  

## 学习目标

- 说出三个评估层次——静态基准、自定义离线、在线生产——以及各自的用途。
- 解释评估器-优化器的紧密循环。
- 描述 2026 年最佳实践：评估与代码共存、在 CI 中运行、门控 PR。
- 将第 14 阶段的每个课程与其产生的评估用例联系起来。

## 问题

智能体通过演示。它们在生产中失败的方式是演示无法预测的。基准回答的是"这个模型大体上是否胜任？"，而不是"这个智能体是否为我的产品交付正确的补丁？"答案：在三个层次上持续评估，每个护栏和学习规则都映射到一个评估用例。

## 概念

### 三个评估层次

1. **静态基准** — 用于代码的 SWE-bench Verified（课程 19）、用于浏览/桌面的 WebArena/OSWorld（课程 20）、用于通用任务的 GAIA（课程 19）、用于工具调用的 BFCL V4（课程 06）。用于跨模型比较和回归门控。污染是真实存在的：SWE-bench+ 发现 32.67% 的解决方案泄漏。始终报告 Verified / +-audited 分数。

2. **自定义离线评估** — 你产品的形态：
   - LLM 作为裁判（Langfuse, Phoenix, Opik — 课程 24）。
   - 基于执行的评估（运行补丁，检查测试）。
   - 基于轨迹的评估（将动作序列与黄金标准进行比较；OSWorld-Human 显示顶级智能体比黄金标准长 1.4-2.7 倍）。

3. **在线评估** — 生产环境：
   - 会话回放（Langfuse）。
   - 护栏触发的警报（课程 16, 21）。
   - 每步骤成本/延迟追踪（课程 23 OTel spans）。

### 评估器-优化器（Anthropic）

紧密循环：

1. 提议者生成输出。
2. 评估者判断。
3. 优化直到评估者通过。

这是 Self-Refine（课程 05）的泛化形式。任何你关心的智能体流程都可以包裹在评估器-优化器循环中以提升可靠性。

### 2026 年最佳实践

- 评估与代码共存。
- 在每个 PR 的 CI 中运行。
- 基于评估分数门控合并（例如"与主分支相比回归不超过 5%"）。
- 每个护栏映射到一个评估用例。
- 每个学习规则（Reflexion、pro-workflow learn-rule）映射到一个失败用例。

### 基于评估的开发在哪些方面失败

- **无基线。** 没有已知最后良好状态的评估是不可读的。存储基线。
- **无依据的 LLM 裁判。** 裁判也会产生幻觉。使用 CRITIC 模式（课程 05）——裁判基于外部工具提供依据。
- **对评估过拟合。** 为了评估优化会偏离生产实用性。轮换用例。
- **不稳定的评估。** 非确定性用例导致误报。固定随机种子，快照状态。

## 构建它

`code/main.py` 是一个 stdlib 评估框架：

- 用例注册表，包含类别（benchmark, custom, online）。
- 一个脚本化的待测智能体。
- 评估器-优化器循环：提议、判断、优化直到通过或达到最大轮数。
- CI 门控：聚合通过率 + 相对于基线的回归。

运行它：

```
python3 code/main.py
```

输出：每个用例的通过/失败、回归标志、CI 门控裁决。

## 使用它

- 在与智能体代码相同的仓库中编写评估用例。
- 在每个 PR 上通过 CI 运行它们。
- 在回归时使构建失败。
- 跟踪通过率随时间的变化。
- 将每个生产失败与一个新用例联系起来。

## 交付它

`outputs/skill-eval-suite.md` 为一个智能体产品构建了一个三层评估套件，包含 CI 门控和回归跟踪。

## 练习

1. 选择你的一次生产失败。编写一个能够复现它的评估用例。你的智能体现在能通过它吗？
2. 为你的领域构建一个包含三个维度（事实准确性、语气、范围）的 LLM 裁判评分标准。对 50 个会话进行评分。
3. 将评估套件接入 CI。当回归 >=5% 时使构建失败。
4. 添加一个轨迹效率指标：智能体采取的步骤数与黄金轨迹的比值。
5. 将第 14 阶段的每个课程映射到你套件中的一个评估用例。有缺失的吗？那就是需要填补的缺口。

## 关键术语

| 术语 | 人们所说的 | 实际含义 |
|------|----------------|------------------------|
| 静态基准 | "现成的评估" | SWE-bench, GAIA, AgentBench, WebArena, OSWorld |
| 自定义离线评估 | "领域评估" | 基于 LLM 裁判 / 执行 / 轨迹的评估，针对你的产品形态 |
| 在线评估 | "生产评估" | 会话回放、护栏警报、成本/延迟追踪 |
| 评估器-优化器 | "提议-判断-优化" | 迭代直到裁判通过 |
| CI 门控 | "合并拦截器" | 在评估回归时使构建失败 |
| 基线 | "已知最后良好状态" | 用于检测回归的参考分数 |
| 轨迹效率 | "相对于黄金标准的步骤数" | 智能体步骤数除以人类专家最小值 |
