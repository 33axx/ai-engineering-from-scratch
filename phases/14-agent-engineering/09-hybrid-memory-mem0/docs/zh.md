# 混合记忆：向量 + 图 + KV（Mem0）

> Mem0（Chhikara等人，2025）将记忆视为三个并行的存储——向量用于语义相似性，KV用于快速事实查找，图用于实体关系推理。一个评分层在检索时融合三者。这是2026年外部记忆的生产标准。

**类型：** 构建
**语言：** Python（标准库）
**先决条件：** 第14阶段·07（MemGPT），第14阶段·08（Letta Blocks）
**时间：** 约75分钟

## 学习目标

- 解释为何单一存储（仅向量、仅图、仅KV）不足以满足智能体记忆。
- 说出Mem0的三个并行存储以及各自优化的内容。
- 描述Mem0的融合评分——相关性、重要性、新近性——并解释为何它是加权和而非层级结构。
- 使用标准库实现一个简易的三存储记忆，包含写入所有三个存储的`add()`和融合结果的`search()`。

## 问题所在

单一存储对于三类查询中至少两类是错误的：

- **语义相似性** —— “上周我们讨论了关于智能体漂移的什么？” 向量胜出；KV和图都会失效。
- **事实查找** —— “用户的电话号码是什么？” KV胜出；向量是浪费，图是过度设计。
- **关系推理** —— “哪些客户共享同一个结算实体？” 图胜出；向量和KV都无法回答。

生产级智能体会在同一个会话中发出所有三类查询。单一存储记忆总是至少对其中两类是错误的。Mem0的贡献在于将三者整合在同一个`add`/`search`接口之后，并提供一个融合它们的评分函数。

## 概念

### 三个并行存储

Mem0（arXiv:2504.19413，2025年4月）在`add(text, user_id, metadata)`时：

1. 从文本中提取候选事实（LLM驱动的步骤）。
2. 将每个事实写入向量存储（嵌入）以用于语义搜索。
3. 将每个事实写入KV存储，键为`(user_id, fact_type, entity)`以进行O(1)查找。
4. 将每个事实写入图存储（Mem0g）作为带类型的边以支持关系查询。

在`search(query, user_id)`时：

1. 向量存储按嵌入余弦距离返回top-k。
2. KV存储按查询派生出的`(user_id, type, entity)`返回直接匹配。
3. 图存储返回从查询实体可达的子图。
4. 一个评分层融合三者。

### 融合评分

```
score = w_relevance * relevance(q, record)
      + w_importance * importance(record)
      + w_recency * recency(record)
```

- **相关性** —— 向量余弦、KV精确匹配、图路径权重。
- **重要性** —— 写入时标记或学习得到（某些事实更重要：姓名、ID、策略）。
- **新近性** —— 自上次写入或读取以来随时间指数衰减。

权重按产品调整。聊天智能体取更高的`w_recency`；合规智能体取更高的`w_importance`；检索智能体取更高的`w_relevance`。

### Mem0g与时间推理

Mem0g增加了一个冲突检测器。当新事实与现有边冲突时，现有边被标记为无效但不删除。时间查询（“用户三月份所在的城市是？”）遍历在特定时间点有效的子图。

这正是Letta失效模式所泛化的合规级行为。

### 基准数据

Mem0论文报告（2025年）：

- **LoCoMo**（长形式对话记忆）：91.6
- **LongMemEval**（长时域情景记忆）：93.4
- **BEAM 1M**（百万Token记忆基准）：64.1

对比基线（全上下文128k LLM、平面向量存储、平面KV）全部落后10+分。基准本身不能证明选择正确——操作形态才是关键——但这些数字表明融合设计并非四舍五入的误差。

### 作用域分类

Mem0按作用域划分记忆：

- **用户记忆** —— 跨会话持久，以`user_id`键控。
- **会话记忆** —— 在单个线程内持久。
- **智能体记忆** —— 每个智能体实例的状态。

每次写入选择一个作用域。检索可以跨作用域查询，并为每个作用域设置权重。不经思考地混合作用域会导致“助手告诉Alice关于Bob的项目”之类的事故。

### 此模式可能出问题的地方

- **嵌入漂移。** 前一百次查询看起来正确的向量结果随着语料库增长而退化。定期重新嵌入最常使用的N条记录。
- **KV模式蔓延。** `(user_id, type, entity)`看起来很简洁，直到每个团队都添加自己的`type`。每季度审计一次类型集合。
- **图爆炸。** 一个嘈杂的提取器每条消息添加50条边。限制每次`add`调用的图写入数量；丢弃低置信度的边。

## 构建它

`code/main.py` 使用标准库实现了三存储模式：

- `VectorStore` —— 使用朴素的token重叠相似度作为嵌入的替代。
- `KVStore` —— 以`(user_id, fact_type, entity)`为键的字典。
- `GraphStore` —— 带类型的边（subject, relation, object, valid）。
- `Mem0` —— 顶层外观，包含`add()`、`search()`、融合评分以及支持作用域感知的检索。
- 一个多用户、多会话对话的完整追踪示例。

运行它：

```
python3 code/main.py
```

输出显示三条独立的召回路径以及融合后的top-k。调整`main()`顶部的评分权重，观察排序变化。

## 使用它

- **Mem0（Apache 2.0）** —— 生产就绪。使用Postgres + Qdrant + Neo4j自托管，或使用托管云服务。
- **Letta** —— 三层核心/召回/归档；自带向量和图后端。
- **Zep** —— 商业替代方案，提供时间知识图谱和事实提取。
- **自定义构建** —— 当你需要精确控制提取器（合规场景）或融合权重（新近性占主导的语音智能体）时。

## 部署它

`outputs/skill-hybrid-memory.md` 生成一个带有融合评分器、作用域分类和时间失效机制的三存储记忆脚手架。

## 练习

1. 将简易向量相似度替换为真实的嵌入模型（sentence-transformers、Ollama、OpenAI嵌入）。在一个合成长对话上测量 recall@10。经过1000次写入后，排序会漂移吗？
2. 添加时间查询：`search(query, as_of=timestamp)`。仅返回在该时间或之前有效的记录。哪个存储需要最多工作？
3. 实现一个冲突检测器：如果新传入的事实与图边冲突，则将旧边标记为无效并记录两者。测试“用户住在柏林” -> “用户住在里斯本”。
4. 在融合评分器中增加`user_feedback`维度（对已检索记录点赞）。如何防止作弊（智能体只返回它已经喜欢的记录）？
5. 阅读Mem0文档（`docs.mem0.ai`）。将简易实现移植为`mem0`客户端调用。在20个相同的测试查询上比较检索质量。

## 关键术语

| 术语 | 人们通常说的 | 实际含义 |
|------|----------------|------------------------|
| Hybrid memory | "向量加图加KV" | 三个存储并行写入，检索时融合 |
| Fact extraction | "记忆摄取" | LLM步骤，将文本拆解为(实体, 关系, 事实)元组 |
| Fusion scoring | "相关性排序" | 相关性、重要性、新近性的加权和 |
| Scope | "记忆命名空间" | 用户/会话/智能体——决定谁能看到什么 |
| Mem0g | "记忆图" | 带时间有效性的类型化边，用于关系查询 |
| Temporal invalidation | "软删除" | 将冲突边标记为无效；从不删除 |
| Embedding drift | "检索腐烂" | 向量质量随语料库增长而退化；定期重新嵌入 |
