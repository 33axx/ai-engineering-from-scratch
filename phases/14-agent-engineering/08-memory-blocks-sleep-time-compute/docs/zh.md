# 记忆块与睡眠时计算（Letta）

> 2024 年 MemGPT 更名为 Letta。2026 年的演进引入了两个新概念：离散的功能性记忆块（模型可直接编辑），以及睡眠时智能体（在主智能体空闲时异步进行记忆整合）。这就是如何将记忆扩展到单次对话之外。

**类型：** 构建
**语言：** Python（标准库）
**前置知识：** 阶段 14 · 07（MemGPT）
**时间：** 约 75 分钟

## 学习目标

- 说出 Letta 使用的三个记忆层级（核心、回忆、归档）及各层级的作用。
- 解释记忆块模式：人类块、角色块以及作为一等类型对象的用户定义块。
- 描述什么是睡眠时计算，为什么它不位于关键路径上，以及为什么它能运行比主智能体更强的模型。
- 实现一个脚本化的双智能体循环：主智能体负责响应，睡眠时智能体在回合之间进行块合并。

## 问题

MemGPT（课程 07）解决了虚拟内存的控制流问题。但生产环境暴露了三个问题：

1. **延迟。** 每个内存操作都位于关键路径上。如果智能体在用户等待时需要做修剪、摘要或协调工作，尾部延迟会急剧上升。
2. **记忆腐败。** 写入不断累积。矛盾的事实仍然存在。检索被陈旧内容淹没。
3. **结构缺失。** 扁平化的归档存储无法表达"人类块始终在提示中；角色块始终在提示中；任务块按会话切换"。

Letta（letta.com）是 2026 年的重写版本。记忆块使结构变得明确；睡眠时计算将合并操作移出关键路径。

## 概念

### 三个层级

| 层级 | 范围 | 所在位置 | 写入者 |
|------|------|----------|--------|
| 核心 | 始终可见 | 主提示内部 | 智能体工具调用 + 睡眠时重写 |
| 回忆 | 对话历史 | 可检索 | 自动回合记录 |
| 归档 | 任意事实 | 向量 + 键值 + 图 | 智能体工具调用 + 睡眠时摄取 |

核心就是 MemGPT 中的核心。回忆是对话缓冲区及其被驱逐的尾部。归档是外部存储。这种划分解决了 MemGPT 两层模型的重载问题。

### 记忆块

块是核心层级中一个带类型、持久化、可编辑的段落。最初的 MemGPT 论文定义了两种：

- **人类块** — 关于用户的事实（姓名、角色、偏好、目标）。
- **角色块** — 智能体的自我概念（身份、语气、约束）。

Letta 将其泛化为任意用户定义的块：用于当前目标的 `Task` 块，用于代码库事实的 `Project` 块，用于硬约束的 `Safety` 块。每个块都有 `id`、`label`、`value`、`limit`（字符上限）、`description`（以便模型知道何时编辑它）。

块通过工具接口进行编辑：

- `block_append(label, text)`
- `block_replace(label, old, new)`
- `block_read(label)`
- `block_summarize(label)` — 当块接近其限制时进行压缩。

### 睡眠时计算

2025 年 Letta 新增：在后台运行第二个智能体，脱离关键路径。睡眠时智能体处理对话转录和代码库上下文，将 `learned_context` 写入共享块，并合并或失效归档记录。

由此产生的特性：

- **无延迟代价。** 主智能体的响应无需等待内存操作。
- **允许更强模型。** 睡眠时智能体可以使用更昂贵、更慢的模型，因为它不受延迟约束。
- **自然的合并窗口。** 当用户不在等待时，进行去重、摘要、失效矛盾事实。

这个模式与人类的工作方式类似：你完成任务，然后睡一觉，长期记忆在夜间沉淀下来。

### Letta V1 与原生推理

Letta V1（`letta_v1_agent`，2026）废弃了 `send_message`/心跳以及内联的 `Thought:` 标记，转而采用原生推理。OpenAI 的 Responses API 和 Anthropic 的 Messages API（扩展思维）在独立通道上输出推理过程，在回合间传递（生产环境中跨提供商加密）。控制循环仍然是 ReAct。思维轨迹是结构化的，而非提示形状。

### 这个模式哪里会出错

- **块膨胀。** 无限制的 `block_append` 很快会触及上限。在写入会超过上限之前，先接入一个块摘要器。
- **静默漂移。** 睡眠时智能体重写了一个块，但主智能体从未注意到。对块进行版本化，并在跟踪记录中展示差异。
- **受污染的合并。** 睡眠时智能体将攻击者可控的内容处理到核心中。课程 27 同样适用于睡眠时的表面。

## 构建它

`code/main.py` 实现：

- `Block` — id、label、value、limit、description。
- `BlockStore` — CRUD + `near_limit(label)` 辅助函数。
- 两个脚本化智能体 — `PrimaryAgent` 负责一个回合，`SleepTimeAgent` 在回合之间进行合并。
- 一个跟踪记录，展示三轮对话中的块写入，以及一个睡眠时过程，对块进行摘要并失效一个陈旧事实。

运行它：

```
python3 code/main.py
```

输出记录显示了这种分离：主回合很快，产生原始写入；睡眠时过程进行压缩和清理。

## 使用它

- **Letta**（letta.com）作为参考实现。可自托管或使用托管云。
- **Claude Agent SDK 技能** 作为块状知识 — 一个技能就是一个命名的、版本化的、可检索的知识块，智能体按需加载。
- **自定义构建** 适用于需要控制存储后端的团队。使用 Letta API 契约，以便以后可以迁移。

## 交付它

`outputs/skill-memory-blocks.md` 生成一个 Letta 形状的块系统，带有睡眠时钩子，可用于任何运行时，包括安全规则和引用接线。

## 练习

1. 添加一个 `block_summarize` 工具，当 `near_limit` 返回 true 时，将块的值替换为模型生成的摘要。哪个触发阈值能使摘要调用次数和块溢出都最小化？
2. 实现睡眠时去重归档：两个文本的 token 重叠超过 90% 的记录合并为一个。只在睡眠时过程中执行，绝不在关键路径上执行。
3. 对块进行版本管理。每次写入时记录旧值及差异。暴露 `block_history(label)`，以便操作员调试"为什么智能体忘记了 X"。
4. 将睡眠时智能体视为不可信的写入者。当它们触及角色块或安全块时，需要第二个智能体审核后才能提交。
5. 将示例移植到使用 Letta API（`letta_v1_agent`）。块模式有哪些变化，原生推理如何改变跟踪记录的形状？

## 关键术语

| 术语 | 人们常说的 | 实际含义 |
|------|-----------|----------|
| 记忆块 | "可编辑的提示段落" | 核心记忆中带类型、持久化、LLM 可编辑的段 |
| 人类块 | "用户记忆" | 关于用户的事实，固定在核心中 |
| 角色块 | "智能体身份" | 自我概念、语气、约束，固定在核心中 |
| 睡眠时计算 | "异步内存工作" | 第二个智能体在关键路径外进行合并 |
| 核心 / 回忆 / 归档 | "层级" | 三层记忆划分：始终可见 / 对话 / 外部 |
| 块限制 | "上限" | 每个块的字符限制；强制进行摘要 |
| 原生推理 | "思维通道" | 提供者级别的推理输出，而非提示级别的 `Thought:` |
| 学习到的上下文 | "睡眠输出" | 睡眠时智能体写入共享块的事实 |
