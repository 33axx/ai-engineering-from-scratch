# 红队测试：PAIR 与自动化攻击

> Chao, Robey, Dobriban, Hassani, Pappas, Wong (NeurIPS 2023, arXiv:2310.08419). PAIR —— 提示自动迭代优化 —— 是一种经典的自动化黑盒越狱方法。带红队系统提示的攻击者大语言模型（LLM）会迭代地为目标LLM提出越狱方案，并将每次尝试及响应累积到自己的聊天历史中，作为上下文反馈。PAIR 通常在 20 次查询内成功，比 GCG（Zou 等人提出的词元级梯度搜索）高效数个数量级，且无需白盒访问权限。PAIR 现在已成为 JailbreakBench (arXiv:2404.01318) 和 HarmBench 中的标准基线，与 GCG、AutoDAN、TAP 和 Persuasive Adversarial Prompt 并列。

**类型：** 动手构建
**语言：** Python（stdlib，针对玩具目标模拟 PAIR 循环）
**前置知识：** 阶段 18 · 01（指令遵循），阶段 14（Agent 工程）
**时间：** ~75 分钟

## 学习目标

- 描述 PAIR 算法：攻击者系统提示、迭代优化、上下文反馈。
- 解释为什么 PAIR 在目标为黑盒时严格优于 GCG。
- 列举另外四种自动化攻击基线（GCG、AutoDAN、TAP、PAP），并说明每种的一个显著特征。
- 描述 JailbreakBench 和 HarmBench 的评估协议，以及各自对“攻击成功率”的定义。

## 问题

红队测试过去是一种手动活动。少数专家测试人员构造对抗性提示，并追踪哪些有效。这种方式无法规模化：攻击成功率需要统计样本，而目标随着模型版本发布而不断变化。PAIR 将红队测试转化为一个针对黑盒目标的优化问题。

## 概念

### PAIR 算法

输入：
- 目标 LLM T（被攻击的模型）。
- 评判 LLM J（评分响应是否属于越狱）。
- 攻击者 LLM A（红队优化器）。
- 目标字符串 G：“回应 [有害指令]。”
- 预算 K（通常为 20 次查询）。

循环，对 k 从 1 到 K：
1. 用目标 G 以及到目前为止的（提示，响应）历史记录来提示 A。
2. A 输出一个新的提示 p_k。
3. 将 p_k 提交给 T；接收响应 r_k。
4. J 对 (p_k, r_k) 根据目标进行评分。
5. 如果分数 >= 阈值，停止——找到越狱。
6. 否则，将 (p_k, r_k) 追加到 A 的历史记录中；继续。

实验结果（NeurIPS 2023）：对 GPT-3.5-turbo、Llama-2-7B-chat 的攻击成功率 >50%；平均成功所需查询次数在 10-20 范围内。

### PAIR 为何高效

GCG（Zou 等人，2023）通过梯度搜索对抗性词元后缀；它需要白盒模型访问权限，并生成不可读的后缀。PAIR 是黑盒的，能生成跨模型迁移的自然语言攻击。PAIR 的上下文反馈让攻击者从每次拒绝中学习；GCG 没有等效机制（每次新的词元更新都必须重新发现之前的进展）。

### 相关的自动化攻击

- **GCG（Zou 等人，2023，arXiv:2307.15043）。** 词元级梯度搜索，寻找对抗性后缀。白盒、可迁移、生成不可读字符串。
- **AutoDAN（Liu 等人，2023）。** 基于进化算法搜索提示，由分层目标引导。
- **TAP（Mehrotra 等人，2024）。** 带剪枝的攻击树——分支多个 PAIR 式展开。
- **PAP（Zeng 等人，2024）。** 说服性对抗提示——将人类说服技巧编码为提示模板。

### JailbreakBench 与 HarmBench

两者（2024）都标准化了评估：

- JailbreakBench（arXiv:2404.01318）。100 个有害行为，涵盖 10 个 OpenAI 政策类别。攻击成功率（ASR）为主要指标。需要评判器（GPT-4-turbo、Llama Guard 或 StrongREJECT）。
- HarmBench（Mazeika 等人，2024）。510 个行为，涵盖 7 个类别，包括语义和功能危害测试。比较 18 种攻击方法对 33 个模型的效果。

ASR 通常在固定查询预算下报告。比较不同攻击需要匹配预算；在 200 次查询下达到 90% ASR 与在 20 次查询下达到 85% ASR 不具备可比性。

### 为何这对 2026 年部署至关重要

每个前沿实验室现在都在发布前对生产模型运行 PAIR 和 TAP。ASR 曲线会出现在模型卡片（第 26 课）和安全案例附录（第 18 课）中。这种攻击并非异类——它已经是标准基础设施。

### 在阶段 18 中的位置

第 12 课是自动化攻击基础。第 13 课（多次越狱）是一种互补的长度利用攻击。第 14 课（ASCII 艺术/视觉）是编码攻击。第 15 课（间接提示注入）是 2026 年生产环境中的攻击面。第 16 课涵盖防御性工具对应部分（Llama Guard、Garak、PyRIT）。

## 动手实践

`code/main.py` 构建了一个玩具 PAIR 循环。目标是一个模拟分类器，它拒绝“明显”有害的提示（关键词过滤）。攻击者是一个基于规则的优化器，尝试改写、角色扮演框架和编码。评判器对响应进行评分。你可以观察到攻击者在大约 5-15 次迭代后成功绕过关键词过滤器，但无法绕过语义过滤器。

## 练习

1. 运行 `code/main.py`。测量三种内置攻击者策略的平均成功查询次数。解释每种策略利用了哪种目标-防御假设。

2. 实现第四种攻击者策略（例如，翻译成另一种语言，base64 编码）。报告针对关键词过滤目标和语义过滤目标的新平均成功查询次数。

3. 阅读 Chao 等人 2023 年论文图 5（PAIR 与 GCG 比较）。描述两种尽管 PAIR 效率更高但仍优先选择 GCG 的场景。

4. JailbreakBench 针对固定目标集报告 ASR。设计一个衡量攻击多样性（成功提示的方差）的额外指标。解释为什么多样性对防御评估很重要。

5. TAP（Mehrotra 2024）通过分支+剪枝扩展了 PAIR。为 `code/main.py` 草拟一个 TAP 风格的扩展，并描述计算成本与成功率之间的权衡。

## 关键术语

| 术语 | 人们怎么说 | 实际含义 |
|------|------------|----------|
| PAIR | “自动化越狱” | 提示自动迭代优化；攻击者LLM + 评判LLM 循环 |
| GCG | “梯度越狱” | 白盒词元级梯度搜索，寻找对抗性后缀 |
| 攻击成功率 (ASR) | “在 k 次查询下的越狱百分比” | 主要指标；必须与查询预算和评判器身份一起报告 |
| 评判 LLM | “评分器” | 对响应是否满足有害目标进行评分的 LLM |
| JailbreakBench | “评估标准” | 标准化的有害行为集，带标签类别 |
| HarmBench | “更广泛的基准” | 510 个行为，功能+语义危害测试 |
| TAP | “攻击树” | PAIR 加上分支+剪枝；在更高计算成本下获得更好 ASR |
