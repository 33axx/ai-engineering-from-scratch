# 动作预算、迭代上限与成本调控

> 一家中等规模的电商智能体月度 LLM 成本在团队启用“订单跟踪”技能后从 1,200 美元跃升至 4,800 美元。这不是定价错误。这是一个智能体找到了新循环并在其中持续消费的问题。微软的 Agent Governance Toolkit（2026 年 4 月 2 日）将针对这类攻击的防御措施规范化：每次请求的 `max_tokens`、每个任务的 Token 与美元预算、每天/每月的上限、迭代上限、分层模型路由、提示缓存、上下文窗口、昂贵动作的人机协同检查点、预算超支时的终止开关。Anthropic 的 Claude Code Agent SDK 也提供了相同的基本功能，只是名称不同。财务速率限制（例如，10 分钟内超过 50 美元则切断访问）比月度上限能更快地捕获循环。

**类型：** 学习
**语言：** Python（标准库、分层成本调控模拟器）
**前置要求：** 阶段 15 · 10（权限模式）、阶段 15 · 12（持久化执行）
**时间：** 约 60 分钟

## 问题

自主智能体在每一步都会消耗实际资金。聊天机器人的糟糕输出只是一次糟糕的回复；而智能体的糟糕循环则是一份账单。业界文档中针对这种失效模式的术语是“拒绝钱包”——智能体不断推理、不断调用工具、不断计费，没有任何东西能阻止它，因为一开始就没有设计任何限制。

解决办法并非一个单一数字。而是一组在不同时间尺度和粒度上的限制栈：每次请求、每个任务、每小时、每天、每月。一个设计良好的限制栈能在几分钟内捕获失控循环，数小时内捕获缓慢泄漏，一天内捕获糟糕的发布。当智能体是长周期且自主运行时，这个限制栈也能始终维持预算。

这是一个工程教训：数学很简单，但纪律往往是团队失败的地方。下面列出的限制要么在微软 Agent Governance Toolkit 中命名，要么在 Anthropic Claude Code Agent SDK 文档中命名。

## 概念

### 成本调控栈

1. **每次请求的 `max_tokens`。** 简单。防止任何单次调用产生无界输出。
2. **每个任务的 Token 预算。** 在整个运行过程中，不超过 N 个 Token。达到上限时硬停止。
3. **每个任务的美元预算。** 与 Token 相同但以货币计算。Claude Code 中的 `max_budget_usd`。
4. **每个工具调用的上限。** 不超过 N 次 `WebFetch` 调用、N 次 `shell_exec` 调用等。
5. **迭代上限（`max_turns`）。** 智能体循环迭代的总次数；防止无限推理循环。
6. **每分钟/每小时/每天/每月上限。** 滚动窗口。在不同时间尺度上捕获泄漏。
7. **财务速率限制。** 例如，“如果 10 分钟内消费超过 50 美元，则切断访问。”在月度上限触发之前捕获循环式消耗。
8. **分层模型路由。** 默认使用较小模型；仅当分类器判断任务需要时才升级到较大模型。
9. **提示缓存。** 系统提示和稳定上下文存储在提供商的缓存中；重新发送的 Token 成本接近于零。
10. **上下文窗口化。** 压缩/摘要以将活动上下文保持在阈值以下；直接降低 Token 成本。
11. **昂贵动作的人机协同检查点。** 在已知昂贵的动作（长时间工具调用、大型下载、昂贵的模型升级）之前，需要人工确认。
12. **预算超支的终止开关。** 当任何上限触发时，会话中止。上限被记录；需要单独的重新启用路径。

### 为什么是栈，而不是单一上限

单一的月度上限只能在钱包耗尽后捕获失控智能体。单一的每次请求上限在会话层面上什么也捕获不到。不同的失效模式需要不同的时间尺度：

- **失控循环**（智能体陷入 5 秒重试循环）：由速率限制捕获。
- **缓慢泄漏**（智能体每个任务完成的工作量约为预期的 2 倍）：由每日上限捕获。
- **糟糕的发布**（新版本使用 5 倍 Token）：由每周/每月上限捕获。
- **合法的激增**（真实需求，而非 bug）：由小时/日上限捕获，并伴有清晰的日志。

### Claude Code 的预算表面

Claude Code Agent SDK 暴露（公开文档）：

- `max_turns` — 迭代上限。
- `max_budget_usd` — 美元上限；超预算时会话中止。
- `allowed_tools` / `disallowed_tools` — 工具允许列表和拒绝列表。
- 在工具使用前的钩子点，用于自定义成本核算。

结合权限模式阶梯（第 10 课）。没有 `max_budget_usd` 的 `autoMode` 会话是没有治理的自主权。Anthropic 明确将自动模式要求预算控制；分类器与成本正交。

### 欧盟 AI 法案、OWASP 智能体安全十大风险

微软的 Agent Governance Toolkit 涵盖了 OWASP 智能体安全十大风险和欧盟 AI 法案第 14 条（人类监督）的要求。在欧盟的生产环境中，日志记录和上限执行不是可选项。

### 观察到的 $1,200 → $4,800 案例

微软文档中的真实案例：一个电商智能体在添加新工具后，月度成本翻了三倍。该工具允许智能体在每次会话中轮询订单状态。没有循环检测。没有每个工具的上限。没有周环比增长的告警。解决办法是设置每个工具的上限加上每日增长告警。这是一个模板：每一个新的工具表面都是一个新的潜在循环；每一个新工具都需要自己的上限和告警。

## 使用它

`code/main.py` 模拟了一个在有无分层成本调控栈情况下的智能体运行。模拟的智能体在某些轮次后陷入轮询循环；分层栈在速率窗口内捕获了它，而单一的月度上限直到几天后才会触发。

## 交付它

`outputs/skill-agent-budget-audit.md` 对提议的智能体部署的成本调控栈进行审计，并标记缺失的层次。

## 练习

1. 运行 `code/main.py`。确认在轮询循环轨迹中，速率限制在迭代上限之前触发。现在禁用速率限制，测量在迭代上限捕获之前智能体“消费”了多少。

2. 为浏览器智能体（第 11 课）设计一组每个工具的上限。哪个工具需要最严格的上限？哪个工具可以无限制运行而没有风险？

3. 阅读微软的 Agent Governance Toolkit 文档。列出该工具包命名的每一种上限类型。将每种类型映射到一种失效模式（失控循环、缓慢泄漏、糟糕的发布、激增）。

4. 为一个现实任务（例如，“对仓库中的 50 个工单进行分类”）估算一次通宵无人值守运行的价格。将 `max_budget_usd` 设置为你的点估计值的 2 倍。证明这 2 倍的合理性。

5. Claude Code 的 `max_budget_usd` 基于会话累计成本触发。设计一个你会在外部强制执行的互补性速率限制。什么触发切断，重新启用看起来是什么样的？

## 关键术语

| 术语 | 人们常说的 | 它实际的含义 |
|---|---|---|
| 拒绝钱包 | “失控账单” | 智能体循环产生消费，没有上限阻止它 |
| max_tokens | “每次请求上限” | 单次完成大小的上限 |
| max_turns | “迭代上限” | 会话中智能体循环迭代次数的上限 |
| max_budget_usd | “美元终止开关” | 会话成本上限；超预算时中止 |
| 速率限制 | “频率上限” | 短时间窗口内的消费限制（例如 10 分钟 50 美元） |
| 分层路由 | “小模型优先” | 默认使用廉价模型；仅在分类器认为有必要时升级 |
| 提示缓存 | “缓存的系统提示” | 提供商侧缓存，将重新发送的 Token 成本降至接近零 |
| 人机协同检查点 | “人工审批门禁” | 在昂贵动作前需要人工确认 |
