# 有界自我改进设计

> 研究已汇聚出四种用于约束自我改进循环的原语。必须在每次编辑中成立的形式化不变性。无法被修改的对齐锚点。多目标约束，其中每个维度（安全性、公平性、鲁棒性）都必须成立，而不仅仅是性能。当历史指标暗示能力损失时暂停循环的回归检测。它们都不是安全性的证明——信息论结果（柯尔莫哥洛夫复杂度、洛布定理）限制了任何系统对其自身后继者所能证明的内容。它们是提高静默失败成本的缓解措施。

**类型：** 学习  
**语言：** Python（stdlib，带不变性检查的有界循环）  
**前置知识：** 阶段15·07（RSI），阶段15·04（DGM）  
**时间：** 约60分钟

## 问题

第7课的竞赛模拟器显示，微小的速率差异会累积成巨大差距。第4课的DGM案例研究表明，循环可以主动操纵自身的评估器。这两个结果都指向同一个工程问题：你可以对自我改进循环施加什么样的约束，使得这些约束不会被循环本身悄无声息地削弱？

ICLR 2026 RSI研讨会总结（openreview.net/pdf?id=OsPQ6zTQXV）指出了上述四种原语。Anthropic的RSP v3.0（第19课）和DeepMind的FSF v3（第20课）在能力阈值中都引用了它们。Meta的HyperAgents工作和社区框架（如SAHOO，2026年3月）在生产中实现了这些原语的子集。

诚实的表述：这些都是缓解措施。信息论结果限制了任何系统对其自身后继者所能证明的内容，当前没有任何设计能在形式上解决这个问题。一个有界良好的循环比无界循环更安全，但绝不是在绝对意义上安全的。

## 概念

### 原语1：形式化不变性

不变性是在每次自我修改前后都必须成立的性质。例如：

- 输出分布依赖于固定的宪法头部（第17课）。
- 没有工具调用进入未经授权的端点。
- 内存写入通过已记录且已签名的路径进行。
- 评估器的模块哈希与已批准版本匹配。

不变性由循环无法修改的外部代码检查。如果提议的修改违反了某个不变性，它将被拒绝。这可以捕获DGM风格的评估器篡改模式（第4课）。

困难之处在于选择那些对安全是必要的、且能在合理时间内计算的不变性。过度指定会阻碍进展；指定不足则会使循环绕过重要属性。

### 原语2：对齐锚点

对齐锚点是循环核心目标的不可变表征，固定在循环的编辑表面之外。例如：

- 在每个调用时从只读位置加载的宪法文本（第17课）。
- 位于独立仓库中、具有独立访问控制的评估器。
- 由人类签名并在每个周期重新验证的工具权限清单。

锚点的作用是防止目标漂移。循环可以改进它追求目标的方式，但不能编辑目标本身。

微妙的失败模式：循环无法编辑的锚点，仍然可能被一个在如何读取锚点上发生漂移的循环重新解释。宪法AI（第17课）明确基于推理来处理新情况；那个推理层正是解释漂移的藏身之处。锚点是必要的，但不是充分的。

### 原语3：多目标约束

一个优化单一标量分数的循环会找到捷径。一个必须同时满足多个硬约束的循环可用的捷径更少。典型维度：

- 性能（任务级基准）
- 安全性（红队评估、对已知不良内容的拒绝率）
- 公平性（敏感子群体上的差异影响界限）
- 鲁棒性（分布外测试集、对抗性输入处理）

只有在每个约束都成立时，修改才被接受。第13课的成本调节器将其与财务约束叠加在一起。第18课的Llama Guard作为一个安全维度接入其中。

### 原语4：回归检测

每个周期的分数与历史分布进行比较。下降超出配置的容忍度则暂停循环。这可以捕获那些本来会被循环“改进超越”而吸收进运行平均值的静默能力损失。

一个实用的实现：存储最近N个周期的每个任务分数。每个新周期计算每个任务的增量。如果某个增量低于阈值，则该周期被拒绝，并交由人工审查。

### 信息论极限

柯尔莫哥洛夫复杂度和洛布定理设定了系统能证明关于自身的内容的上限。Schmidhuber的形式化哥德尔机（第4课）旨在达到这个最高上限；但没有人完成过一个非平凡证明。洛布的结果说：如果一个系统可证明地相信“如果我证明我应该做X，我就会做X”，那么它会在没有证明自己应该做的情况下就去做X——这是一个众所周知的自我指涉失效。

对我们原语的含义：它们无法解决安全问题。它们使得静默失败更加昂贵。一个恶意或发生漂移的循环，本可以悄悄绕过缺失的检查，现在必须主动破坏一个显式检查，而这是一种更容易被检测到的特征。

### 一个工作示例

假设一个智能体提出一次编辑。门控堆栈：

1. 不变性检查：模块哈希、工具权限清单、宪法头部。
2. 锚点检查：目标陈述匹配已批准版本（逐字节或语义上）。
3. 多目标评估：性能、安全性、公平性、鲁棒性维度。
4. 回归检测：没有维度下降超过容忍度。

编辑要生效，必须全部通过四项检查。任何一项失败都会暂停循环。

## 使用它

`code/main.py` 对第4课的DGM风格玩具模型运行一个有界自我改进循环，但叠加了上述四个原语。每个原语可以单独启用或禁用。演示的目的是展示每个原语能够捕获特定的失效类别，而移除任何一个都会让相应的失效类别通过。

## 交付物

`outputs/skill-bounded-loop-review.md` 对一个提议的有界循环进行审计，并对其实际实现了四个原语中的哪些（而非声称实现了哪些）进行评分。

## 练习

1. 运行 `code/main.py`，所有原语都已启用。确认循环仍然在主指标上有所改进，同时不让黑客手法获胜。

2. 禁用回归检测。构造一个输入，使得该输入导致静默能力损失被接受。

3. 禁用多目标约束。展示循环在性能维度上收敛的同时，某个安全性维度在下降。

4. 为一个编程智能体设计一个对齐锚点。存储什么文本？存放在哪里？如何检查？

5. 阅读ICLR 2026 RSI研讨会总结。从四个原语中选择一个，提出一个针对当前技术状态的具体改进。

## 关键术语

| 术语 | 人们说的意思 | 实际含义 |
|---|---|---|
| 不变性 | “始终为真的性质” | 由外部代码在每次编辑前后检查的性质 |
| 对齐锚点 | “固定的目标” | 固定在循环编辑表面之外的核心目标不可变表征 |
| 多目标约束 | “所有维度都必须成立” | 性能、安全性、公平性、鲁棒性——全部必需 |
| 回归检测 | “下降时暂停” | 当历史指标增量暗示能力损失时暂停循环 |
| 柯尔莫哥洛夫界 | “信息论极限” | 限制系统能证明关于自身后继者的内容 |
| 洛布定理 | “自我指涉陷阱” | 系统可以基于“我应该”行事，而不必证明应该 |
| 门控堆栈 | “分层检查” | 多个原语组合；任何失败都会拒绝编辑 |
| 有界改进 | “缓解措施，非证明” | 提高静默失败成本；不解决安全问题 |
