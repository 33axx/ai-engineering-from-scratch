# Show-o 与离散扩散统一模型

> Transfusion 混合了连续表示和离散表示。Show-o（Xie 等人，2024 年 8 月）走了另一条路：文本词元使用因果式下一个词元预测，图像词元使用受 MaskGIT 启发的掩码离散扩散。两者共存于一个 Transformer 中，并采用混合注意力掩码。其结果是在一个骨干网络、每种模态一个分词器、一种损失形式（将下一个词元预测扩展为掩码预测）上统一了 VQA、文生图、图生图修复和多模态生成。本课程介绍 Show-o 的设计——为什么掩码离散扩散是一种并行的、少步数的图像生成器——并与 Transfusion 和 Emu3 进行对比。

**类型：** 学习  
**语言：** Python（标准库，掩码离散扩散采样器）  
**前置知识：** 阶段 12 · 13（Transfusion）  
**时长：** 约 120 分钟

## 学习目标

- 解释掩码离散扩散：一种调度策略，均匀地掩码词元，然后让 Transformer 恢复它们。
- 从速度和质量上比较并行图像解码（Show-o、MaskGIT）与自回归图像解码（Chameleon、Emu3）。
- 说出 Show-o 在同一个检查点中处理的三个任务：T2I、VQA、图像修复。
- 选择一种掩码调度（余弦、线性、截断）并论证其对样本质量的影响。

## 问题

Transfusion 的双损失训练虽然有效，但动态更复杂——连续扩散损失与离散 NTP 损失处于不同的数值尺度。平衡损失权重是一次超参数搜索。该架构有效但复杂。

Show-o 的回答：保持两种模态都是离散的（像 Chameleon 一样），但通过掩码离散扩散并行生成图像，而不是顺序生成。训练目标变成了单一掩码词元预测，它自然泛化了下一个词元预测。

## 概念

### 掩码离散扩散（MaskGIT）

原始的 Chang 等人（2022）的 MaskGIT 技巧很优雅。从全掩码图像开始（每个词元都是特殊的 `<MASK>` id）。在每一步，并行预测所有掩码词元，然后保留最自信的 top-K 预测，并重新掩码其余部分。经过大约 8-16 次迭代后，所有词元都被填充。每一步解除掩码的词元数量的调度是经过调优的——余弦调度效果很好。

训练很简单：从 [0, 1] 均匀采样一个掩码比例，将其应用于图像的 VQ 词元，训练 Transformer 恢复被掩码的词元。这正是 BERT 对文本所做的，但被扩展到图像生成。

### Show-o：一个 Transformer，混合掩码

Show-o 将 MaskGIT 放入一个因果语言模型 Transformer 中。注意力掩码如下：

- 文本词元：因果式（标准 LLM）。
- 图像词元：在图像块内完全双向（这样掩码词元在预测期间可以看到所有其他图像词元）。
- 文生图：文本关注先前的图像，图像关注先前的文本。

训练在以下之间交替进行：
1. 文本序列的标准 NTP。
2. T2I 样本：文本 → 图像，带掩码图像词元，掩码词元预测损失。
3. VQA 样本：图像 → 文本，带掩码文本词元（实际上就是 NTP）。

统一损失是 `<MASK>` 词元上的交叉熵，它同时覆盖了文本 NTP（只有最后一个词元“被掩码”）和图像掩码扩散（随机子集被掩码）。

### 并行采样

Show-o 在大约 16 步内生成一张图像，而不是大约 1000 步（每个词元自回归）或大约 20 步（扩散）。在每一步，并行预测所有掩码词元；提交最自信的 top-K 个；重复。

比较：
- Chameleon / Emu3（词元上的自回归）：N_tokens 次前向传播，通常每张图像需要 1024-4096 次。
- Transfusion（连续扩散）：约 20 步，每一步是一次完整的 Transformer 前向传播。
- Show-o（掩码离散扩散）：约 16 步，每一步是一次完整的 Transformer 前向传播。

在相同规模的模型下，Show-o 比 Chameleon 更快，步数大致与 Transfusion 相当，但每一步的代价更低（离散词表 logits 对比连续 MSE 损失）。

### 单一检查点中的任务

Show-o 在推理时支持四种任务，由提示格式选择：

- 文本生成：标准自回归文本输出。
- VQA：图像输入，文本输出。
- T2I：文本输入，图像输出，通过掩码离散扩散。
- 修复：部分词元被掩码的图像，填充。

修复能力来自掩码预测训练的免费副产品。掩码 VQ 词元网格的一个区域，输入其余部分加上文本提示，预测被掩码的词元。

### 掩码调度

每一步解除掩码的词元数量调度会影响质量。Show-o 推荐余弦调度：

```
mask_ratio(t) = cos(pi * t / (2 * T))   # t = 0..T
```

在第 0 步，所有词元被掩码（比例 1.0）。在第 T 步，没有词元被掩码。余弦将质量集中在预测信息最丰富的中等比例上。线性调度也有效，但会更快达到平台期。

### Show-o2

Show-o2（2025 年后续工作，arXiv 2506.15564）扩展了 Show-o：更大的 LLM 基座，更好的分词器，改进的掩码调度。相同的架构模式。

### Show-o 的位置

在 2026 年的分类中：

- 离散词元 + NTP：Chameleon、Emu3。简单但推理慢。
- 离散词元 + 掩码扩散：Show-o、MaskGIT、LlamaGen、Muse。并行采样，仍受分词器损失影响。
- 连续 + 扩散：Transfusion、MMDiT、DiT。质量最高，训练更复杂。
- 连续 + 流匹配于 VLM：JanusFlow、InternVL-U。最新。

根据任务选择：当你希望在一个开放模型中同时获得 T2I + 修复 + VQA 且速度合理时，选择 Show-o；当质量最重要且你能承受双损失管道时，选择 Transfusion。

## 使用它

`code/main.py` 模拟了 Show-o 采样：

- 一个包含 16 个 VQ 词元的玩具网格。
- 一个“伪 Transformer”，根据提示和当前未掩码的词元预测 logits。
- 使用余弦调度，在 8 步内进行并行掩码采样。
- 打印中间状态（掩码模式演变）和最终词元。

运行它，观察掩码逐步消失。

## 练习

1. 掩码离散扩散大约在 16 步内采样。为什么不是 1 步？如果在第 0 步就解除所有掩码，会出什么问题？

2. 掩码扩散免费提供了修复能力。请提出一个产品用例（真实或假设），其中 Show-o 的修复能力击败了专门模型。

3. 余弦调度与线性调度：对于 T=8，追踪每一步解除掩码的词元数量。哪个更平衡？

4. 一张 512x512 的 Show-o 图像包含 1024 个词元。在词表大小 K=16384 的情况下，模型输出 1024 * log2(16384) = 14,336 比特（约 1.75 KiB）的数据。Stable Diffusion 输出 512*512*24 比特 = 6,291,456 比特（约 768 KiB）的原始像素。压缩比是多少？它带来了什么质量收益？

5. 阅读 LlamaGen（arXiv:2406.06525）。LlamaGen 的类条件自回归图像模型与 Show-o 的掩码方法有何不同？

## 关键术语

| 术语 | 人们说的 | 实际含义 |
|------|---------|----------|
| 掩码离散扩散 | “MaskGIT 风格” | 训练预测掩码词元；推理时，迭代地解除最自信预测的掩码 |
| 余弦调度 | “解除掩码调度” | 推理步骤中掩码比率的衰减；将置信度增长集中在中等范围 |
| 并行解码 | “一次性全部词元” | 每一步在一次前向传播中预测整个掩码词元序列，然后提交 top-K |
| 混合注意力 | “因果 + 双向” | 对文本词元是因果式的，对图像块内部是双向的掩码 |
| 修复 | “填充生成” | 以部分词元被掩码的图像为条件，预测缺失的词元；从训练目标中免费获得 |
| 提交率 | “每步 top-K” | 每次迭代中声明“完成”的词元数量；控制推理速度与质量的权衡 |
