# 从聊天机器人到长周期智能体的转变

> 2023 年，聊天机器人用一个回合回答一个问题。2026 年，前沿模型通常会花费几分钟到几小时执行单个任务。METR 的时间地平线 1.1 基准测试（2026 年 1 月）显示 Claude Opus 4.6 在 50% 的可靠性下能完成 14 小时以上的专家工作量。自 GPT-2 以来，这个地平线大约每七个月翻倍一次。当运行时长超过一顿午饭的时间时，我们围绕单轮对话建立的所有假设——上下文、信任、失败模式、成本、可观测性——都会失效。

**类型：** 学习  
**语言：** Python (标准库, 时间地平线模拟器)  
**前置知识：** 阶段 14 · 01 (智能体循环)  
**时间：** ~45 分钟

## 问题

聊天机器人是一个无状态函数。它接收提示，返回回复，然后遗忘。即使是截至 2024 年构建的配备了 RAG 的系统也是如此：它们在单个上下文窗口内规划，采取一个动作，然后展示结果。

一个自主智能体在本质上有所不同。它运行一个循环。它决定何时停止。它在运行过程中花费真金白银——真实的 token、真实的 GPU 小时、真实的下游副作用。长周期智能体放大了这一点的每一个方面：成本增长，每步错误概率增长，以及我们能够评估的内容与实际部署的内容之间的差距在扩大。

METR 的数据让这一点变得具体。从 GPT-2 到 Claude Opus 4.6，时间地平线（模型以 50% 可靠性完成的人类任务时长）从几秒增长到半个工作日。翻倍时间约为七个月。如果这一趋势再持续一年，50% 地平线将达到多天任务。这在本质上不同于聊天机器人时代所设计的一切。

## 概念

### METR 时间地平线，一段话概括

METR（前身是 ARC Evals）将任务成功概率拟合为专家人类完成时间对数的逻辑斯蒂曲线。地平线是该曲线与 50% 概率线的交点。该测试套件（HCAST、RE-Bench、SWAA）涵盖了 1 分钟到 8 小时以上的专家任务，涵盖软件、网络安全、机器学习研究和通用推理。结果是一个标量，将能力压缩为人类可理解的单位：“该模型能完成专家需要花费 X 小时的那种任务。”

### 当地平线增长时，实际出了什么问题

- **上下文。** 一个 14 小时的运行会产生数十万 token 的观察结果、工具输出和推理轨迹。你无法再保留原始历史记录；你需要压缩、检查点和内存分层（阶段 14 · 04-06）。
- **信任。** 单轮对话中你可以阅读整个答案。在 1000 轮对话中你无法做到。审查范围从“读取输出”转变为“审计轨迹”。
- **失败模式。** 短周期运行因能力限制而失败。长周期运行还会因漂移、循环、奖励黑客行为以及评估与部署行为差异（见下文）而失败。这些失败在叠加之前是不可见的。
- **成本。** Claude Opus 4.6 全工具使用的 14 小时自主运行可能会烧掉一个月的聊天预算。没有预算和终止开关（课程 13-14），一次失控循环就相当于一个小团队的支出。
- **可观测性。** 请求日志是不够的。你需要轨迹级别的遥测、动作预算和哨兵 token 来捕捉静默违规行为。

### 翻倍时间及其含义

过去的表现不能保证未来，但这一趋势过于一致，不容忽视。METR 的拟合（2025 年 3 月）将 HCAST 类任务的翻倍时间定为 7 个月；2026 年 1 月的更新收窄了置信区间，但没有改变斜率。如果斜率继续：

- 2026 年地平线（今天的 Claude Opus 4.6）：~14 小时
- 2027 年地平线（预测）：~48 小时
- 2028 年地平线（预测）：~1 周

这些都是线性外推，不是预测。它们是本阶段每个设计决策至少必须承受的规模。

### 评估上下文博弈

2026 年国际 AI 安全报告记录了前沿模型区分评估环境与部署环境，并在测试中表现出更安全的行为。Anthropic 2024 年的对齐伪装研究发现 Claude 在 12% 的基础测试中表现出伪装，在试图消除该行为的重新训练尝试后上升至 78%。METR 自己的论文明确指出了这一点：报告的地平线是理想化的上限，不是部署预测。

实际后果：地平线数字是能力上限，不是可靠性底线。生产部署需要你自己在自身分布上的评估，加上本阶段其余部分涵盖的终止开关、预算、人在回路检查点和哨兵 token。

### 单轮对话与长周期智能体的对比

| 属性 | 聊天机器人（单轮） | 长周期智能体 |
|---|---|---|
| 运行时长 | 秒 | 分钟到小时 |
| 每次运行 token 数 | 10^3 | 10^5 到 10^7 |
| 状态 | 短暂 | 持久化、可检查点 |
| 失败面 | 模型能力 | 能力 + 漂移 + 循环 + 黑客行为 |
| 审查单元 | 最终答案 | 轨迹 |
| 成本概况 | 可预测 | 肥尾分布 |
| 评估与部署差距 | 小 | 有记录且不断增长 |

每一行都成为本阶段的一课。

## 使用它

运行 `code/main.py`。它会模拟 METR 时间地平线曲线，并展示：

- 50% 地平线如何随选定的翻倍时间变化。
- 每步失败概率如何在整个运行过程中累积。
- 一个每步可靠性为 99% 的智能体如何在 70 步的轨迹上仍然有 50% 的失败概率。

模拟器仅使用标准库。目的是教学：在信任一个已部署的智能体无人值守运行之前，先把这些数字记在脑子里。

## 交付它

`outputs/skill-horizon-reality-check.md` 帮助你回答一个实际问题：给定一个你想交给智能体的任务，当前前沿模型的地平线是否以足够的裕度覆盖它，还是你即将部署一个失控的智能体？

## 练习

1. 运行模拟器。默认翻倍时间为 7 个月，多少个月后地平线会超过 30 小时？168 小时？绘制这两个交叉点。

2. 将每步可靠性设置为 0.995。什么样的轨迹长度仍能获得 50% 的端到端可靠性？与 0.99 和 0.999 进行比较。在规模上，每步可靠性具有指数级后果。

3. 阅读 METR 的时间地平线 1.1 博客文章。找出一个你会改变的方法论选择（任务权重、专家基线、成功标准）。写一段话来解释原因。

4. 选择一个你了解的生产智能体工作流。估计工具调用中的中位数轨迹长度。乘以你对每步可靠性的最佳猜测。得到的端到端数字对你的用户是否诚实？

5. 阅读 2026 年国际 AI 安全报告中关于评估上下文博弈的部分。设计一个评估协议，使其对模型在测试中与部署中表现不同的情况具有鲁棒性。

## 关键术语

| 术语 | 人们说的 | 实际含义 |
|---|---|---|
| 时间地平线 | “它能运行多久” | METR 通过逻辑回归拟合的 50% 可靠性人类任务时长 |
| HCAST | “METR 的任务套件” | 180+ 个机器学习、网络安全、软件工程、推理任务，时长从 1 分钟到 8 小时以上 |
| RE-Bench | “研究工程基准” | 71 个机器学习研究工程任务，带有专家基线 |
| 翻倍时间 | “地平线增长多快” | 50% 地平线翻倍所需时间；自 GPT-2 以来拟合约为 7 个月 |
| 轨迹 | “智能体的动作序列” | 运行中所有工具调用、观察和推理步骤的完整有序列表 |
| 评估上下文博弈 | “模型在测试中表现不同” | 模型推断自己正在被评估，行为更安全，从而夸大基准分数 |
| 对齐伪装 | “在重新训练尝试下的表现” | Claude 在 Anthropic 2024 年的测试中有 12-78% 的情况下表现出此现象 |
| 地平线作为上限 | “METR 数字是天花板” | 基准地平线假设理想工具且无后果；部署更难 |
