# Flamingo 与门控交叉注意力：面向少样本视觉语言模型

> DeepMind 的 Flamingo（2022）率先完成了两件事。它展示了一个单一模型可以处理任意交错的图像、视频和文本序列。它还展示了视觉语言模型能够进行上下文学习——只需提供一个包含三个示例（图像、描述）对的少样本提示，模型就能描述新图像，无需任何梯度更新。其机制是：在冻结的大语言模型现有层之间插入门控交叉注意力层，并通过一个初始化为零的可学习 tanh 门控来保持大语言模型在初始化时的文本能力。本课程将讲解 Flamingo 的 Perceiver 重采样器和门控交叉注意力架构——这是 Gemini 的混合输入和 Idefics2 的视觉令牌的祖先。

**类型：** 学习
**语言：** Python（标准库，门控交叉注意力 + Perceiver 重采样器演示）
**前置知识：** 第 12 阶段 · 03（BLIP-2 Q-Former）
**时长：** 约 120 分钟

## 学习目标

- 解释门控交叉注意力如何通过 tanh(门控) = 0 在初始化时保持冻结大语言模型的文本能力。
- 理解 Perceiver 重采样器的工作原理：N 个图像块 → 通过交叉注意力生成 K 个固定的“潜在”查询。
- 描述 Flamingo 如何处理交错的图文序列，并使用考虑图像位置的因果掩码。
- 复现少样本多模态提示结构（3 个图文示例，然后是查询图像）。

## 问题

BLIP-2 将 32 个视觉令牌输入到冻结大语言模型的输入层。这对每个提示一张图像有效。但如果你想在一个提示中交错输入*多张*图像，例如“这是图像 A，描述它；这是图像 B，描述它；现在这是图像 C，描述它”，该怎么办？大语言模型的自注意力机制需要在一个流中处理图像令牌和文本令牌，并且哪些位置可以关注哪些图像的问题会变得非常棘手。

Flamingo 的答案：完全不改变大语言模型的输入流。在现有大语言模型块之间插入额外的交叉注意力层。文本令牌仍然像往常一样通过大语言模型的因果自注意力。每经过几个大语言模型块，文本令牌还会通过新的门控层交叉关注图像特征。门控（初始化为零）意味着在初始步骤时，新层是空操作——模型的行为与预训练的大语言模型完全相同。随着训练的进行，门控打开，视觉信息开始流动。

Flamingo 解决的第二个问题是：如何处理每个提示的可变图像数量（0、1 或多张）？一个 Perceiver 重采样器——一个小的交叉注意力模块，它接收任意数量的图像块，并产生固定数量的视觉潜在令牌。无论提示中有多少张图像，大语言模型的交叉注意力层看到的形状都是相同的。

## 概念

### 冻结的大语言模型

Flamingo 从一个冻结的 Chinchilla 70B 大语言模型开始。所有 70B 权重保持不变。现有的文本自注意力和前馈网络正常运行。

### Perceiver 重采样器

对于提示中的每张图像，ViT 产生 N 个图像块令牌。Perceiver 重采样器有 K 个固定的可学习潜在令牌（Flamingo 使用 K=64）。每个重采样器块包含两个子步骤：

1. 交叉注意力：K 个潜在令牌关注 N 个图像块令牌（查询来自潜在令牌，键/值来自图像块）。
2. 潜在令牌内的自注意力 + 前馈网络。

经过 6 个重采样器块后，输出是 K=64 个维度为 1024 的视觉令牌，无论 ViT 产生了多少图像块。一张 224x224 的图像（196 个块）和一张 480x480 的图像（900 个块）都输出为 64 个重采样器令牌。

对于视频，重采样器在时间上应用：每帧的图像块产生 64 个潜在令牌，时间位置编码让模型区分 t=0 和 t=N。整个视频变为 T * 64 个视觉令牌。

### 门控交叉注意力

在冻结大语言模型的每 M 层之间（Flamingo 使用 M=4），插入一个新的门控交叉注意力块：

```
x_after_llm_block = llm_block(x_before)
cross = cross_attn(x_after, resampler_output)
gated = tanh(alpha) * cross + x_after
x_before_next_block = gated
```

- `alpha` 是一个可学习的标量，初始化为零。
- `tanh(0) = 0`，因此在初始化时，门控分支的贡献为零。
- 当 `alpha` 偏离零时，交叉注意力的贡献平滑增长。
- 残差连接意味着即使门控完全打开，也不会覆盖大语言模型的文本表示；它只是在其上叠加视觉信息。

这是 Flamingo 中最重要的设计选择：视觉条件是加性的、门控的，并且在初始化时为零。在步骤 0 时，Flamingo 在纯文本输入上就是一个完美的 Chinchilla 70B。

### 面向混合输入的掩码交叉注意力

在一个像“<图像 A> 描述 A <图像 B> 描述 B <图像 C> ？”这样的提示中，每个文本令牌只能看到序列中出现在它之前的图像。交叉注意力掩码强制执行：位置 `t` 的文本令牌只关注其图像索引 `i < i_t`（其中 `i_t` 是位置 `t` 之前最近的图像）的重采样器令牌。“只看最后一张前面的图像”或“看所有前面的图像”都是有效选择；Flamingo 选择了前者。

### 上下文少样本学习

一个 Flamingo 提示看起来像这样：

```
<image1> A photo of a cat. <image2> A photo of a dog. <image3> A photo of a
```

模型看到完成模式并输出“bird”（或图像3显示的任何内容）。没有梯度更新。冻结的大语言模型的上下文学习能力通过门控交叉注意力传递——这是论文的核心点及其重要性所在。

### 训练数据

Flamingo 在三个数据集上训练：

1. MultiModal MassiveWeb (M3W)：4300 万个包含交错图像和文本的网页，重建了阅读顺序。
2. 图像-文本对 (ALIGN + LTIP)：44 亿对。
3. 视频-文本对 (VTP)：2700 万个短视频片段。

OBELICS（2023）是一个开源的交错网页语料库复现，Idefics、Idefics2 以及大多数开源的“Flamingo 类似”模型都基于它进行训练。

### OpenFlamingo 和 Otter

OpenFlamingo（2023）是开源复现。架构相同（在冻结的 LLaMA 或 MPT 上使用 Perceiver 重采样器 + 门控交叉注意力）。提供 3B、4B、9B 的检查点。由于基础大语言模型更小且数据更少，质量落后于 Flamingo。

Otter（2023）基于 OpenFlamingo，在 MIMIC-IT（一个多模态指令数据集）上进行指令微调，展示了门控交叉注意力同样适用于指令跟随任务。

### 衍生模型

- Idefics / Idefics2 / Idefics3：Hugging Face 的门控交叉注意力系列，逐步简化（Idefics2 放弃了重采样器，转而使用带自适应池化的直接图像块令牌）。
- 从 Flamingo 到 Chameleon 的过渡：到 2024 年，许多团队转向早期融合（第 12.11 课）；Flamingo 风格的门控交叉注意力在需要冻结骨干网络的场景中仍被用于生产。
- Gemini 的混合输入：概念上继承了 Flamingo 的混合格式灵活性，尽管具体机制是专有的。

### 与 BLIP-2 的比较

| | BLIP-2 | Flamingo |
|---|---|---|
| 视觉桥梁 | 仅在输入处使用 Q-Former | 每 M 层使用门控交叉注意力 |
| 视觉令牌 | 每张图像 32 个 | 每张图像每个交叉注意力层 64 个 |
| 冻结大语言模型 | 是 | 是 |
| 少样本上下文学习 | 弱 | 强——论文的核心重点 |
| 混合输入 | 不原生支持 | 是，设计目标 |
| 训练数据 | 1.3 亿对 | 13 亿对 + 4300 万个交错页面 |
| 参数数量 | 训练 1.88 亿 | 训练约 100 亿（交叉注意力层） |
| 计算量 | 在 8 个 A100 上数天 | 在数千个 TPUv4 上数周 |

预算有限且只需单图像 VQA 时选择 BLIP-2。需要处理混合输入、少样本或多图像推理时选择 Flamingo/Idefics2。

## 使用它

`code/main.py` 演示了：

1. 一个 Perceiver 重采样器，对 36 个虚拟图像块令牌使用 8 个可学习潜在令牌（纯 Python 交叉注意力）。
2. 一个门控交叉注意力步骤，当 `alpha = 0` 时，输出等于输入（大语言模型不变），当 `alpha = 2.0` 时，融入视觉贡献。
3. 一个混合掩码构建器，为“(图像 1) (文本 1) (图像 2) (文本 2)”序列生成 2D 注意力掩码。

## 交付它

本课程产出 `outputs/skill-gated-bridge-diagnostic.md`。给定一个开源视觉语言模型的配置（是否有重采样器、交叉注意力频率、门控方案），它能识别出 Flamingo 系列的要素并解释冻结策略。这在调试微调导致文本性能下降（原因：门控打开过快过宽）时非常有用。

## 练习

1. 计算 Flamingo-9B 的视觉参数数量：9B 大语言模型 + 1.4B 门控交叉注意力层 + 64M 重采样器。训练参数占总参数的比例是多少？

2. 在 PyTorch 中实现门控残差 `y = tanh(alpha) * cross + x`。通过实验证明，当 `alpha=0` 时，初始化时 `y==x` 完全成立。

3. 阅读 OpenFlamingo 论文第 3.2 节（arXiv:2308.01390），了解当每个提示的图像数量不同时，他们如何处理批次中的多张图像。描述填充策略。

4. 为什么 Flamingo 的交叉注意力掩码让文本令牌只关注*最近*的前一张图像，而不是所有前面的图像？阅读 Flamingo 论文第 2.4 节，解释其中的权衡。

5. 上下文少样本学习：为一个新的 Flamingo 变体构造一个提示，包含 4 个“图像 → 主体颜色”示例。描述当示例数量从 0 到 8 变化时，期望的准确率模式。

## 关键术语

| 术语 | 人们常说的 | 实际含义 |
|------|------------|-----------|
| Perceiver 重采样器 | “固定潜在交叉注意力” | 从可变数量的输入块中产生 K 个固定令牌的模块 |
| 门控交叉注意力 | “Tanh 门控桥梁” | 残差层 `y = tanh(alpha)*cross + x`，可学习 alpha，初始化为 0 |
| 混合输入 | “混合序列” | 图像和文本按阅读顺序自由混合的提示格式 |
| 冻结大语言模型 | “无大语言模型梯度” | 文本大语言模型的权重不更新；仅训练重采样器和交叉注意力层 |
| 少样本 | “上下文示例” | 在提示中给出几个（图像，答案）对；模型无需微调即可泛化 |
| OBELICS | “交错网页语料库” | 包含 1.41 亿个网页（图像和文本按阅读顺序排列）的开源数据集 |
| Chinchilla | “70B 冻结基座” | Flamingo 的冻结文本大语言模型，来自 DeepMind 的 Chinchilla 论文 |
| 门控调度 | “alpha 如何变化” | 训练过程中交叉注意力门控打开的速率 |
| 交叉注意力频率 | “每 M 层” | 门控交叉注意力块插入的频率；Flamingo 使用 M=4 |
| OpenFlamingo | “开源复现” | MosaicML/LAION 的开源检查点（3-9B）；架构与 Flamingo 相同 |
