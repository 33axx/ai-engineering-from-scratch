# 多 token 预测 (MTP)

> 从 GPT-2 到 Llama 3 的每一个自回归 LLM，每个位置只训练一个损失：预测下一个 token。DeepSeek-V3 在每个位置增加了一个额外的损失：预测再下一个 token。额外的 14B 参数（基于 671B 模型）通过梯度流蒸馏回主模型，训练好的 MTP 头在推理时被重新用作投机解码的草稿模型，接受率超过 80%。从而免费获得了 1.8 倍的生成吞吐量。本课程将根据 DeepSeek 技术报告构建顺序 MTP 模块，计算损失和共享头参数布局，并解释为何 MTP 保持了因果链，而 Gloeckle 等人最初的并行 MTP 打破了它。

**类型：** 构建  
**语言：** Python（标准库）  
**前置知识：** 阶段 10 · 04（预训练小型 GPT）、阶段 10 · 15（投机解码）  
**时长：** ~60 分钟

## 学习目标

- 表述 MTP 训练目标，并推导跨预测深度的联合损失。
- 解释 Gloeckle 等人的并行 MTP 头（2024 年）与 DeepSeek-V3 的顺序 MTP 模块之间的区别，以及为何顺序设计保留了因果链。
- 计算向预训练运行添加 MTP 模块所需的参数和内存开销。
- 从头实现一个 MTP 模块：共享嵌入、每深度 transformer 块、投影以及共享输出头。

## 问题所在

下一个 token 预测是标准的 LLM 训练目标。每个隐藏状态被监督去预测恰好一个东西：紧随其后的 token。这是一个出奇弱的信号。序列中的大部分信息都延伸到一个 token 之外——结构、连贯性、事实性、算术流程。模型必须通过在海量 token 上累积许多单 token 信号来学习这些。

MTP 提出：如果每个隐藏状态同时被监督去预测多个未来 token 会怎样？Gloeckle 等人（Meta，2024 年）证明了这有帮助。他们的实现在主干之上放置了几个独立的输出头，每个头预测不同的偏移。并行、简单，但这些头看到的是相同的隐藏状态，没有层次化细化——并且预测之间没有因果链，因此无法用于投机解码。

DeepSeek-V3（2024 年 12 月）将 MTP 重新设计为顺序模块，在每个预测深度保持因果链。模型从 `h_i^(0)` 预测 `t+1`，然后从一个新的隐藏状态 `h_i^(1)` 预测 `t+2`，该新状态结合了 `h_i^(0)` 和 `E(t+1)` 嵌入，依此类推。每个深度都是它自己的小型 transformer 块。共享嵌入和共享输出头使参数开销保持在较低水平。在 DeepSeek-V3 的规模下，671B 主模型权重之上的 MTP 模块额外增加了 14B 参数。这 2% 的开销带来了更密集的训练信号以及在推理时现成的投机解码草稿模型。

本课程从头构建一个 MTP 模块和一个 D 深度损失。数学很简洁。实现只有 150 行。

## 概念

### 顺序 MTP 配方

DeepSeek-V3 在主干之上添加了 `D` 个 MTP 模块。每个模块 `k`（`k = 1..D`）预测深度 `k` 处的 token——即，给定直到位置 `i` 的前缀，预测 `t_{i+k}`。

模块 `k` 由以下部分组成：

- 一个 transformer 块 `T_k`，拥有自己的注意力和 MLP。
- 一个投影矩阵 `M_k`，它将前一个深度的隐藏状态与下一深度的真实 token 嵌入结合起来。
- 共享嵌入 `E`（与主模型相同）。
- 共享输出头 `Out`（与主模型相同）。

在训练时，对于直到位置 `i` 的前缀，每深度隐藏状态为：

```
h_i^(0) = main model backbone at position i
h_i^(k) = T_k( M_k * concat(RMSNorm(h_i^(k-1)), RMSNorm(E(t_{i+k}))) )   for k >= 1
```

每深度预测为：

```
logits_{i+k} = Out(h_i^(k-1))   for k = 1..D
```

每深度损失是相对于真实 token `t_{i+k}` 的交叉熵：

```
L_k = CE(logits_{i+k}, t_{i+k})
```

跨深度的联合损失：

```
L_MTP = (lambda / D) * sum_{k=1..D} L_k
```

`lambda` 是一个小的加权因子——DeepSeek-V3 在训练的前 10% 使用 0.3，之后使用 0.1。总训练损失为 `L_main + L_MTP`。

### 为何是顺序而非并行

Gloeckle 最初的并行 MTP 有 D 个输出头，每个头直接应用于 `h_i^(0)`。每个头从相同的主干隐藏状态预测 `t_{i+k}`。训练没问题，但预测之间没有相互条件。你不能使用 `head_1` 的输出来帮助 `head_2`——这些头是并行发射的。

DeepSeek-V3 的顺序设计从 `h_i^(k-1)` 加上实际的下一个 token 嵌入 `E(t_{i+k})` 构建 `h_i^(k)`。这保留了因果链：为了预测 `t_{i+k+1}`，深度 `k+1` 模块能看到 `t_{i+k}` 处的内容。这在结构上与自回归解码器消耗自身输出的方式相同——使得 MTP 模块可以直接用作投机解码的草稿模型。

在推理时：将 `h_i^(k-1)` 和草稿 `t_{i+k}` 送入模块 `k+1`，得到对 `t_{i+k+1}` 的预测。重复。这正是 EAGLE 风格的草稿，使用训练好的 MTP 模块作为草稿网络。DeepSeek-V3 报告在第一个 MTP 模块上接受率超过 80%，加速约 1.8 倍。

### 参数核算

对于隐藏尺寸为 `h`、词汇表大小为 `V` 的模型：

- 主模型：数十亿参数，加上一个大小为 `V * h` 的输出头。
- 共享输出头：复用主模型的头。无额外参数。
- 共享嵌入：复用主模型的嵌入。无额外参数。
- 每个 MTP 模块：
  - 投影 `M_k`：`(2h) * h = 2h^2`。
  - transformer 块 `T_k`：注意力（MHA 为 `4h^2`）加 MLP（对于比率 8/3 的 SwiGLU 通常为 `8h^2`）。每个块大约 `12h^2`。

每个模块总额外参数：`~14h^2`。对于 DeepSeek-V3 的 `h = 7168`，D = 1 模块：纸上计算 `~14 * 7168^2 = ~720M` 参数。DeepSeek-V3 报告为 14B——差异主要在于 MTP 模块中的专家层也是 MoE，导致每模块参数数量膨胀。

### 投机解码的回报

在预训练期间，MTP 模块会使训练减慢约 10%（更多前向计算、额外损失）。回报是双重的：

1. 更密集的训练信号。每个隐藏状态看到 D+1 个监督目标。在 DeepSeek-V3 的消融实验中，对 MMLU、GSM8K、MATH、HumanEval 的测量效果是持续提高几个百分点。

2. 推理时免费的投机解码草稿。MTP 模块已经过训练可以预测接下来的几个 token。重新用作草稿网络时，它可实现 80% 以上的接受率。在该水平上，N=3 或 N=5 的投机解码可提供 1.8 倍吞吐量。10% 的训练时间成本在第一次运行推理时就会回本。

### 与 EAGLE 的关系

EAGLE 在预训练之后单独训练一个小型草稿模型。MTP 则将草稿并入了预训练。两种方法在相似的接受率上趋同，但通过不同的流程：

| 维度 | EAGLE-3 | MTP (DeepSeek-V3) |
|-----------|---------|------------------|
| 训练时机 | 预训练后 | 预训练期间 |
| 与现有权重的向后兼容性 | 是 | 否（需要重新训练） |
| 草稿参数 | 1-2 个 transformer 层 | 1 个 transformer 块 + 投影 |
| 接受率 | 0.88-0.92 | 深度 1 处 0.80+ |
| 除加速外的益处 | 仅投机解码 | 更密集的训练信号 + 加速 |

## 动手构建

`code/main.py` 从头构建了一个完整的 MTP 模块：共享嵌入、投影、transformer 块、共享输出头。然后在一个短合成序列上计算每深度交叉熵损失，并按组件打印参数数量。词汇表大小为 32 个 token，使数字可读。

### 第一步：共享嵌入表

一个单一的 `vocab_size x hidden` 表被主模型以及每个深度的每个 MTP 模块使用。不是副本——字面上是同一个张量。

### 第二步：每深度组合

```python
def combine(prev_hidden, next_token_embed, M_k):
    # concat along feature dim, then project down to hidden
    concat = rms_norm(prev_hidden) + rms_norm(next_token_embed)  # vector addition stand-in
    projected = matvec(M_k, concat)
    return projected
```

真正的 DeepSeek-V3 将两个经过 RMSNorm 的向量拼接成 `[2h]`，然后用一个 `h x 2h` 矩阵进行投影。本玩具代码为了标准库简洁性使用了向量加法。

### 第三步：深度 k 处的 transformer 块

自注意力加 MLP。在玩具代码中，一个单层线性注意力块和一个 SwiGLU MLP 保持了结构的可见性，无需 numpy。

### 第四步：共享输出头

复用主模型的输出投影。在整个词汇表上生成 logits。

### 第五步：每深度损失

对 softmax(logits) 与偏移 `k` 处的真实 token 的交叉熵。使用 `lambda / D` 缩放因子跨深度聚合。

### 第六步：参数核算

打印总参数数量、共享（嵌入、头）数量以及每模块额外数量。显示 MTP 额外参数与主模型大小的比率。

## 使用方式

MTP 已集成到 DeepSeek-V3（2024 年 12 月）和 DeepSeek-R1 系列中。在推理时：

- DeepSeek 自己的服务堆栈直接消费 MTP 模块作为投机解码器。
- 截至 2026 年 4 月，vLLM 和 SGLang 已有用于 DeepSeek-V3 MTP 的集成路径。
- AMD 的 ROCm SGLang 教程展示了一个特定的 MTP 投机解码配置，在 V3 检查点上测量得到 1.8 倍加速。

何时在新预训练运行中使用 MTP：

- 你掌控完整的预训练流程，并希望获得更密集的训练信号。
- 你知道你将以规模化方式服务模型，并希望免费的投机解码。
- 你的隐藏尺寸至少为 4096。在 1B 规模下，开销的伤害大于增益。

何时不使用：

- 微调现有的预训练密集模型。MTP 模块未经过训练。
- 研究模型中，你希望有一个干净的基线进行比较。MTP 改变了架构。

## 练习

1. 运行 `code/main.py`。显示每深度损失随着合成信号增强而单调递减。修改合成信号使用固定模式，并验证深度 1 和深度 2 损失都收敛。

2. 计算一个密集 70B 模型（隐藏 8192，80 层）加上 D=1 MTP 模块的参数开销。与 DeepSeek-V3 报告的 14B 开销进行比较。解释为什么 DeepSeek 的数字更高：MTP transformer 块继承了相同的 MoE 结构，导致每模块参数数量膨胀。

3. 在玩具代码中实现 D=2：添加第二个 MTP 模块，它接受 h^(1) 并预测 `t_{i+2}`。验证联合损失和参数核算与 DeepSeek 论文中的方程 19-21 一致。

4. 将玩具代码切换为并行 MTP（Gloeckle 风格）：在主隐藏状态之上添加 D 个输出头，每个头预测不同的偏移。测量每深度损失与顺序版本在相同合成信号上的对比。对于 k > 1，顺序版本应该产生更低的深度 k 损失，因为它依赖于中间预测。

5. 使用训练好的 MTP 模块作为 EAGLE 风格的草稿：调用模块 k 来在推理时提出 `t_{i+k}`。在保留序列上测量这些草稿 token 相对于主模型预测的接受率。如果在玩具上达到 50% 以上，你就重现了 MTP 作为草稿的经验性质。

## 关键术语

| 术语 | 人们通常怎么说 | 实际含义 |
|------|----------------|------------------------|
| MTP 模块 | "额外的损失块" | 一个小型 transformer 块加上投影，预测主模型前方 `k` 个位置的 token |
| 预测深度 | "哪个偏移" | 整数 `k`，使得模块 `k` 从通过位置 `i` 的前缀预测 `t_{i+k}` |
| 并行 MTP | "Gloeckle 风格" | 在同一主干隐藏状态上的 D 个独立头，无条件链 |
| 顺序 MTP | "DeepSeek-V3 风格" | 每个模块依赖于前一深度的隐藏状态加上下一个 token 的嵌入；保留因果链 |
| 共享输出头 | "复用主头" | MTP 模块调用主模型的 LM 头，而非单独的输出投影 |
| 共享嵌入 | "复用主表" | 相同的词汇嵌入表各处使用；无重复参数 |
| 投影矩阵 M_k | "结合隐藏 + 下一个 token" | 一个 `h x 2h` 线性层，将前一隐藏状态和目标 token 嵌入折叠成下一深度的输入 |
| 联合损失 L_MTP | "平均化的额外损失" | 每深度交叉熵损失的算术平均，乘以 `lambda` 缩放 |
| 深度 1 接受率 | "MTP 草稿正确的频率" | 深度 D=1 的 MTP 模块的 top-1 预测等于主模型 top-1 预测的比率；DeepSeek-V3 上超过 80% |
| Lambda 加权 | "额外损失的重要性" | 每深度缩放因子；DeepSeek-V3 在训练开始时为 0.3，之后为 0.1 |
