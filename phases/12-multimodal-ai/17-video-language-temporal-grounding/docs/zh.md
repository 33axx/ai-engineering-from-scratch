# 视频-语言模型：时序令牌与时间定位

> 视频并非一叠照片。一段5秒的剪辑包含因果顺序、动作动词和事件时序，这些都是图像模型无法表示的。Video-LLaMA（Zhang 等人，2023年6月）发布了首个具有音视频定位能力的开源视频-LLM。VideoChat 和 Video-LLaVA 扩展了这一模式。到2025年，Qwen2.5-VL 的 TMRoPE 缩小了与前沿专有模型的差距。每个系统以不同方式处理时序令牌——每个片段使用 Q-former、每帧使用 concat-pool、每个令牌使用 TMRoPE。本课程解读这些模式，构建统一与动态帧采样器，并在时序定位任务上进行评估。

**类型：** 构建  
**语言：** Python（标准库，帧采样器 + 时序定位评估器）  
**先决条件：** Phase 12 · 08 (LLaVA-OneVision)  
**时间：** 约180分钟

## 学习目标

- 解释为什么时序位置编码能够独立于视觉编码器改变视频 VLM 的表现。
- 比较均匀、动态 FPS 和事件驱动帧采样在每秒令牌数与定位准确率上的差异。
- 描述每个片段 Q-former（Video-LLaMA）、每帧池化（Video-LLaVA）和每个令牌 M-RoPE（Qwen2.5-VL）的设计。
- 说出四个视频基准：VideoMME、TempCompass、EgoSchema、Video-MMMU。

## 问题

一段1分钟、30 FPS 的视频包含1800帧。按每帧196个视觉令牌（224分辨率下的 ViT-B）计算，即35.2万个令牌——超过任何2024年 LLM 的上下文长度。

存在三种缩减策略：

1. 子采样帧（根据内容每秒1-8帧）。
2. 对每帧的 patch 令牌进行激进池化（3x3 或 4x4 双线性池化）。
3. 通过 Q-former 压缩，将16帧的片段输出为64个令牌。

每种策略有不同的权衡。子采样丢失时序细节，池化丢失空间细节，Q-former 两者都丢失一些但节省令牌。

时序位置编码是另一个维度：模型如何知道第5帧在第6帧之前？选项包括简单的一维时序 RoPE（Video-LLaMA）、学习的时序嵌入（Video-LLaVA）以及 TMRoPE（Qwen2.5-VL，完整3D）。

## 概念

### Video-LLaMA：每个片段的 Q-former + 音频分支

Video-LLaMA (2023) 是首个开源的视频-LLM。架构：

- 以2 FPS 采样16帧（即8秒）。
- 每帧 ViT 特征 → 视频 Q-former，对所有16帧进行交叉注意力 → 32个学习查询 → LLM。
- 并行音频分支：波形 → ImageBind 音频编码器 → 音频 Q-former → 32个查询 → LLM。

优势：音视频联合推理。劣势：固定片段长度，无法进行任意时间定位。

### VideoChat 和 Video-LLaVA

VideoChat 保留了 Video-LLaMA 的思想，但去掉了音频并简化了设计。Video-LLaVA（Lin 等人，2023）在图像和视频帧上训练了一个单一的视觉编码器（“投影前对齐”），从而得到统一的表示。两者都是冻结的 CLIP 编码器 + MLP + LLM。

两者都无法处理长视频，都是8-16帧的系统。

### Qwen2.5-VL 和 TMRoPE

Qwen2.5-VL 引入了 TMRoPE——时间-模态旋转位置嵌入。每个 patch 令牌携带 (t, h, w) 位置，其中 t 是实际时间戳（而非帧索引）。

与简单时序嵌入的关键区别：

- 绝对时间而非索引。模型看到的是“在第4.2秒”，而非“在第15帧”。
- 每个令牌独立旋转，而非每个片段。每个视觉令牌根据其时间戳独立旋转。
- 兼容动态 FPS。如果你在这里以2 FPS采样，在那里以4 FPS采样，TMRoPE 原生处理不均匀间隔。

TMRoPE 支持“猫在第几秒跳？”这样的查询。模型可以输出“在第4.2秒”。Video-LLaMA 只能回答“在片段早期”。

### 帧采样策略

均匀采样：在视频时长内均匀采样 N 帧。简单，但会错过运动峰值。

动态 FPS：根据运动强度自适应采样。光流或帧差法选择高运动片段进行更密集采样。Qwen2.5-VL 基于此训练。

事件驱动：运行轻量级检测器，在动作发生处采样更多帧。被 VideoAgent 使用。

关键帧 + 上下文：在镜头边界采样，并加上少量相邻帧。用于电影类内容。

### 每帧池化

在1 FPS 和每帧576个令牌的情况下，一个5分钟的剪辑有172,800个令牌。Qwen2.5-VL-72B 的128k上下文可以处理，但成本高。

3x3 双线性池化将每帧减少到64个令牌 → 5分钟共19,200个令牌。这是大多数任务的理想选择。

对于空间细节不那么重要的智能体工作流，可以采用更激进的池化（6x6 → 每帧16个令牌）。

### 四个视频基准

- VideoMME：综合视频理解，包含短、中、长视频。
- TempCompass：细粒度时序推理，“之前”/“之后”问题。
- EgoSchema：长视界第一人称视频。
- Video-MMMU：多模态多学科视频问答。

完整的视频 VLM 评估会覆盖全部四个基准。它们从不同维度考验模型——TempCompass 完全关于顺序，EgoSchema 涉及3分钟以上的推理，VideoMME 跨越不同时长。

### 定位输出格式

时序定位的输出格式：

- 自由文本：“猫在大约第4秒时跳起。”易于解析但不精确。
- 结构化 JSON：`{"event": "跳起", "start": 4.1, "end": 4.3}`。Qwen2.5-VL 训练这种格式。
- 基于令牌：特殊 `<time>4.1</time>` 令牌穿插在答案中。Qwen2.5-VL 的内部格式。

对于下游应用，基于令牌的格式最精确。Qwen2.5-VL 的 JSON 输出格式可直接解析。

### 2026年最佳实践

对于2026年的视频 VLM：

- 编码器：带有 M-RoPE 或 TMRoPE 的 SigLIP 2（Qwen2.5-VL）。
- 帧采样：动态 FPS（根据运动每秒1-4帧），并设置最大帧数上限。
- 每帧池化：3x3 双线性。
- 输出：带有时间和事件字段的结构化 JSON。
- 基准：一般任务用 VideoMME + TempCompass；长视界任务用 EgoSchema。

## 使用

`code/main.py` 包含：

- 均匀和动态 FPS 帧采样器。
- 一个玩具时序定位评估器：给定“真实”事件时间 T 和模型输出，使用容差计算准确率。
- Video-LLaMA（16帧，Q-former）、Video-LLaVA（8帧，MLP）、Qwen2.5-VL（动态 FPS + TMRoPE）之间的比较。

## 交付

本课程产出 `outputs/skill-video-vlm-frame-planner.md`。给定一个视频任务（监控、动作识别、时序定位、摘要），它将选择帧采样器、池化因子、输出格式和期望的准确率等级。

## 关键术语

| 术语 | 人们常说的意思 | 实际含义 |
|------|----------------|----------|
| 时序定位 | “时间定位的答案” | VLM 输出事件发生的具体时间戳范围 |
| TMRoPE | “时间-多模态 RoPE” | 使用绝对时间戳的3D旋转位置，由 Qwen2.5-VL 使用 |
| 动态 FPS | “运动感知采样” | 在高运动片段采样更多帧，在静态片段采样更少帧 |
| 帧池化 | “每帧空间压缩” | 在进入 LLM 之前，使用双线性插值减少每帧的 patch 数量 |
| 视频 Q-former | “片段压缩器” | 将 N 帧映射到 K 个学习查询的交叉注意力瓶颈 |
| VideoMME | “视频基准” | 综合短/中/长视频基准，2500+样本 |
