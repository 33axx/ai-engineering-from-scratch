# 多模态智能体与计算机使用（顶点项目）

> 2026年的前沿产品是一个多模态智能体，能够读取截图、点击按钮、浏览网页UI、填写表单，并端到端地完成工作流。SeeClick 和 CogAgent（2024）证明了 GUI 定位原语的有效性。Ferret-UI 增加了对移动端的支持。ChartAgent 引入了图表视觉工具使用能力。VisualWebArena 和 AgentVista（2026）是前沿模型追逐的基准——即使 Gemini 3 Pro 和 Claude Opus 4.7 在 AgentVista 的困难任务上也只拿到约 30% 的分数。这个顶点项目将阶段 12 的所有线索汇集在一起：感知（高分辨率 VLM）、推理（具备工具使用能力的 LLM）、定位（坐标输出）、长程记忆以及评估。

**类型：** 顶点项目  
**语言：** Python（标准库、动作模式 + 智能体循环骨架）  
**前置条件：** 阶段 12 · 05（LLaVA）、阶段 12 · 09（Qwen-VL JSON）、阶段 14（智能体工程）  
**时间：** 约 240 分钟

## 学习目标

- 设计一个多模态智能体循环：感知 → 推理 → 行动 → 观察 → 重复。
- 构建一个 GUI 定位输出模式（点击坐标、输入文本、滚动、拖拽），使 VLM 能够以 JSON 形式输出。
- 比较纯截图智能体、无障碍树智能体以及混合智能体。
- 在 VisualWebArena 的小数据集上搭建多模态智能体基准评估。

## 问题

一个预订网站的工作流："帮我找一趟4月15日去东京的航班，靠过道座位，价格低于800美元，然后订下来。"

多模态智能体需要：

1. 对浏览器进行截图。
2. 将截图 + URL + 目标解析成一个计划。
3. 输出结构化动作：点击（在 x,y 处）、输入 "Tokyo"（在元素 E 上）、向下滚动、选择（单选按钮）。
4. 在浏览器上执行该动作。
5. 观察新状态（下一张截图）。
6. 重复直到任务完成。

每一步都是一次多模态 VLM 调用。VLM 输出必须是可解析的 JSON。每一步中错误会累积，因此恢复能力很重要。

## 概念

### GUI 定位——原语

GUI 定位是：给定一张截图和一个自然语言指令，输出要点击的 (x, y) 坐标（或其他动作）。

SeeClick（arXiv:2401.10935）是第一个大规模公开成果：在合成+真实 GUI 数据上微调 VLM，将坐标作为纯文本 token 输出。可行。

CogAgent（arXiv:2312.08914）增加了 1120x1120 的高分辨率编码以处理密集 UI。得分：在网页导航上约 84%。

Ferret-UI（arXiv:2404.05719）专注于移动端 UI，集成了 iOS 无障碍数据。

输出格式通常是 JSON：

```json
{"action": "click", "x": 384, "y": 220, "element_desc": "Search button"}
```

`element_desc` 有助于恢复：如果坐标在不同截图间发生偏移，语义提示能让系统重新定位。

### 动作模式

典型的动作模式包含 6-10 种动作类型：

- `click`：(x, y)
- `type`：(text, x?, y?)
- `scroll`：(direction, amount)
- `drag`：(x0, y0, x1, y1)
- `select`：(option_index)
- `hover`：(x, y)
- `navigate`：(url)
- `wait`：(ms)
- `done`：(success, explanation)

智能体每一步只输出一个动作。浏览器封装器执行该动作并返回新状态。

### 纯截图 vs 无障碍树

两种输入模式：

- **纯截图**：完整图像，无结构化信息。最通用，适用于任何应用。
- **无障碍树**：结构化 DOM / iOS 无障碍信息。定位时更可靠，适用于可获取树的环境。
- **混合**：两者兼用，树作为原子动作的可靠定位器，截图提供语义上下文。

生产环境中的智能体在可能的情况下使用混合方式。浏览器自动化（Selenium + 无障碍）总是能获取树；桌面应用有时也可以。

### 长程记忆

一个 20 步的工作流会产生 20 张截图。VLM 的上下文窗口很快就会被填满。三种压缩策略：

- **摘要链**：每 5 步后总结已完成事项，丢弃旧截图。
- **跳帧**：保留第一张、最后一张以及每第 3 张截图。
- **工具记录日志**：执行动作，保留文本日志记录已完成的操作；不再重新查看旧截图。

Claude 的计算机使用 API 采用日志模式。更简单，更可靠。

### 视觉工具使用

ChartAgent（arXiv:2510.04514）引入了用于图表理解的视觉工具使用：裁剪、缩放、OCR、调用外部检测。智能体可以输出"裁剪到区域 (100, 200, 300, 400) 然后调用 OCR"作为工具调用。工具返回文本；VLM 继续推理。

这种模式具有一般性：标记提示、区域注释和外部检测工具都符合"输出工具调用，接收结构化响应"的模式。

### 2026 年的基准测试

- **ScreenSpot-Pro**。约 1000 张网页截图上的 GUI 定位。开源最佳 Qwen2.5-VL-72B 约 85%。前沿模型约 90%。
- **VisualWebArena**。端到端网页任务（购物、论坛、分类信息）。开源最佳约 20%。Gemini 3 Pro 约 27%。
- **AgentVista**（arXiv:2602.23166）。2026 年最难的基准测试。跨 12 个领域的现实工作流。前沿模型得分 27-40%；开源模型 10-20%。
- **WebArena / WebShop**。较老的基准测试，已被前沿模型饱和。

### 为什么仍然困难

智能体性能瓶颈：

1. **精细尺度上的视觉定位**。"点击那个小叉号"在移动分辨率下经常失败。
2. **长程规划**。经过 10 步操作后，智能体偏离目标。
3. **错误恢复**。当点击失败（按错按钮）时，检测并恢复在训练数据中很少见。
4. **跨页面上下文**。在标签页之间跳转或填写长表单时会丢失状态。

研究方向：记忆架构、显式重新规划、多模态验证（动作成功的截图匹配）。

### 顶点项目构建

顶点项目任务：构建一个计算机使用智能体，能够：

1. 读取预订网站模拟页面的 HTML 和截图。
2. 规划多步序列：搜索 → 选择 → 填写表单 → 提交。
3. 输出符合动作模式的 JSON 动作。
4. 在固定的 10 个任务数据集上进行评估。

本课程提供了易于扩展为真实浏览器的脚手架代码。

## 使用它

`code/main.py` 是顶点项目骨架：

- 动作模式 JSON 定义（10 种动作）。
- 模拟浏览器状态为字典。
- 智能体循环骨架：接收状态，输出动作，应用，循环。
- 10 个任务的小型基准测试（合成页面）用于测量端到端成功率。
- 动作失败时的错误恢复钩子。

## 交付它

本课程产出 `outputs/skill-multimodal-agent-designer.md`。给定一个计算机使用产品（领域、动作集合、评估目标），设计完整的智能体循环、记忆策略、定位模式和预期基准测试分数。

## 练习

1. 在动作模式中扩展一个 `screenshot_region` 工具（裁剪+缩放）。哪些任务会受益？

2. 阅读 AgentVista（arXiv:2602.23166）。描述最困难的任务类别，以及为什么前沿模型仍然失败。

3. 长程记忆压缩：设计一个摘要链，最多保留 ≤4 张活跃截图，其余任何数量均记录日志。

4. 构建一个错误恢复钩子：动作失败（未找到按钮）时，智能体下一步该做什么？

5. 在 10 个网页任务上比较纯截图的 Claude 4.7 与混合截图+无障碍树的 Qwen2.5-VL。哪个在哪些任务上胜出？

## 关键术语

| 术语 | 人们说的 | 实际含义 |
|------|---------|----------|
| GUI 定位 | "点击坐标" | 模型针对截图上的指令输出 (x,y) |
| 动作模式 | "工具定义" | 有效动作（点击、输入、滚动、拖拽）的 JSON 描述 |
| 无障碍树 | "结构化 DOM" | 来自浏览器/iOS API 的机器可读 UI 层级结构 |
| 混合智能体 | "截图 + 树" | 同时使用图像和结构化信息，比单独使用任一更可靠 |
| 视觉工具使用 | "缩放/裁剪/检测" | 智能体在计划过程中调用外部视觉工具（OCR、检测） |
| 摘要链 | "记忆压缩" | 定期用文本摘要替换长截图历史 |
| VisualWebArena | "端到端网页基准" | 2024 年用于端到端网页任务的基准测试 |
| AgentVista | "2026 年困难基准" | 12 个领域的现实工作流；即使 Gemini 3 Pro 也只拿到约 30% |
