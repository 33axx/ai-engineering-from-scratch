# 视频生成

> 图像是二维张量，视频是三维张量。理论相同，计算量却高出10-100倍。OpenAI的Sora（2024年2月）证明了其可行性。到2026年，Veo 2、Kling 1.5、Runway Gen-3、Pika 2.0和WAN 2.2已能通过文本生成1080p级别的生产级视频——而开源权重堆栈（CogVideoX、HunyuanVideo、Mochi-1、WAN 2.2）落后了12个月。

**类型：** 构建
**语言：** Python
**前置知识：** 阶段8·07（潜在扩散），阶段7·09（ViT），阶段8·06（DDPM）
**预计时长：** ~45分钟

## 问题

一段10秒的1080p视频，24fps，共240帧，每帧1920×1080×3像素。每个片段原始数据约1.5 GB。像素空间扩散不可行。你需要：

1. **时空压缩。** 一个能编码视频（而非单帧）为时空块序列的VAE。
2. **时间一致性。** 帧与帧之间需要在数秒内共享内容、光照和物体身份。网络必须建模运动。
3. **计算预算。** 对于相同模型规模，视频训练成本是图像的10-100倍。
4. **条件控制。** 文本、图像（首帧）、音频或其他视频。多数生产模型接受全部四种输入。

解决此问题的架构是将**扩散Transformer（DiT）**应用于时空块，并在大型（提示、字幕、视频）数据集上训练。扩散损失与第6课相同。

## 概念

![视频扩散：分块、DiT、解码](../assets/video-generation.svg)

### 分块

使用3D VAE（学习到的时空压缩）对视频进行编码。潜变量的形状为 `[T_latent, H_latent, W_latent, C_latent]`。将其分割成大小为 `[t_p, h_p, w_p]` 的块。对于Sora风格模型，`t_p = 1`（逐帧块）或 `t_p = 2`（每两帧）。一段10秒的1080p视频压缩后约有20,000到100,000个块。

### 时空DiT

一个Transformer处理扁平的块序列。每个块具有三维位置嵌入（时间 + y + x）。通常将注意力分解为：

- **空间注意力**：在同一帧内的块之间。
- **时间注意力**：在同一空间位置的帧之间。
- **完整3D注意力**的计算代价是前者的16-100倍，仅在低分辨率或研究中才使用。

### 文本条件

与大型文本编码器（Sora和CogVideoX-5B使用T5-XXL）进行交叉注意力。长提示很关键——Sora的训练集使用了GPT生成的密集重标注，平均每个剪辑200个token。

### 训练

在时空潜变量上应用标准扩散损失（ε或v预测）。数据：网络视频 + 约1亿个精选片段 + 合成文本字幕。计算：即便是小型研究运行也需要10,000+ GPU小时；Sora规模则超过100,000小时。

## 动手构建

`code/main.py` 模拟了时空DiT的核心思想：对一个小的合成视频进行分块，添加逐块位置嵌入，然后利用Transformer风格的跨块注意力对整个序列去噪。不使用numpy，纯Python。我们将展示，即使在一维情况下，当相邻帧的块共享去噪器和位置嵌入时，时间一致性也能涌现。

### 步骤1：对合成的一维"视频"分块

```python
def make_video(T_frames=8, rng=None):
    # a "video" is a sequence of 1-D values following a smooth trajectory
    base = rng.gauss(0, 1)
    return [base + 0.3 * t + rng.gauss(0, 0.1) for t in range(T_frames)]
```

### 步骤2：逐帧位置嵌入

```python
def pos_embed(t, dim):
    return sinusoidal(t, dim)
```

### 步骤3：去噪器处理整个序列

我们的微型网络不是独立去噪每一帧，而是将所有帧的值及其位置嵌入拼接起来，共同预测所有帧的噪声。

### 步骤4：时间一致性测试

训练后，采样一段视频。衡量帧间差异。如果模型学到了时间结构，帧间差异应小于独立采样每一帧的情况。

## 常见陷阱

- **逐帧独立采样 = 闪烁。** 如果对每一帧分别运行图像扩散，输出会闪烁，因为每帧的噪声是独立的。视频扩散通过注意力或共享噪声将帧耦合起来解决这个问题。
- **朴素的3D注意力 = 显存溢出（OOM）。** 对10秒1080p潜变量进行完整3D注意力操作是数千亿次计算。应分解为空间 + 时间注意力。
- **数据标注比数据规模更重要。** Sora相对于先前工作的主要改进是训练数据使用了约10倍更详细的字幕（GPT-4重新标注的片段）。OpenAI的技术报告明确指出了这一点。
- **首帧条件。** 多数生产模型也接受一张图像作为首帧，即"图像到视频"模式；训练包含此变体。
- **物理漂移。** 长片段（>10秒）会累积细微的不一致性。滑动窗口生成 + 关键帧锚定可帮助缓解。

## 关键术语

| 术语 | 人们说的 | 实际含义 |
|------|----------|----------|
| 视频VAE | "3D VAE" | 将 `(T, H, W, C)` 压缩为时空潜变量的编码器。 |
| 块 | "tokens" | 潜变量中固定大小的三维块；DiT的输入。 |
| 分解注意力 | "空间 + 时间" | 先运行空间注意力，再运行时间注意力；避免完整3D注意力。 |
| 图像到视频 (I2V) | "让这张照片动起来" | 模型接收一张图像 + 文本，输出从该图像开始的视频。 |
| 关键帧条件 | "锚点帧" | 固定特定帧以控制视频走向。 |
| 运动笔刷 | "方向提示" | 用户通过在图像上绘制运动矢量进行控制的界面输入。 |
| 重新标注 | "密集字幕" | 使用LLM重新标记训练片段，生成详细提示。 |
| 闪烁 | "时间伪影" | 帧间不一致；通过耦合去噪修复。 |

## 生产提示：视频潜变量是内存带宽问题

一段10秒1080p视频，24fps，共240帧 × 1920 × 1080 × 3 ≈ 1.5 GB的原始像素。经过4倍视频VAE压缩（2倍空间 × 2倍时间）后，每个请求的潜变量约为100 MB。将其通过时空DiT运行30步（batch size 1），每一步需要搬运约3 GB数据经过HBM——瓶颈是内存带宽而非FLOPs。

三个生产调节旋钮，均直接来自生产推理文献的推理章节：

- **DiT的张量并行（TP）。** 文本到视频模型通常≥10B参数。跨4块H100使用TP=4是标准做法；对于405B级别模型可采用PP=2 × TP=2。每步延迟随TP大致线性下降，直至触发all-reduce瓶颈。
- **帧批处理 = 连续批处理。** 在生成时，视频概念上是帧通过注意力链接而成的批处理。连续批处理（运行时调度）适用：如果模型架构允许滑动窗口生成，可以在返回第 `t-1` 帧的同时开始渲染第 `t+1` 帧。
- **片段级预填充缓存。** 对于图像到视频，首帧条件类似于LLM的提示预填充：计算一次，在时间解码器多次传递中复用。这本质上是视频的KV缓存。
