# 推测解码与EAGLE-3

> 第七阶段·第16课从数学上证明：Leviathan拒绝规则精确保持了验证器的分布。本课是2026年生产级推测解码的训练栈视角。EAGLE-3将草稿模型从一个廉价的近似器变成了一个基于验证器自身隐藏状态训练的小型专用网络，并添加了一个训练时测试循环，使其训练和推理分布对齐。结果：端到端加速3至6.5倍，聊天场景下每令牌接受率超过0.9，无分布折衷。2026年每套生产推理栈默认集成此方案。

## 学习目标

- 用一句话陈述Leviathan定理，并证明推测循环产生的样本与验证器同分布。
- 梳理从普通推测解码（Leviathan 2023）到EAGLE、EAGLE-2、EAGLE-3的两年演进路线，指出每一步解决的具体限制。
- 根据接受率 `α` 和草稿模型与验证器的成本比 `c` 计算预期加速比，并为每种场景选择最佳草稿长度 `N`。
- 从头实现完整的推测循环：草稿生成、验证、从残差中拒绝采样、拒绝时的KV缓存回滚、完全接受时的奖励令牌。

## 问题

在H100上对70B模型进行自回归解码，速度大约为每秒35个令牌。GPU远未饱和。内存带宽是瓶颈：每个令牌从HBM加载70B的权重，执行一步算术运算，产生一个浮点数。计算单元大部分时间闲置。

推测解码将其转变为一个可以实际解决的吞吐量问题。廉价的草稿模型通过 `N` 次小型前向传播提出 `N` 个令牌。验证器在prefix加上所有 `N` 个草稿令牌上运行一次。如果验证器在位置 `i` 的分布与草稿一致（在我们将精确定义的统计意义上），则接受；否则拒绝并从残差分布中采一个纠正令牌。一次大模型前向传播最多产生 `N+1` 个接受令牌，而不是一个。

关键定理来自Leviathan, Kalman, Matias (ICML 2023)：输出分布与直接对验证器采样得到的分布完全相同。不是近似，是相同。这就是推测解码在生产环境中可接受的唯一原因——它是一种纯延迟优化，没有质量折衷。

第七阶段·第16课提供的是数学。本课提供的是训练栈。一个好的草稿模型带来的加速是廉价草稿模型的两倍。EAGLE、EAGLE-2和EAGLE-3 (Li et al., 2024–2025) 将“草稿模型 = 同一模型的更小版本”转变为精确的工程规范。2026年生产推理服务器默认使用EAGLE-3。

## 概念

### 不变式：Leviathan拒绝采样

设 `p(t)` 是草稿模型在给定prefix下对下一个令牌的分布，`q(t)` 是验证器的分布。采样一个草稿令牌 `d ~ p`。以概率 `min(1, q(d) / p(d))` 接受。如果拒绝，则从残差分布 `(q - p)_+ / ||(q - p)_+||_1` 中采样。结果样本的分布为 `q`。无论 `p` 的质量如何，此结论都成立——质量越差，拒绝越频繁，但输出仍然精确。

将 `N` 次这样的调用串联，使用一次验证器前向传播处理 `prefix + d_1 + ... + d_N`。验证器同时返回 `q_1, q_2, ..., q_{N+1}`。从左到右遍历。在位置 `j` 第一次拒绝时，从 `residual(q_j, p_j)` 中采样并停止。如果全部接受，则从 `q_{N+1}` 中采样一个奖励令牌。

### 什么决定加速比

设 `α` 为每个草稿令牌的期望接受率。设 `c = cost(草案) / cost(验证器)` 为成本比。每次验证器前向传播的期望接受令牌数为：

```
E[accepted] = (1 - α^(N+1)) / (1 - α)
```

每个接受令牌的期望总墙钟时间为 `(N * c + 1) / E[accepted]`。针对 `N` 最小化该值即可得到最佳点。对于 `α = 0.8, c = 0.05`：最佳 `N` 约为5–7，加速比为3.2×。对于 `α = 0.95, c = 0.02`：最佳 `N` 约为8–10，加速比接近5×。

最大的杠杆是 `α`。固定 `N = 5`，从 `α = 0.6`（普通草稿模型）提升到 `α = 0.9`（EAGLE-3），每次验证器前向传播的期望接受令牌数从2.2增加到4.1。相同验证器下的吞吐量提升近2倍。

### 两年演进

**普通推测解码（Leviathan, 2023）。** 草稿模型是同一系列独立训练的较小LLM。容易搭建，`α ≈ 0.6`，加速比最好约为2×。

**EAGLE-1 (Li et al., 2024)。** 草稿模型是一个小型Transformer（通常一到两层），以验证器最后一层的隐藏状态作为输入，直接预测下一个令牌。由于草稿模型能看到验证器的特征表示，其分布更接近验证器。`α` 提升至0.7–0.8。

**EAGLE-2 (Li et al., 2024)。** 添加了动态草稿树：不提出单一 `N` 令牌序列，而是提出一个小型的候选树，在验证器的一次前向传播中（使用树注意力）为每个候选打分，然后走最高概率路径。草稿长度每一步自适应。每条接受路径上的 `α` 超过0.85。

**EAGLE-3 (Li et al., 2025, NeurIPS)。** 还有两个变化。首先，完全放弃了特征预测损失——EAGLE-1/2训练草稿模型去匹配验证器的隐藏状态，这限制了数据的效果。EAGLE-3直接训练令牌预测。其次，训练时测试（TTT）：在草稿模型训练期间，将草稿模型自身的先前预测作为输入回传，类似于推理时的多步操作。这对齐了训练和测试分布，阻止了误差累积。实测加速比：聊天场景高达6.5×，在SGLang H100 batch 64下吞吐量提升38%。

### KV缓存回滚

验证过程将验证器的KV缓存扩展了 `N` 个条目。如果拒绝发生在位置 `j`，则位置 `j-1` 之后的缓存内容变得不正确。两种常见实现：写入临时缓冲区并在接受时提交（vLLM, TensorRT-LLM），或保持物理KV缓存加逻辑长度，拒绝时截断。无论哪种方式，回滚成本是每层每头的字节数，与前向传播成本相比可以忽略。

对于EAGLE-2树搜索，验证器使用一个尊重树拓扑的非因果掩码运行注意力。工程实现稍显繁琐，但计算本质上是一个带有自定义掩码的标准flash-attention调用。

## 构建它

参见 `code/main.py`。这是完整的Leviathan推测循环，包含所有组成部分：长度为N的草稿、验证器并行前向传播、逐个位置拒绝、残差采样、奖励令牌、KV回滚，以及实证验证输出分布与直接对 `q` 采样一致。

### 步骤1：拒绝规则

```python
def accept(q_prob, p_prob, u):
    if p_prob <= 0:
        return True
    return u < min(1.0, q_prob / p_prob)
```

### 步骤2：残差分布

```python
def residual(q, p):
    raw = [max(0.0, qi - pi) for qi, pi in zip(q, p)]
    s = sum(raw)
    if s == 0:
        return list(q)
    return [r / s for r in raw]
```

### 步骤3：完整推测步骤

`spec_step` 函数从 `p` 中草拟 `N` 个令牌，然后通过一次并行 `q` 评估验证所有令牌。对每个草拟令牌应用拒绝规则，并在第一次拒绝时从残差中采样纠正令牌。如果全部接受，则从 `q_{N+1}` 中发射一个奖励令牌。

### 步骤4：KV回滚簿记

模拟器为每个worker维护一个逻辑 `kv_length`。如果接受了 `k` 个草稿，则 `kv_length += k`。如果在位置 `j` 拒绝，缓存已经写入了 `j` 之后的内容，但逻辑长度设置为 `prefix_length + j + 1`——即纠正令牌之后一个位置。后续读取截断到逻辑长度。

### 步骤5：Leviathan检验

运行50,000步推测步骤。统计接受令牌的经验分布。与50,000次直接从 `q` 采样的结果进行比较。卡方统计量应远小于临界值。定理在实践中成立。

### 步骤6：加速比 vs. α

通过以不同幅度扰动 `p` 使其偏离 `q` 来改变草稿质量。测量 `α`，然后绘制期望令牌数随 `α` 和 `N` 的变化图。代码打印一个表格，展示EAGLE-3级别的草稿质量（`α ≈ 0.9`）如何实现每次验证器调用产生4–5个令牌。

## 使用它

使用EAGLE-3的生产级 `vllm serve`：

```bash
vllm serve meta-llama/Llama-3.3-70B-Instruct \
  --speculative-config '{
    "model": "yuhuili/EAGLE3-LLaMA3.3-Instruct-70B",
    "num_speculative_tokens": 5,
    "method": "eagle3"
  }'
```

SGLang在H100 batch 64下使用EAGLE-3：根据EAGLE-3论文，吞吐量大约是batch-64普通解码的1.38倍。

何时使用推测解码：

- 任何交互式聊天工作负载，p50延迟比峰值吞吐更重要。
- 代码生成和结构化输出（JSON, SQL）。因为目标分布高度可预测，`α` 高于0.9。
- 长文本生成（数千令牌）。分摊的加速持续生效。

何时不使用：

- 非常小的模型（< 3B）。草稿模型并不比验证器便宜多少。
- tiny batch-1 CPU部署。草稿模型的内存开销可能不值得。
- 高温创作采样，此时 `α` 会崩溃。

## 关键术语

| 术语 | 人们常说的 | 实际含义 |
|------|----------------|------------------------|
| Leviathan规则 | "min(1, q over p)" | 以概率 `min(1, q(d)/p(d))` 的Bernoulli接受/拒绝，拒绝时从残差采样，精确保持验证器的分布 |
| 残差分布 | "q减p再加，归一化" | `(q - p)_+` 截断到零并重新归一化——拒绝时采样的正确分布 |
| 接受率 α | "草稿正确的频率" | 拒绝规则下每个令牌的期望Bernoulli成功概率；支配所有加速比计算 |
| EAGLE-1 | "隐藏状态草稿" | 以验证器最后一层隐藏状态为条件的小型Transformer草稿（Li et al., 2024） |
| EAGLE-2 | "动态草稿树" | EAGLE-1加上一个候选延续树，在验证器的一次前向传播中使用树注意力打分 |
| EAGLE-3 | "训练时测试" | 放弃特征预测损失，直接训练令牌预测，并在训练期间将草稿自身输出作为输入 |
| 训练时测试 (TTT) | "暴露偏差修复" | 在训练期间让草稿自回归运行，使得训练和测试输入分布匹配——调度采样的直接类比 |
| KV回滚 | "撤销拒绝的草稿" | 拒绝后将验证器的KV缓存重置为已接受前缀长度的簿记 |
| 奖励令牌 | "免费的" | 当所有 `N` 个草稿都被接受时，从 `q_{N+1}` 多采一个令牌，不增加验证器成本 |
| 树注意力 | "一次验证多个候选" | 使用尊重草稿树拓扑的非因果掩码的注意力；在一次前向传播中计算树中每个节点的 `q_i` |
